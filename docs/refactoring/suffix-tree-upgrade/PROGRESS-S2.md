### The guard and the skip accounting (S2.2)

**The guard of the checked build.** `BufAndArenaTests.BuildMode_IsReported_AndMatchesTheExpectedMode` (default set) fails when `ESA_EXPECT_BOUNDS` is `true` and `EsaBuild.BoundsChecked` is false, i.e. when a run that was meant to be the checked build ran the Release accessor. The test existed (it was the one that "cannot fail" without the variable) and did what R04 asks; S2.2 moved its rule into `BuildExpectation` (test code) and pinned it: the table of the rule in `BuildExpectationTests` (unset, `true`, `false`, case, blanks, anything else; default and checked build), the reading of the variable by its name, and the live test called with the variable set in process. The honest configurations pass: a default build without the variable (the default CI), a checked build with `true` (the deep workflow), a checked build without the variable (a developer's own `-p:EsaBounds=true` run: the tests that need the accessor run, nothing needs an expectation). The dishonest one fails: a default build with `true`, a checked build with `false`, any other value (including the empty string of a workflow expression that expanded to nothing).

**The skip accounting.** A test cannot see the outcome of the other tests of its own run, so the check reads the `.trx` of a run: `analysis/ci/skip_accounting.py` against `tests/SuffixTree/SuffixTree.Esa.Tests/skips.tsv`. It fails on every test that was not executed and is not in the list (**an added `Assert.Ignore("x")` is this failure**), on every listed row whose test ran (the list cannot rot), and, in checked mode, on every test that needs the checked accessor and was skipped. The list has rows of four kinds: `ignore` (a test that skips itself: **37** in the default run, 18 of them in the checked build too), the nine `host` rows (tests that mount a tmpfs, skipped on a host without the right to: may be skipped or run), `explicit` (four `[Explicit]` methods) and `explicit-class` (40 `[Explicit]` fixtures): an Explicit test is not a skip of the run (the console of `dotnet test` does not count it: **37 skipped**, 6,675 passed, total 6,712 at the end of S2.2, while the trx has 897 not-executed results = 37 + 860 Explicit), but the trx cannot tell the two apart, and a test that is made Explicit leaves the default run, so the list names every Explicit test and a new one must be added on purpose. It runs as a step of the job `checked` (checked mode) and by hand on the trx of the default run at the end of a package (default mode; `--partial` for a filtered hand run). Why this and not a source scan: the scan sees call sites, not outcomes (a helper that skips many tests, `Assume`, a parameter that has no such state, an Explicit fixture), cannot know which tests skip in which build, and cannot find a stale row.

### Reading a red night

Open the run of `suffix-tree-deep`: every job has a summary (the page of the run) and a `.trx` artifact `trx-<job>`.
* **`checked`**, step *Test*: `ESA_EXPECT_BOUNDS=true but SuffixTree.Esa was compiled WITHOUT ESA_BOUNDS` means the build step lost `-p:EsaBounds=true` (someone edited the workflow); any other red test is a failure that appears in the checked build, most likely an `EsaMemoryViolationException` whose message names the buffer, the index and the length: an out-of-bounds access that the Release build only reads or writes silently, a real finding. Step *Skip accounting*: `UNLISTED SKIP` (a new `Assert.Ignore`, `Assume`, `[Ignore]`, `Assert.Inconclusive`, or a test made Explicit: remove it, or add a row to `skips.tsv` and say why), `STALE` (a listed test ran: remove the row), `CHECKED-BUILD TEST SKIPPED` (one of the 19 tests that need the accessor was skipped: the build was not checked), `LISTED BUT ABSENT` (a test was renamed or deleted: update the row). A `host` surprise on the first nights (a skip that this machine, as root, never had) is one line in `skips.tsv`.
* **`exhaustive`, `fuzz`**: the summary lists the failed tests; both are deterministic in their seeds: `dotnet test $T -c Release --filter "FullyQualifiedName~<TestName>"` reproduces it.
* **`harness`**: the first lines of the summary are the master seed and the command that reproduces the run by hand; every failure prints `family seed n op` and a minimised case (in the log of the test step and in the artifact `trx-harness`); a minimised case becomes a permanent line of `Fuzz/regressions.txt` (S1 rule). A job that ends by `timeout-minutes` is a hang or a very slow runner: the watchdog of the harness is 900 s per case.
* **`vectors`**: a red step *Generate the benchmark inputs* means the generator changed or Python's `random` did; a red test is a suffix array or LCP hash that differs from libsais (a real defect, the manifest or the input; the test tells which side the independent verifier supports).
* **`large`** (weekly): nine red tests are by design; the summary lists them, marks a red test that is not in `analysis/ci/large_expected_red.txt` as **UNEXPECTED** (a real finding) and a listed test that is green as to be removed. * **A. The long descent** (`WideSearch.cs`, 342 lines). `WideSearch.Run<TAccess, TSa, TCells, TText, TPat>` is the loop of `MappedSearch` with `long` in every register: ranks, positions, depths and the length of the pattern. The strategies are structs, as in S1: the access mode (`CheckedAccess` / `TrustedAccess`), the stored width of the suffix array and of the child cells (`IPosReader`: `Pos32`, `Pos40`), the kind of the LCP base array (`Pos8/16/32/64`), the child cells (`WideCells`: packed, or tagged as a flag of the struct, since the tagged codec exists over 4-byte cells only), the packed text (`PackedSymbols`) and the pattern (`SpanPattern`, a `ref struct`). `WideSearcher.Create(WideSections)` is the one switch of the matrix: **2 access modes x 2 widths x 4 LCP kinds = 16 instantiations of the descent**, which the JIT compiles lazily, only for the rows that a process uses; with the 12 of the 32-bit loop of S1 that is **28 instantiations, inside the 24 - 36 that ADR-005 section 3.3 (R2) budgets for `Pos40` and the tagged codec**. The checks of `Checked` mode are those of the 32-bit loop (a boundary must increase and stay inside its interval, a child must be deeper than its parent and not deeper than the text, a rank from a section is validated before it indexes, a text position from the suffix array is clamped); the text is compared symbol by symbol (the 32-bit loop compares 64-bit windows; a text above 2^31 - 2 symbols is not the hot path of S1).
* **B. `MappedSearch` selects once per index.** `SesaFile.IsNarrow` (fewer than 2^31 - 1 symbols, 4-byte entries, an LCP array of 8, 16 or 32 bits: exactly the containers of S1) keeps **the 32-bit loop of S1, character for character** (12 variants, 0 .. 11); every other container, and every view that a test made (`MappedSearch(WideSearcher, CompactLcp, int bits)`), gets variant 12, the long descent. `TryMatch(ReadOnlySpan<byte>, out long, out long)` is the long member; the 32-bit `TryMatch` of a wide index says `NotSupportedException` by name through `IntBridge.Length` (the long members are `TryMatch` with `long` ranks, `LongCount`, `Locate`). The loop of S1 is **pinned by a hash of its text** (`NarrowingLintTests.TheThirtyTwoBitLoopOfMappedSearch_IsTheTextThatS1Gated_ByteForByte`): "the S1 hot path is untouched" is a test.
* **C. `EsaIndex`** (`Search`, `Matching`, `Analysis`, `Traverse`): `TextLength` (`long`; `Length` is the `int` bridge that names `TextLength`), `LongCount`, `TryMatch(long, long)` (the in-memory index answers with the numbers of the 32-bit descent, widened), `Locate(long lo, long hi, long skip, Span<int|long>)` over `PageOf` (a page may start above rank 2^31 and hold positions above 2^31), `FindAllOccurrences` (an `int` list: `NotSupportedException` when it cannot fit); the analysis at `long` (LRS depth, rank and count; the ties; the distinct substrings in `Int128` narrowed by `ToCount`; the distinct substrings by length); `Traverse` over `IWideTreeVisitor` (the events carry 64-bit start, end, leaf count, child count and depth; `NarrowingVisitor` adapts the 32-bit `ISuffixTreeVisitor` through the checked bridge); `LcpIntervalScan` at `long` for an LCP array of any size and kind (`Run` of the wide form; the 32-bit scan stays for S1); `LeftmostOccurrence` at `long` (its result is a managed table of `n + 1` entries: a text whose table cannot exist is refused by name before the first event); `CompactLcp.LongCursor`.

No public signature changed; no public member was added (neither red test needed one).

**Design choices and the alternatives that were rejected**

1. **Two paths, selected once per index (kept); one generic long path for every container (rejected, measured).** The brief leaves open whether the long descent also serves the containers of S1. Built and measured against the S1 head (`MappedSearch` sends every container to variant 12; `abapp`, 5 processes, B / A, present / absent / locate; `results_s24_abapp_rows_alternative.txt`): `dna_10m` `file:1` **0.934 / 0.910** / 1.014, `fileT:1` **0.955 / 0.968** / 1.034, `prot_1m` `fileT:1` 0.999 / **0.946 / 0.923**, `rep_10m` `file:4` 0.979 / 0.988 / 0.990: 3 - 9 % of the S1 rows lost on count, which the brief forbids. The long registers, the symbol-by-symbol compare and the second reader indirection cost that; the narrow loop is kept and the long one is next to it.
2. **The stored width as a second struct strategy** (ADR 3.3): `IPosReader` is the type argument, not a runtime branch; `Pos32` is the 4-byte read of S1, `Pos40` one unaligned 8-byte load and a mask. The matrix is a switch in `WideSearcher.Create` and a test parameter (`WideDescentTests.TheSwitchOfTheMatrix_...16Instantiations`).
3. **The 32-bit members of a wide index refuse by name** instead of wrapping: `IntBridge.Length` is the `NotSupportedException` that names the member and the long one; `IntBridge.Value` is the `InvalidDataException` of a value that came from a file. No new unchecked narrowing: the lint.
4. **The locate of a short list** (the one hot-path decision that took five builds; see the A/B section): the lists of `FindAllOccurrences` are `int[]`; `SaView.ToArray` is the plain `new int[count]` of S1 below 512 entries, and `ToArrayUninitialized` (out of line, `GC.AllocateUninitializedArray`) from 512 entries up (2,048 bytes: below that the runtime zeroes the array anyway, so the call only adds its dispatch to a protein 4-mer); the bridged copy of a 5-byte section is out of line (`CopyBridged`), so that the copy of an array and of a 4-byte section stays the small code of S1 (the S2.3 form had inlined the loop into `FindAllOccurrences`: 730 bytes against 556 at tier 1).
5. **Not done: a second long descent as a readable reference** (`DescendMappedWide`, written in the first implementation, never called, found by three surviving mutants of the audit, deleted): the reference of the tests is the 32-bit descent of S1 (`EsaIndex.DescendMapped`), which every damaged-table test compares with exactly.
