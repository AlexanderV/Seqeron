**The four gaps and their closure.**
* **G16** (`false` compared case-sensitively): the cells `FALSE` in a checked build fail either way (as garbage), so nothing separated `false` from garbage in a default build. Closed by three cells that must HOLD: `False`, `FALSE` and ` false ` in a default build (`BuildExpectationTests`, 43 tests now).
* **A08, A17** (an explicit fixture or an ignore row matched by a PREFIX of the name): the fixtures of the tests had no two names that start alike. Closed by `test_a_name_that_only_starts_like_a_listed_one_is_unlisted` (`OnlyChecked10`, `OnlyChecked2(70)` against the rows `OnlyChecked1`, `OnlyChecked2(7)`; `SomeFuzzTestsExtra` against the fixture `SomeFuzzTests`).
* **W25** (the vectors job runs `Category=Exhaustive`): the checker looked for the filter in the text of the whole job, where the title of the summary step contains it too. Closed: the checker finds the step that runs the tests and looks for `--filter "<the category>"` in that step.

**What the first pass of the audit also showed about the guard** (the `evidence` column of `results_s22_guard.tsv`): for **G03** (the variable is ignored), **G04** (BoundsChecked is ignored), **G05** (the condition is inverted), **G06** (another variable), **G07** (the process verdict inverts the build), **G08** (the live test fails when the rule holds), **G09** (the live test drops the failure) and **G17** (the build of the assembly is ignored) the live check `BufAndArenaTests.BuildMode_...` PASSES a dishonest build (a default build with `ESA_EXPECT_BOUNDS=true`), that is, the guard that the CI relies on is blind: all eight are killed only by the tests of the rule and of the glue in `BuildExpectationTests`, which run without any variable (the configuration of the default CI). That is why the rule was moved into `BuildExpectation` and pinned: the existing single test would have let all eight survive.

**Not mutated, said once.** `trx_summary.py` (six Python tests exist; not audited: it formats a summary and cannot make a run green or red); the YAML semantics that only GitHub evaluates (actionlint is not installed here and the workflow cannot run before the owner merges it); the host rows of `skips.tsv` (found by a run with a `mount` that fails; their number, 9, is pinned by a test of the list, their content by that run); `gen_inputs.py` and the test classes it feeds (S1).
