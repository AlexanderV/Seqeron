# The other programs of the MUMmer 3.23 package

Audit items A3-9d / A3-9e / A3-9f (B09 F204 ...). Every program of `dpkg -L mummer` that is not part of the nucmer / delta toolchain (see [Nucmer_And_Delta_Programs.md](Nucmer_And_Delta_Programs.md)) is ported here and compared with the installed binary (Debian `mummer 3.23+dfsg-8`; the sources are the Debian source package `mummer_3.23+dfsg.orig.tar.xz` with its patches applied - `addition_from_mugsy.patch` (delta2blocks, delta2maf), `0009-improve-performance-of-delta2maf.patch`, `mummerplot.patch`, `gnuplot.patch`, `remove-csh-dependency.patch`). The oracle generators are in `scripts/alignment/`, the recorded runs are embedded test data (`TestData/Alignment/*.jsonl.gz`).

## `mummer` (A3-9e)

`MummerProgram.Run` is the `mummer` command (Kurtz' `maxmat3`, `src/kurtz/mm3src`: `maxmatopt.c` options, `maxmatinp.c` file reading, `procmaxmat.c` output, `findmaxmat.c` / `findmumcand.c` matching, `cleanMUMcand.c` the `-mum` filter). MCP tool `mummer`.

* **Input.** `scanmultiplefastafile`: every `>` outside a description starts a record (the first white-space delimited word of the header is its id; the line is otherwise ignored), residues are lower-cased, white space is dropped, the records are joined by one separator byte (255). Residues before the first `>` belong to the first record. A file without `>` ("no sequences") or without residues ("empty sequence"), and an empty file, abort the program. With `-n` every residue that is not `a c g t` becomes a replacement byte (252 in the reference, 251 in the query) that matches nothing; without `-n` all bytes are letters of the alphabet (so `mummer` also finds matches in protein text, which `promer` relies on).
* **Matches.** The program walks a suffix tree of the reference; for every query suffix `i` it reports the reference suffixes that share a prefix of at least `-l` characters with it and are left-maximal (`maxmatch`), or those whose longest match is unique in the reference (`mumreference`: the longest prefix of the query suffix that occurs in the reference ends inside a leaf edge, i.e. occurs exactly once; the terminator of the tree makes a match that touches the end of the reference unique like any other), and for `-mum` additionally the ones unique in the query (`mumuniqueinquery`: candidates sorted by reference start / descending length, those whose right end is not beyond the previous one are dropped). The port builds the suffix array of the joined reference with a terminator **greater than every byte**, which is the order the tree enumerates its leaves in (verified: sentinel low fails 69 of 300 random runs, sentinel high none), follows the suffix link of a suffix-array interval with the inverse array and the LCP array and narrows by binary search. `maxmatch` lists the occurrences of one query position in suffix order; `-mum` lists by reference position.
* **Output.** Per query record a header `> id` (` Reverse` for the reverse strand, `  Len = n` with `-L`), then `%8lu  %8lu  %8lu` (reference position, query position, length); several reference records (or `-F`) print `  id<padding>  %8lu  ` with the reference id padded to the longest header (including its terminating newline in the program's count) and the offset in the record. The reverse strand matches the Watson-Crick complement read backwards (`wccSequence`: IUPAC pairs `r/y m/k b/v d/h`, `s` `w` self, every other character becomes `n`, replacement bytes stay); `-c` prints `querylen - start` instead of `start + 1`. `-s` prints the matching text below each match.
* **Errors.** `-b` with `-r`, `-c` without `-b` / `-r`, `-l` not a positive integer, no query file, more than 32 query files, `-mum` with `-maxmatch` / `-mumreference` ... are errors of the program (`ArgumentException`); the file errors are `FormatException`.
* **Standard error.** `MummerTextOutput.Messages` holds the deterministic stderr lines (`# reading input file`, `# construct suffix tree`, `# matching query-file`); the three timing lines of the program (`# CONSTRUCTIONTIME`, `# COMPLETETIME`, `# SPACE`) are not reproduced.

**Oracle.** `scripts/alignment/generate_mummer_cli_oracle.py`: 700 recorded runs (`TestData/Alignment/mummer_cli_oracle.jsonl.gz`; 653 normal, 47 error runs; `-mum` 111, `-mumreference` 202, `-maxmatch` 340; 327 multi-record references, 310 with reverse strand, 126 with `-s`, 156 with several query files; text before the header, CR LF, N / IUPAC / odd characters, empty records): stdout and the deterministic stderr lines **700 / 700 equal**; a further 2 500 runs of seed 77 equal during the port.

## `promer` (A3-9d)

`PromerProgram.Run` is the perl script `promer` (3.07) over its four programs; MCP tool `promer`. Sources: the installed script, `prepro.cc`, `translate.cc` / `translate.hh`, `postpro.cc`, `sw_align.cc` / `sw_align.hh`, `sw_alignscore.hh`, `mgaps.cc`, `show-aligns.cc`, `show-snps.cc` (MUMmer 3.23, Debian source package).

1. **`prepro` (`PromerPrepro`, `MummerTranslate`).** The DNA records (`Read_String`: lower case, anything but a letter or `*` becomes `x`) are translated in the six frames (`Translate_DNA`: the 16 symbol IUPAC code `transdna`, the universal code `universal`, `compdna` for the reverse frames; tables extracted by `scripts/alignment/extract_mummer_promer_tables.py`). An ambiguous codon gives `X` (or `B` / `Z` where the code is unambiguous between two amino acids); a character that is not an IUPAC nucleotide (`e`, `z`, `*`) warns `WARNING: Forcing unrecognized DNA char to N` in a forward frame; in a reverse frame the program reads `compdna [-1]`, the word in front of the array, which is 0 in the installed binary (the character acts as `t`, no warning; measured with `prepro` on `ccc?ccc` for 14 letters; the oracle contains such characters). Every frame is ended by the mask character; a stop is written `J`; a stretch of at most `-m` residues between two stops or a sequence end is masked (`X` in the reference, `O` in the query; a stretch of `X` in the query becomes `O`). The reference output is one record `>allcontigs file` with all frames of all sequences, 60 characters per line, the query output a record `>id.frame` per frame.
2. **`mummer -mumreference -l 6` (`MummerProgram`).** The translations are matched as text (no `-n`: every letter is a letter of the alphabet, the output is lower-cased, so reference `x` never meets query `o`, but a stop `j` meets a stop `j`). Matches are used directly (`MummerProgram.Enumerate`), not through text.
3. **`mgaps -l 20 -s 30 -f 0.11` (`NucmerClusters` + `MummerMgapsText`).** `mgaps` passes the header line of a block without a cluster (the port writes it as the program does; `postpro` ignores such blocks).
4. **`postpro` (`PromerPostpro`).** Reads the clusters, maps a start in the concatenation back to (sequence, frame, position) with `refLen = (len + 1) * 2` and `(len - (i % 3)) / 3 + 1` per frame (so a sequence shorter than 2 nucleotides shifts the coordinates of the following sequences, as in the program), sorts the clusters of a (reference, query) pair with the `std::sort` of libstdc++ (`LibstdcxxSort`), extends them with the routines it shares with `postnuc` (`MummerExtension`: `extendBackward` / `extendForward` over `NucmerSwAlign.AlignEngine` with the BLOSUM 45 / 62 / 80 tables, `GOOD_SCORE` 10 / 8 / 8, gap open -10, extend -1; give-up distance `-b` in amino acids, default 60), and writes the delta file: nucleotide coordinates `transC` of the first / last residue (the last base of the codon, `+-2`), error counts from the translated frames (`1 > MATCH_SCORE` counts the similarity errors, stops count as non-alphabetic), delta values in amino acids. `-x 0` warns and uses BLOSUM 62, another invalid value warns and is ignored; `-b` outside 1 - 10 000 warns and is ignored; with `-d` the cluster file lists the clusters with signed frames and three nucleotides per residue.
5. **`show-coords -r`** (with `-o`) is `MummerShowCoords` (already read PROMER files).

**`show-aligns` / `show-snps` on PROMER delta files.** The coordinates are translated back to amino-acid positions and frames (`frame += (s + 2) % 3`, `s = (s + 2) / 3`), the frames are translated, `show-aligns` prints the three rows reference / match row / query (the match row shows the identical residue, `+` for a positive BLOSUM score, a blank otherwise; `-x` selects the matrix; the score is read from the flat `int [4][26][26]` array like the program, so a stop `*` against a letter reads the neighbouring row), `show-snps` reports amino-acid substitutions (`Norm`: position `c * 3 - (3 - |f|)` on the nucleotide strand, reverse frames by `len - c + 1`). A context that reaches past the end of a translated frame holds the zero byte of the translation and the program prints it with `c_str ()`: the context ends there (a frame 2 / 3 translation is one or two residues shorter than the `length / 3` the program tests against).

**Oracle.** `scripts/alignment/generate_promer_oracle.py`: 320 recorded `promer` runs (`TestData/Alignment/promer_oracle.jsonl.gz`; random proteins back-translated with random codons, copies mutated at the amino-acid level with substitutions / in-frame indels / frame shifts, both strands, several records, N / IUPAC / untranslatable characters, lower case, tiny records; every option family `--mum --mumreference --maxmatch -l -c -g -b -d -m -x --noextend --nooptimize --nodelta -o -p`, `-x 0 / 9`, `-b 0 / 20000`, `-m -2`): the `.delta` / `.cluster` / `.coords` text, the stderr text, and the temporary files `.aaref`, `.aaqry`, `.mgaps` (computed with the sub-programs by hand) **all equal on 320 / 320** (9 of them the aborts: a file without sequence); a further 1 920 runs (seeds 20261201 x 420, 99 x 1 500) equal during the port. `scripts/alignment/generate_promer_show_oracle.py`: PROMER delta files of gene-like inputs and of genome-like contig sets (`promer_show_oracle.jsonl.gz`, 105 cases): `delta-filter` 210, `show-coords` 315 (also `-k`), `show-aligns` 210 (also `-x`), `show-snps` 315 (also `-S`, `-x`), `show-diff` 210, `show-tiling` 234 (also `-R`, `-x`, the `-t -u -p` files) **all equal**; two more seeds (125 and 400 cases, 7 458 runs) equal.

## `gaps`, `delta2blocks`, `mummer-annotate`, `run-mummer1` (A3-9e)

Sources: `gaps.cc`, `delta2blocks.cc` (Debian `addition_from_mugsy.patch`), `annotate.cc`, the installed `run-mummer1` script (MUMmer 3.23 / Debian 3.23+dfsg-8). MCP tools `mummer_gaps`, `delta2blocks`, `mummer_annotate`, `run_mummer1`. Oracle: `scripts/alignment/generate_mummer_gaps_oracle.py` (`TestData/Alignment/mummer_gaps_oracle.jsonl.gz`, 865 rows).

* **`gaps` (`MummerGaps`).** `scanf ("%ld %ld %ld")` triples (a partial triple at the end keeps the earlier values of the missing fields), `qsort` by the second start (glibc's merge sort: ties keep the input order - verified with tied starts in the oracle), the dynamic programme of `mgaps` without the diagonal penalty (score = sum of lengths minus the overlap with the previous match, overlap = the larger of the two overlaps), the best chain is *Consistent*, the rest *Other* (a gap is printed only after the match the line chains to). The program never terminates on text that is not a number (the port refuses it) and crashes (SIGSEGV) on an empty list (refused). **259 / 259 equal**, the empty list crashes in both.
* **`delta2blocks` (`MummerDelta2Blocks`).** One line per alignment of one (reference id, query id) pair: `refId qryId sR eR sQ eQ` (`%d` of a `long`: the low 32 bits) and the run-length CIGAR of the three-row alignment of `show-aligns` (`M` equal characters, `X` differences, `I` a positive delta = a base only in the reference, `D` a negative one); `-q` / `-r` sort with `std::sort`. On a PROMER delta file the program indexes a null array and crashes (refused with `InvalidOperationException`). **226 / 226 equal**, 20 / 20 promer crashes.
* **`mummer-annotate` (`MummerAnnotate`).** `fgets (Line, 200, ...)` chunks, every line echoed; a `>` line names the first sequence file (read again at every `>` line; a line `Wrap` is skipped) and a tag `reverse` toggles the reverse complement of the query; a digit line is parsed with `sscanf ("%ld %ld %ld %s %s %s")` (missing fields keep their old values), `none` / a word = overlap 0, a numeric overlap is used as written (so the `-5` of `gaps` makes `Olap = -5`), a gap starting with `-` is skipped; the stretch `Start - gap - 10 ... gap - olap + 20` of both sequences is aligned by the edit-distance recurrence of the program (`D(i,j-1) + 1 + [Op != d]` ...) and printed as `Errors = n`, `T:` / `S:` / marks 60 columns per block, a stretch of 10 000 or more prints `*** Too long ***`; `witherrors.gaps` gets every line with the error count (`%7d`). **230 / 230 equal** (windows inside the sequences). **Genuine non-determinism (the one BLOCKED class), proven:** a window that reaches before the first base reads memory in front of the 10 000 byte buffer - `valgrind` reports `Invalid read of size 1 ... 13 bytes before a block of size 10,000 alloc'd` on all 14 crafted runs and the output of three of them changes under `MALLOC_PERTURB_=165`; the port refuses such a window with `InvalidOperationException` (beyond the end the buffer holds zeros, which the port reads).
* **`run-mummer1` (`MummerRunPrograms.RunMummer1`).** `mummer -mum -l 20 "$rev" ref qry | tail +2 > pfx.out`, `gaps ref "$rev" < pfx.out > pfx.gaps`, `mummer-annotate pfx.gaps qry > pfx.align`, `mv witherrors.gaps pfx.errorsgaps`. Without the fourth argument `-r` the script passes an empty argument to `mummer` (it fails: `cannot open file ""`), `gaps` then crashes on the empty file - the script fails (refused); with several query records `gaps` meets a second `> id` line and never terminates (refused). **55 / 55 successful and 60 / 60 failing runs equal.**

## `delta2maf` (A3-9e)

`MummerDelta2Maf.Run` (source `delta2maf.cc`, Debian `addition_from_mugsy.patch` + `0009-improve-performance-of-delta2maf.patch`; MCP `delta2maf`; oracle `scripts/alignment/generate_delta2maf_oracle.py`, 375 rows): `##maf version=1 scoring=single_cov2`, then for every alignment (all alignments of the records that match the optional reference / query id; `-r` / `-q` sort with `std::sort`) `a score=|eR - sR|` and two `s` lines `s id start length strand sourceLength text` (0-based start, `-` strand = the reverse complement of the sequence read with the coordinates counted from its other end, `-` for a gap, the program writes `%d` of a `long`: the low 32 bits), then `##eof maf` without a newline. `forceDNA` is on, so a PROMER delta file is read as nucleotide deltas and runs past the sequences (refused). The two FASTA files are read into one `map` by id with `insert` (the first record of an id wins). `-w` only sizes the output buffer (the text does not change), values of 11 or less warn. No alignment for the ids: `Could not find any alignments`, exit status 1, the maf header already printed. **315 / 315 equal + 60 / 60 error rows.**

## `nucmer2xfig` (A3-9e)

`MummerNucmer2Xfig.Run` is the perl script `nucmer2xfig` (Steven Salzberg 2001; MCP `nucmer2xfig`; oracle `scripts/alignment/generate_nucmer2xfig_oracle.py`, 260 rows). It reads a coords file of `show-coords -c -l` (19 fields: `s1 e1 | s2 e2 | l1 l2 | %idy | lenR lenQ | covR covQ | idR idQ`, header lines removed) and writes FIG 3.2: per line a green line (colour 2) from `int (0.005 s1)` to `int (0.005 e1)` (one pixel wider when equal) at height `20 (identity - 50)` (identity below 50 is 50), per contig (consecutive lines of one query id; a line whose start is more than `2 lenQ` from the previous one closes the contig and starts a new one) a blue line (colour 1) at height 20 x 50 once its stretch is more than 1 000 bases, with a vertical label when the stretch is wider than 40 pixels, the reference id with a red line of `0.005 lenR` pixels, an x tick every 250 000 bases and y ticks for 50 ... 100 percent. Perl's behaviour is reproduced: the numeric value of a field is its leading number (a word is 0, `1e2` is 100, `12abc` is 12), a missing field is undef (0 / empty), `printf ("%.0f")` rounds half to even (`CFormat.Fixed`), the label text ends with the two characters `\001` written literally. **260 / 260 equal**, including malformed lines and an empty file (the output then is the header, the reference line with empty fields and the tick marks).

## `nucmer -p|--prefix` and `promer -p` (A3-9f)

What the scripts do with the prefix (installed `nucmer` / `promer` perl scripts, checked against 170 recorded runs of `nucmer`, `scripts/alignment/generate_nucmer_prefix_oracle.py`, `nucmer_prefix_oracle.jsonl.gz`): they test that `<pfx>.ntref` (`.aaref`, `.aaqry` for promer), `<pfx>.mgaps`, `<pfx>.delta` (`<pfx>.coords` with `-o`) can be created (the prefix may contain a directory, which must exist: otherwise `ERROR: The following critical files could not be used` and the file `nucmer.error`), run `prenuc`, `mummer | mgaps`, `postnuc <pfx>` and `show-coords -r <pfx>.delta > <pfx>.coords`, and delete the temporary `.ntref` and `.mgaps` at the end (`promer`: `.aaref .aaqry .mgaps`). What is left: `<pfx>.delta` (`<pfx>.cluster` instead with `--nodelta`; both are never written together) and `<pfx>.coords` with `-o`. A run that fails after the temporaries were written (`--nodelta -o`: `show-coords` has no delta file) leaves them behind and writes `nucmer.error`.

In the API: `NucmerOptions.Prefix` / `PromerOptions.Prefix` (default `out`) name the files of `NucmerResult.Files` / `PromerResult.Files` (`out.delta`, `out.cluster`, `out.coords`) and the temporary files in the log; `NucmerResult.Log` is the standard error of the whole script in order - `1: PREPARING DATA`, the warnings of `prenuc` (`Unexpected character`), `2,3: RUNNING mummer AND CREATING CLUSTERS` with the reading lines of `mummer` (`# reading input file "<pfx>.ntref" of length N`, `# construct suffix tree ...`, `# reading input file "<query>" of length M`, `# matching query-file ... against subject-file "<pfx>.ntref"`; its timing lines `# CONSTRUCTIONTIME`, `# COMPLETETIME`, `# SPACE` are not reproduced), `4: FINISHING DATA`, the warnings of `postnuc`, `5: GENERATING COORDS FILE` - equal to the real standard error on all 123 successful recorded runs (54 with a custom prefix, 15 in a sub directory, 18 `--nodelta`, 29 `-o`); the 5 recorded runs that fail inside the programs fail in the port too (the checks of the script that need the file system - a prefix in a missing directory, two matching algorithms - are not part of an in-memory API). MCP `nucmer` has the parameter `prefix` and returns `files` and `log`; MCP `promer` returns the same names through its prefix.

## `combineMUMs` and `run-mummer3` (A3-9e2)

`MummerCombineMums.Run` (source `combineMUMs.cc`, Delcher; MCP `combine_mums`; oracle `scripts/alignment/generate_combinemums_oracle.py`) reads a gaps file of `mgaps` (`> id` / `> id Reverse` lines, `#` between clusters, `start1 start2 length ...` lines), the first record of the reference and the query records in the order the forward blocks ask for them (a reverse block reverse-complements the query in place and the next forward block reads the next record). For every cluster it extends the first match backwards and the last one forwards (`Rev_Prefix_Edit_Dist` / `Prefix_Edit_Dist` with `extending` true: diagonal bands in steps of at most `MAX_EXTENSION = 10 000` bases, repeated while an extension is longer than 9 000) and aligns the gap between two matches (`Prefix_Edit_Dist` with `extending` false, at most `MAX_ERRORS - 1 = 499` errors) with the `Edit_Array` of the program (one array, rows at the offsets `2 + 6 e + e (e - 1)`, the cells next to the band set to -2). The scoring that decides where an extension ends is single precision (`float Branch_Pt_Match_Value = 0.272`, `Row * value`, `Longest * value - e`, compared as doubles; `-e rate` makes it `(float) (1 - (1 - rate))`), give-up length 200. Output: the gap line, `   No extension` or `     Errors = n` with the alignment (rows `A:` / `B:` and a mark row `=` for the 10 bases of the flanking matches, `^` for a difference, 60 columns), `Region:  ref .. ref  qry .. qry  errors / length  percent` for every combined region (a reverse region prints `1 + Query_Len - position`), `-D` (positions of the differences: `%-15s %-15s %8d %8d  %c  %c`), `-S` (`%8ld %8ld:  a  b` / `ins` / `del`), `-v` (every extension, `Rev_Display_Alignment` with an empty line before each block); `witherrors.gaps` (`-W`) gets the gap lines with `%7d` errors (`-` for the first match and for `No extension`; nothing for a `-D` gap), the `.cover` files (`Show_Coverage`, unless `-x`) the regions and gaps with their N counts and the summary goes to standard error. Read as the program reads: its own `Read_String` (the whole header line is the name, `*` is not a residue, `fgets (Line, 1024)`), `fgets (line, 1024)` chunks for the gaps file, `sscanf ("%ld %ld %ld")`.

Reproduced behaviours of the program: the query buffer is one block that every record is read into again, so the coverage of the query counts the bytes a longer earlier record left behind when the covered regions of earlier records reach beyond the last record (`StoreQuery`); the coverage list of the query accumulates over all records. **Genuine non-determinism (the one BLOCKED class), proven:** the reference buffer is `realloc`'d to `Ref_Len + 1` bytes and `Show_Coverage` takes `strlen (Ref + 1)`, i.e. reads the byte after the block - when `Ref_Len` is 7 modulo 16 that byte is the size field of the next heap chunk (`valgrind`: `Invalid read of size 1 ... 0 bytes after a block of size N alloc'd` on all 36 recorded runs; the printed length is 2520, 2519 or 2521 for the same input under `GLIBC_TUNABLES=glibc.malloc.tcache_count=0` / `MALLOC_MMAP_THRESHOLD_=50000` / default): the port refuses the coverage of such a reference (`-x` has no strlen and is unaffected: `run-mummer3` always passes `-x`). Coordinates beyond a sequence read outside the buffers (the output changes under the allocator tuning on the 5 crafted runs: recorded, refused). Failed assertions (no reference record, fewer query records than forward blocks, a gaps line that is not three numbers, a header line without newline) are `FormatException`s (the program aborts: 9 recorded runs).

`MummerRunPrograms.RunMummer3` (MCP `run_mummer3`) is the script: `mummer -mumreference -b -l 20 ref qry > pfx.out`, `mgaps -l 100 -f .12 -s 600 < pfx.out > pfx.gaps` (`MummerMgaps`, the text front end of `NucmerClusters` / `MummerMgapsText`), `combineMUMs -x -e .10 -W pfx.errorsgaps ref qry pfx.gaps > pfx.align`; the standard output is `Find MUMs` / `Determine gaps` / `Align gaps`, the standard error the lines of `mummer` followed by the summary of `combineMUMs`. **combineMUMs 244 / 244 recorded runs equal** (239 random: every option, both strands, upper case, N / IUPAC characters, multi-record queries, raw `mummer` output with overlapping matches as the gaps file; 5 extensions of 24 kb in up to three steps; 14 crafted inputs) **+ 24 undefined + 9 failing (assertion aborts, one segmentation fault); run-mummer3 216 / 216 recorded runs equal** (files, standard output, standard error; 4 failing runs fail in the port); 3 000 more random runs of each (seeds 11 - 13) equal.

## `repeat-match` and `exact-tandems` (A3-9e3)

`MummerRepeatMatch.Run` (source `repeat-match.cc`, Delcher 2002; MCP `repeat_match`; oracle `scripts/alignment/generate_repeatmatch_oracle.py`) is a line-by-line port of the program's own suffix tree, because the listing order is the order of that tree: `Build_Suffix_Tree` (McCreight with suffix links over `Data = % genome $ revcomp(genome) $`, nodes and leaves in parallel arrays, a new leaf / node is put in front of its siblings, `New_Find_Child` / `New_Jump_Down` / `New_Step_Down` with the common split code written once), `Add_String` (the reverse complement into the same tree, with `Add_Duplicates` for suffixes that already exist; a genome that is its own reverse complement prints `*** Genome is exact palindrome ***` and exits with 255), `Set_Subtree_Size`, `Mark_Skipable_Nodes` and `List_Maximal_Matches` (the walks of the program recurse child subtree, then sibling, then the node itself; the port keeps that order with an explicit stack, so a repeat of 10^5 bases does not overflow the stack), `List_Matches` (`%9d %10d%c %8d`; `r` for the reverse strand, `-t` keeps `L + n >= R`), the exhaustive `-E` search and the `-V` outputs (`Node size = 24`, `Leaf size = 12`, `Verify_Match`, the per-node lines of `-V 2`). Standard error: `Verbose = n` (first), the `Unexpected character` warnings, `Genome Length = n   Used m internal nodes`. **370 / 370 recorded runs equal** (every option; both strands; N / IUPAC; CR LF; non-letter characters; multi-record files; 6 genomes of 6 - 30 kb and 5 homopolymer / dinucleotide / trinucleotide arrays of 1 200 - 5 000 bases; 24 stops of the program, 1 illegal `-n`), 3 300 more random runs equal; valgrind clean on 110 random runs. **Genuine non-determinism (the one BLOCKED class), proven:** an empty file or a file without a `>` line never writes the sequence buffer (`valgrind`: use of uninitialised values; under `MALLOC_PERTURB_=165` the program reports a genome of 9 999 bases) - refused; a header whose first word has 500 characters or more overflows the 500 byte name buffer (`*** buffer overflow detected ***`, abort: 3 recorded runs) - refused.

`MummerExactTandems` (MCP `exact_tandems`): `repeat-match -t -n N file | tail +3 > $$.tmp.matches`, `sort -k1n -k2n`, `awk -f tandem-repeat.awk` (header `%8s %8s %8s %10s`; a match is skipped when `start + length < start2` or its start equals the previous printed start; `start`, `extent = start2 + length - start`, `unitlen = start2 - start`, `extent / unitlen` as `%10.1f`). `Run` is that intended pipeline (**215 / 215 recorded runs equal**, 1 200 more). The installed script is broken - its last command reads `awk -f $` and, on the next line, `$scriptdir/tandem-repeat.awk` - so `awk` fails with `awk: fatal: cannot open source file `$' for reading: No such file or directory` and status 2, and `sh -e` stops there with `$$.tmp.matches` left behind: `RunInstalled` reproduces the script's standard output (`Finding matches`, `Tandem repeats`), the standard error of `repeat-match` followed by the message of `awk` (gawk of the oracle machine), the status 2 and the leftover file (**215 / 215 recorded runs equal**, 1 200 more; the 4 usage errors of the script are file-system checks and have no in-memory meaning). `repeat-match` failing (`-n` below 1, a palindrome) does not stop the script (the pipeline's status is `tail`'s).

## `mapview` (A3-9e4)

`MummerMapview.Run` (source `scripts/mapview.pl`, the installed perl script; MCP `mapview`; oracle `scripts/alignment/generate_mapview_oracle.py`) is ported with the Perl semantics the script relies on (`MummerPerl`: numeric conversion of strings - `12abc` is 12, an undefined value is 0 and prints as the empty string -, `split` on white space, `int`, `%.0f` with ties to even, `%.15g` for numbers): the coords file (`show-coords -rl` of nucmer or promer; the second line gives the program name used in the default file prefix, the header line gives the columns `[S1]`, `[E1]`, `[% IDY]`, `[LEN R]` by their index among the `|` / `[...]` tokens, the reference id is the second field from the end and the query id the last) is read to get the reference lengths, the reference is partitioned into `-n` files of `int (sum of lengths / n)` bases (one file per group of references for several references), and every file gets the FIG header, the grid (reference bar, 50 / 75 / 100 percent identity lines and labels, a tick and label per 10 000 bases at `x / 14.5` pixels), the alignments (a red line at `3000 + 250 + 2000 - 40 (identity - 50)`, a thick line at 3150), the link lines between the alignments of one query contig (three colours rotated for every new contig, no link when the previous match of that contig is `-d` or more bases away) and the legend. With a UTR and a CDS file in GFF format (`get_cds_ends`, `get_utrcds_info`, `get_utrcds_ends`, `test_overlap`) every gene is split into 5' UTR, CDS exons and 3' UTR (minus-strand genes in reverse), overlapping genes go to higher levels, the ranges of the files follow the gene ends (`SetTheRangeForEachFile`, `-x1` / `-x2`), and `print_genes` draws them sorted by the 5' end; the script's own state is kept (`$tmpname` and `$sign` are shared by the two GFF readers, the last gene of a contig is listed twice, `$startcoord` is undefined - empty - until a range sets it). `-g` converts mgaps output into a show-coords-like side file `<name>coords` (rows sorted numerically by the first field, the reference id from `-g`) and draws the clusters as arcs. Wrong bounds (`x1 > x2`, a negative bound) print `ERROR2` / `ERROR3` and the script goes on. `-f pdf|ps`: the script writes `tmp<prefix>_<n>.fig`, runs `fig2dev -L <format> -x 100 [-m <mag>] -M <tmp fig> <out>` and removes the temporary file; the port returns the FIG text, the command line and the output name (the conversion is done by `fig2dev`, a separate program: run by hand on port-made FIG files it writes `.ps` / `.pdf`, the oracle replaces it by a recording stub). A UTR file without a CDS file, or GFF files without a reference of the coords file, print the long `ERROR in the input files` message and exit with 1. **263 / 263 recorded runs equal** (coords of nucmer and promer, one to three references, 1 - 5 query contigs on both strands, mgaps input (`-g`, 33 runs with side file), GFF genes on both strands, `-n -p -v -d -I -Ir -f pdf|ps -m -x1 -x2`, wrong bounds), 800 more random runs (seeds 2 - 4) equal. **Genuine non-determinism, proven:** genes with equal 5' ends are drawn in perl's hash order (`PERL_HASH_SEED` changes the order): such runs would differ between runs of the program itself; the port lists them in order of first appearance, and the oracle records and skips rows whose output differs between 6 runs (random and fixed seeds).

## `mummerplot` (A3-9e4)

`MummerPlot.Run` (source `scripts/mummerplot.pl`, version 3.5; MCP `mummerplot`; oracle `scripts/alignment/generate_mummerplot_oracle.py`): `ParseOptions` (terminal / size flags and their warnings - `Multiple terminals not allowed`, `Multiple sizes now allowed` -, `--[no]color` / `--[no]coverage` / `--[no]filter` / `--[no]layout` as true / false / undefined, `-x` / `-y` ranges with `,` read as `:`, `-b` with and without a value, `--fat` implies `-l`, the file names `<prefix>.fplot` `.rplot` `.hplot` (with `-b` or `-S`) `.filter` `.gp` `.ps` / `.png`, `--color` switched off when a highlight file exists, the ports of non-x11 plots), `GetParseFunc` (the first lines decide: tiling `>id n bases`, mummer `> id`, delta `NUCMER` / `PROMER` + a numeric alignment header, cluster `[ -][1-3] [ -][1-3]`; the names in the first line of a delta / cluster file become the `-R` / `-Q` defaults and are read - the port takes them from `files`), the four parsers (`ParseDelta` with the similarity `(tot - sim) / tot * 100`, tot / 3 for PROMER, `ParseCluster`, `ParseMummer`, `ParseTiling`), `ParseIDs` (FASTA: offsets and lengths, `(length)` counts the newline; id lists: `id len [+-]`; duplicates ignored with a warning), `LayoutIDs` / `SpanXwY` (the delta is filtered with `delta-filter -r -q` and read as `show-coords -B`; the chains of sequences are laid out recursively with flips), `PlotData` (alignments sorted by ascending identity, breakpoint highlight, coverage mode, SNPs through `show-snps -H -T -l`), `WriteGP` (terminals, sizes, tics of several sequences, ranges, borders, palette, line styles, plot / splot) and `RunGP` (the gnuplot command line, `-geometry`, `-rv`, mono). The status of `system ("gnuplot --version")` is a parameter (0 found: its output line is on standard output; -1; outdated). The listener forked for x11 plots with `-rport` / `-qport` writes `Could not connect to rport / qport` after the parent's lines. **Oracle:** the script was run with a stub `gnuplot` (prints the version for `--version`, records the arguments of any other call) and a stub `xclip`, so that the script text and its messages are deterministic; the real gnuplot 6.0 renders the generated `.gp` / `.fplot` / `.rplot` of the port to a PNG (byte-identical on repeated runs) and a PostScript file (the `%%CreationDate` line differs), and the real `fig2dev` converts the port's FIG files to `.ps` / `.pdf` - checked by hand on samples. **330 + recorded runs equal** (delta of nucmer and promer, cluster, mummer `-b -c -L`, tiling; every option listed above; the dies of the script: invalid terminal / size / range, empty or unrecognised match file, no alignment data), further random runs (seeds 5, 6) equal. **Genuine non-determinism, proven:** the sequences a layout leaves out (filtered alignments) and sequences of equal length are ordered by perl's hash order (`keys %hash`; four runs of the program give four different `ytics`); the oracle compares only rows that agree in 6 runs (random and fixed `PERL_HASH_SEED`), the port uses the order of first appearance. The exit status of a `die` is the stale `errno` of the program's last system call (2, 25 or 255 depending on the environment): the port returns 2 and the oracle compares zero / non-zero.
