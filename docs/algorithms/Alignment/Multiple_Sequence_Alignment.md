## 1. Overview

Multiple sequence alignment aligns three or more sequences in one shared coordinate system by inserting gap characters until every aligned sequence has the same length. Exact optimal MSA is computationally expensive, so practical implementations usually rely on heuristics. This repository provides, besides the exact optimum (`MultipleAlignExact`, §4.7) and the program ports of §4.6 / §4.9 / §4.10, five Seqeron aligners over `DnaSequence` inputs, by default in the **linear gap model** of `GlobalAlign` (every gap position scores `GapExtend`; `GapOpen` is not used; the additive affine model `MsaOptions.GapModel = Affine`, §4.2, is available on all five):

1. `SequenceAligner.MultipleAlign(...)` — **center-star** alignment (Gusfield 1993) with *exact* pairwise alignments: all pair scores come from the canonical Needleman-Wunsch (`GlobalAlign` core), the center is the sequence with the highest total pair score, every other sequence is aligned to it with the same DP and the pairwise alignments are merged column-wise ("once a gap, always a gap"). For two sequences the result is an optimal pairwise global alignment.
2. `SequenceAligner.MultipleAlignAnchored(...)` — the approximate, faster variant of (1): 4-mer-cosine center (counts from the Core `CountKmersSpan`), suffix-tree exact-match anchors (`AnchorBasedAligner`: MUMmer-style seeds, weighted colinear chain with overlap trimming, Needleman-Wunsch on the gaps, exact Hirschberg for very large gaps). Pairwise alignments are *not* guaranteed optimal.
3. `SequenceAligner.MultipleAlignProgressive(...)` — guide-tree progressive alignment: ClustalW pairwise distances (1 − identities / shorter length) → guide tree: UPGMA by default (Higgins & Sharp 1988 CLUSTAL; Feng & Doolittle 1987 progressive scheme) or ClustalW's neighbour-joining tree (`MsaOptions.GuideTree = NeighborJoining`, §4.5) → profile-profile Needleman-Wunsch, single pass.
4. `SequenceAligner.MultipleAlignIterative(...)` — adds **iterative refinement** of the progressive seed by MUSCLE-style tree-dependent restricted partitioning (Edgar 2004), accepting a re-alignment only when the SP score strictly increases.
5. `SequenceAligner.MultipleAlignConsistency(...)` — **consistency-based** alignment (T-Coffee; Notredame, Higgins & Heringa 2000): a primary library of percent-identity-weighted global and local pairwise alignments, the triplet extension evaluated for every residue pair, and a progressive alignment that scores columns with the extended-library weights (zero gap penalties) — a distinct objective from the sum-of-pairs (SP) score the other four optimise.

The scalar-scoring overloads take `DnaSequence` inputs (validated DNA strings, `ScoringMatrix` match / mismatch scores). Every aligner except `MultipleAlignClustalW` additionally has **substitution-matrix overloads for protein and any other alphabet** (`IEnumerable<ProteinSequence>` / `IEnumerable<string>` with a `MatrixScoring`: BLOSUM62, PAM250, EDNAFULL, real-valued gap scores; §4.8, audit A1-14). MCP tools: `multiple_align`, `multiple_align_anchored`, `multiple_align_progressive`, `multiple_align_iterative`, `multiple_align_consistency`, `multiple_align_exact` (exact optimum, §4.7); the program ports `multiple_align_clustalw` (§4.6; also `iteration`, `clustering`, `type='auto'`), `clustalw_profile_align` / `clustalw_sequences_to_profile` (§4.6a), `multiple_align_muscle` / `muscle_msa_command` (§4.9), `multiple_align_tcoffee` (§4.10); and the stage tools `clustalw_pairwise_align`, `clustalw_quick_pairwise_align`, `tcoffee_slow_pair_align`, `tcoffee_lalign_top_alignments`, `tcoffee_primary_library`, `tcoffee_guide_tree`, `tcoffee_ktup_similarity`, `sum_of_pairs_score` (audit A2-36). Options shared by the five Seqeron aligners: `MsaOptions` (`GapModel`, `Distance`, `GuideTree`, `ConsistencyEngine`, `PrimaryLocalAlignments`, `SequenceWeights`, k-tuple / pairwise parameters of the ClustalW distances, `MaxDegreeOfParallelism`, `CancellationToken`).

## 2. Scientific / Formal Basis

### 2.1 Domain Context

Given sequences $S_1, S_2, \ldots, S_k$, an MSA produces aligned sequences $S'_1, S'_2, \ldots, S'_k$ of common length $L$ such that removing gap characters from each $S'_i$ recovers the corresponding original sequence. The usual MSA representation requires a common aligned length and excludes columns that consist entirely of gaps. These are the structural properties cited in the multiple-sequence-alignment reference and enforced by the repository tests.

### 2.2 Core Model

The exact MSA optimization problem is NP-complete; the current document's cited summary states that exact dynamic programming for $n$ sequences of length $L$ requires `O(L^n)` time and space. Practical tools therefore use heuristics such as progressive or center-star alignment. In a center-star approach, one sequence is chosen as the center, each other sequence is aligned to it, and the pairwise alignments are reconciled into one multi-sequence result.

For scoring a completed alignment, the document and the repository both use column-based sum-of-pairs (SP) scoring:

$$
SP = \sum_{c=1}^{L} \sum_{i<j} score\left(S'_i[c], S'_j[c]\right)
$$

where the score function is applied to every unordered pair of characters in each alignment column. (Multiple sequence alignment)

### 2.4 Properties and Invariants

| ID | Invariant | Holds because |
|----|-----------|---------------|
| INV-01 | All aligned sequences have equal length. | That is the defining representation of an MSA and is enforced by the repository after gap reconciliation and padding. |
| INV-02 | Removing gaps from each aligned sequence recovers the original input sequence. | The algorithm only inserts gap characters; it does not rewrite the input sequence content. |
| INV-03 | No output column consists entirely of gaps. | This is a structural MSA validity condition and is asserted by the repository tests. |
| INV-04 | `Consensus.Length` equals the aligned sequence length. | The repository builds consensus one column at a time across the final aligned strings. |
| INV-05 | `TotalScore` is the SP score over the final aligned sequences. | `ComputeSumOfPairsScore` recomputes the public score from the finished alignment columns. |
| INV-06 | `MultipleAlignIterative` SP score is ≥ the `MultipleAlignProgressive` seed SP score (monotonic non-decreasing). | Each refinement re-alignment is accepted only on a strict SP improvement (Edgar 2004, step 3.4); the seed is the lower bound. |
| INV-07 | `MultipleAlignIterative` is deterministic and converges. | Edges are visited in a fixed order (decreasing distance from the root, deterministic tie-break); no RNG; a pass with no accepted change stops the loop, bounded by a positive iteration cap. |
| INV-08 | The T-Coffee extended-library weight of a residue pair equals its primary (direct) weight plus the sum over intermediate sequences of `min(W1, W2)`, and is therefore ≥ the primary weight (extension never lowers a weight). | The triplet consistency transformation only adds non-negative `min`-of-legs contributions to the direct weight (Notredame et al. 2000, p.209; worked example 88 → 165). |
| INV-09 | A consistency-supported residue pair has a strictly greater extended weight than an unsupported (inconsistent) pair. | An unsupported pair is absent from the library (weight 0); a supported pair carries the positive direct weight plus triplet support (Notredame et al. 2000, p.209). |
| INV-10 | `MultipleAlignConsistency` is deterministic and produces a structurally valid MSA (equal-length rows, each degaps to its input, no all-gap column, count preserved). | No RNG; primary alignments, UPGMA tree, extension sum and DP tie-breaks are all deterministic; gaps are inserted only as whole all-gap columns. |

| INV-11 | For two sequences `MultipleAlign`, `MultipleAlignProgressive` and `MultipleAlignIterative` return an optimal pairwise global alignment (SP = Needleman-Wunsch optimum = Biopython `PairwiseAligner` with `open_gap_score = extend_gap_score = GapExtend`). | The star and the two-leaf progressive/iterative merges are exactly one canonical NW / profile NW on two single rows. `MultipleAlignAnchored` returns a score ≤ the optimum; `MultipleAlignConsistency` maximises library weights (zero gap cost), not the NW score. |
| INV-12 | The `MultipleAlign` center is argmax over sequences of the total optimal pair score to the others (ties: lowest index). | Gusfield 1993 center-star definition (the string minimising the total pairwise distance). |

### 2.5 Comparison with Related Methods

| Aspect | Repository center-star variant | Guide-tree progressive alignment |
|--------|--------------------------------|----------------------------------|
| Global structure | Pick one center sequence, then align all others to it | Build a guide tree from pairwise distances, then align along the tree |
| Sensitivity | Depends strongly on center selection | Depends on the guide tree |
| Pairwise pre-processing | All C(k,2) optimal pair scores pick the center (Gusfield); `MultipleAlignAnchored` uses a 4-mer cosine heuristic instead | Classical progressive methods compute pairwise distances before tree construction |
| Refinement | The star method has no refinement; the progressive method is single-pass; `MultipleAlignIterative` adds MUSCLE-style tree-dependent iterative refinement (Edgar 2004) | Progressive toolchains often include additional tree-driven or iterative refinement |

### 3.3 Preconditions and Validation

`SequenceAligner.MultipleAlign(...)` throws `ArgumentNullException` when the sequence collection itself is null. An empty collection returns `MultipleAlignmentResult.Empty`. A single sequence returns that sequence unchanged as both the sole aligned sequence and the consensus, with `TotalScore = 0`. `DnaSequence` normalizes inputs to uppercase, validates `A`, `C`, `G`, and `T`, and allows empty strings; the MSA tests explicitly cover empty sequences inside the collection.

## 4. Algorithm

### 4.1 High-Level Steps

`MultipleAlign` (center-star, Gusfield 1993):

1. Validate the input collection and handle trivial empty or single-sequence cases.
2. Compute the optimal Needleman-Wunsch score of every pair (canonical `GlobalAlignCore`; parallel over pairs).
3. Choose the center: the sequence with the highest total pair score (ties: lowest input index).
4. Align every other sequence to the center with the canonical Needleman-Wunsch (center = sequence 1).
5. Merge the independent center-vs-other gap patterns: for every center position the number of inserted columns is the maximum over rows; each row's inserted residues are left-justified in the slot (`MergeCenterAlignments`).
6. Build the majority consensus and the column sum-of-pairs score of the final strings.

`MultipleAlignAnchored` replaces steps 2-4 by the 4-mer cosine center and `AnchorBasedAligner.AlignWithAnchors` (suffix tree of the center, `FindExactMatchAnchors`, weighted chain, NW between anchors), then continues with steps 5-6.

### 4.2 Decision Rules, Scoring, Reference Tables, or Data Structures

`SelectCenterSequence` (anchored variant only) counts the 4-mers of every sequence with `SequenceExtensions.CountKmersSpan` (DNA input is upper-case ACGT, so every window is a valid 4-mer; the earlier private 256-slot hash gives identical counts) and picks the sequence with the highest total cosine similarity of the count vectors. During consensus construction gaps participate in the vote; ties between a nucleotide and `-` go to the nucleotide. `ComputeSumOfPairsScore` evaluates every unordered sequence pair in every column: match/mismatch from the matrix, `GapExtend` for gap-versus-nucleotide, `0` for gap-versus-gap.

**Anchor chaining (`AnchorBasedAligner.ChainAnchors`).** The anchors are maximal exact matches, one per matching diagonal run found by suffix-link streaming (not the full MEM set), so anchors from different diagonals may overlap. The chain is the maximum-total-length colinear chain (Abouelhoda & Ohlebusch 2005: maximum-weight chain of colinear non-overlapping fragments, weight = length); an anchor that overlaps its predecessor is trimmed at the front by the smallest amount that makes it non-overlapping (a suffix of an exact match is an exact match). MUMmer's longest increasing subsequence (Delcher et al. 1999) is the unit-weight, overlap-free special case. The regions between chained anchors are aligned with the canonical NW (linear gaps, same scoring as `GlobalAlign`); segments above 25 M cells use the exact linear-space Hirschberg recursion (`GlobalAlignLinearSpace`). The reported `Score` is the linear score of the returned alignment and never exceeds the unconstrained optimum.

**Anchor-chain algorithm (audit A1-16).** `ChainAnchors` evaluates best[i] = Lᵢ + max(0, maxⱼ<ᵢ best[j] − trim(j,i)), trim(j,i) = max(0, endRef(j) − refStart(i), endQuery(j) − queryStart(i)), over the predecessors that leave a positive remainder (trim < Lᵢ ⇔ endRef(j) < endRef(i) ∧ endQuery(j) < endQuery(i)), with range-maximum queries instead of the all-pairs scan (the sparse dynamic programming of Abouelhoda & Ohlebusch 2005). With the diagonal δ = query − ref, the predecessors split into δⱼ ≤ δᵢ (reference overlap is the larger one, trim = (endRef(j) − refStart(i))⁺) and δⱼ > δᵢ (trim = (endQuery(j) − queryStart(i))⁺); inside each half trim is a function of ONE end coordinate (0 when it is ≤ the new anchor's start), so each half is two orthogonal range-maximum queries — a Fenwick tree over diagonal ranks whose nodes carry max segment trees over the end coordinate. Time O(a log² a), memory O(a log a); 10⁵ anchors chain in well under a second. The chain, its score and every tie decision (earliest predecessor, earliest anchor) are identical to the former O(a²) scan, which is kept as the oracle of `AnchorBasedAligner_ChainEquivalence_Tests`.

**Progressive distance.** `1 − identical aligned residue pairs / min(|a|, |b|)` of the optimal pairwise alignment — the ClustalW distance (`pairalign.c`, clustalw 1.83: `tmat = (100 − 100·count/MIN(len1,len2)) / 100`). Equal averaged distances tie (within 1e-9) and the lowest index pair merges first. `MsaOptions.Distance = MsaDistanceMode.ClustalWAffine` (MCP `distance=clustalw`) takes the identity count from ClustalW 2.1's own pairwise stage instead (`SequenceAligner.ClustalWPairwiseAlign`, §4.2); `Linear` (default) is the repository's linear NW alignment.

**T-Coffee library.** Primary weight of every aligned residue pair of a pairwise alignment = ⌊100 · identical columns / aligned (non-gap) columns⌋ — `get_seq_sim`, mode sim1, `lib/util_lib/aln_convertion_util.c` of the T-Coffee sources; global (NW) and local (SW) entries of the same residue pair are signal-added. Extended weight of any pair (Si.p, Sj.q) = direct weight + Σ over residues Sk.r of third sequences with both legs in the primary library of min(W1, W2) (`residue_pair_extended_list`, `lib/dp_lib/evaluate.c`); a pair without a direct entry but with triplet support therefore has a positive extended weight.

**ClustalW pairwise stage (§4.2 reference, `ClustalWPairwiseAlign`).** Port of `FullPairwiseAlign::pairwiseAlign` (ClustalW 2.1; the full-DP mode of `clustalw -ALIGN`/`-TREE`): an affine **local** Smith-Waterman-Gotoh alignment (`forwardPass`: end cell = first row-major maximum, scores floored at 0; `reversePass`: start cell; `diff`: Myers-Miller divide-and-conquer with ClustalW's midpoint tie rule) with the DNA matrix IUB × 100 (`matrices.h` `swgapdnamt`: identical codes +1000, non-compatible −900; the 2.1 transition-weight lines address residue codes A-E, C-M, C-N, so A/C/G/T pairs are unchanged) and gap cost 3000 + 666·k (`PWGAPOPEN 15` → `2·15·100`, `PWGAPEXT 6.66` → `666`). Percent identity = 100 · identical aligned code pairs / min(len1, len2) in single precision; distance = (100 − that)/100; an empty sequence gives distance 1; `-ALIGN` prints `(int)` of the percent identity as "Score:". Because the Myers-Miller choice among co-optimal paths decides the identity count, the alignment is reproduced step by step (not `LocalAlignAffine`). Verified on 3 600 pairs against the installed `clustalw` 2.1.

**ClustalW PROTEIN pairwise stages (audit A1-15b part b, B09 F62).** `ClustalWPairwiseAlign(a, b, ClustalWProteinPairwiseOptions)` and `ClustalWQuickPairwiseAlign(a, b, ClustalWSequenceType.Protein, ClustalWQuickOptions?, maxLength?)` ([SequenceAligner.ClustalWProtein.cs](../../../src/Seqeron/Algorithms/Seqeron.Genomics.Alignment/SequenceAligner.ClustalWProtein.cs)) are the same two ports run with ClustalW's protein parameters (read from `SubMatrix.cpp` `getMatrix` / `getPairwiseMatrix`, `FullPairwiseAlign.cpp`, `UserParameters.cpp`, `CommandLineParser.cpp`, `matrices.h`, `FastPairwiseAlign.cpp` of clustalw 2.1+lgpl-7, sources.debian.org):
- **Matrix** (`-PWMATRIX`, `ClustalWPairwiseMatrix`): `GONNET` (default) = `gon250mt` × intScale 10, `BLOSUM` = `blosum30mt` × 100, `PAM` = `pam350mt` × 100, `ID` = `idmat` × 100, each the lower-triangular table of `matrices.h` over the packing order `ABCDEFGHIKLMNPQRSTVWXYZ` scattered to ClustalW's residue codes (`ABCDEFGHIKLMNOPQRSTUVWXYZ`; O and U have no row and score 0); the tables are `SubstitutionMatrix.ClustalWGonnet250 / ClustalWBlosum30 / ClustalWPam350 / ClustalWIdentity` (BLOSUM30 = EMBOSS `EBLOSUM30` on all 23 × 23 cells, GONNET250 = round(10 × Biopython `GONNET1992`) on the 20 amino acids, its sibling `pam250mt` = Biopython `PAM250`; PAM350 only from ClustalW's own table).
- **Gap penalties:** `matrixAvgScore = −(int)(Σ_{i>j} M[i][j] / 231f)` over the 25 residue codes (82 GONNET, 113 BLOSUM, 142 PAM, 0 ID), gap open = `(int)(2·avg·(PWGAPOPEN + ln MIN(len1, len2)))` (`2·(int)((PWGAPOPEN + ln MIN)·100)` when avg ≤ 0), gap extend = `(int)(PWGAPEXT·intScale)` in single precision (defaults 10 and 0.1); a gap of length k costs open + k·extend.
- **Fast stage:** residues are their codes (25 letters, 25^k k-tuples), defaults KTUPLE 1 (≤ 2), WINDOW 5, TOPDIAGS 5, PAIRGAP 3 (`-KTUPLE=k` sets PAIRGAP k + 3); `-SCORE`, `(Partial alignment)` and the unstable quicksort as in the DNA stage. J and '*' are not residues for ClustalW (the program drops them): `ArgumentException`.
- **Oracle** (`scripts/alignment/generate_clustalw_protein_pairwise_oracle.py`): `clustalw -TYPE=PROTEIN -ALIGN` printed `Score:` equal on **4 204 pairs** of 366 sets (4 matrices, 10 gap-penalty variants, B/Z/X, tie-heavy two-letter and repeat sequences, up to 400 residues; the identity count and the DP score also equal the line-by-line Python port with the `matrices.h` tables), `-QUICKTREE -ALIGN` `Score:` equal on **3 774 pairs** of 335 sets (k-tuple 1-2, `-WINDOW -TOPDIAGS -PAIRGAP -SCORE` variants, 357 "Not Aligned"). Note: the full stage's Myers-Miller path (the rows of `ClustalWPairwiseResult`) can re-score below the forward optimum when the length-dependent protein gap-opening penalty is huge (unrelated pairs with several gap runs); the identity count that ClustalW reports is that of this path and is reproduced.
- **MSA guide trees:** `MsaDistanceMode.ClustalWAffine` / `ClustalWQuick` with a protein `MatrixScoring` (matrix alphabet containing a non-nucleotide residue) use these stages (`MsaOptions.ClustalWProtein`: matrix, `GapOpen`, `GapExtend`, `Quick`), nucleotide matrices and the scalar scoring the DNA stages; protein progressive / iterative / consistency rows with `Distance = ClustalWAffine` (UPGMA) equal an independent Python implementation driven by the port on 60 sets x 3 methods; MCP `type = protein` + `distance = clustalw | clustalw-quick`, `pwMatrix`, `pwGapOpen`, `pwGapExtend`.

**Affine-gap MSA (`MsaOptions.GapModel = MsaGapModel.Affine`, MCP `gapModel=affine`).** *Objective (exact):* the sum of pairs with **natural** affine gap costs (Altschul 1989, J Theor Biol 138:297): for every pair of rows delete the columns that are gaps in both rows, score residue pairs with Match/Mismatch and charge every maximal run of gap columns of the projection `GapOpen + length·GapExtend` (a gap in row i directly followed by a gap in row j = two runs). `SequenceAligner.SumOfPairsScore(rows, scoring, MsaGapModel.Affine)` computes it in O(k²·L) and it is the `TotalScore` of every method under the affine model; for k = 2 it is the Gotoh score of `GlobalAlignAffine`, so a pairwise optimum is an MSA optimum. *Optimisation:* (a) star methods (`MultipleAlign`, anchored): every sequence is aligned to the center with the exact affine pairwise aligner (`GlobalAlignAffineLinearSpace`, identical to `GlobalAlignAffine`; anchored: `GlobalAlignAffineLinearSpace` between anchors), the center maximises the total optimal affine pair score; (b) progressive / iterative: a Gotoh three-state profile–profile DP (`AlignProfilesAffine`): column pair M(i, j) = Σ over cross pairs (Match/Mismatch for residue pairs, GapExtend for a residue against an existing gap, 0 gap against gap); a run of new all-gap columns against column i costs `r_i·|B|·(GapOpen + GapExtend)` at its first column and `r_i·|B|·GapExtend` afterwards (r_i = residues of column i; ClustalW/MUSCLE-style occupancy scaling); exact integer arithmetic, same Flouri border and M > own gap state > other gap state tie rule as `GlobalAlignAffine`, so for two sequences the rows equal `GlobalAlignAffine`. The iterative method accepts a re-alignment only if the *exact* natural objective strictly improves; (c) consistency: the T-Coffee primary library is built from Gotoh global and Smith–Waterman–Gotoh local alignments, the progressive DP keeps T-Coffee's zero gap penalty; guide-tree identities come from `GlobalAlignAffine` when the distance mode is `Linear`. *Optimal vs heuristic:* exact only for k = 2 (and the exact objective value for any rows). For k ≥ 3 the natural cost of a pair depends on the whole column history of both rows, which a three-state profile DP cannot track, so (a)–(c) are heuristics; on 227 random 3-sequence sets of length ≤ 6 (exact optimum by dynamic programming over (i, j, l, run state of each pair), validated against exhaustive enumeration) the affine star reaches the optimum in 170, progressive and iterative in 189 sets and none exceeds it (`SequenceAligner_MultipleAlignAffine_Tests`).

### 4.5 Guide trees (audit A1-12)

`MsaOptions.GuideTree` selects the tree that orders the merges of `MultipleAlignProgressive`, `MultipleAlignIterative` (also the edges of its refinement) and `MultipleAlignConsistency`:

- `Upgma` (default): `PhylogeneticAnalyzer.BuildTreeFromMatrix(…, TreeMethod.UPGMA)` with `TreeBuildOptions { TieTolerance = 1e-9 }` — proportional (cluster-size weighted) averaging, Sokal & Michener 1958; identical to the former private copy on 900 random and tie-heavy matrices.
- `NeighborJoining`: Saitou & Nei 1987 as ClustalW 2.1 uses it (`-CLUSTERING=NJ`, default; T-Coffee/Clustal-style pipelines). NJ is unrooted (trifurcating centre), so ClustalW (1) writes the unrooted tree (`.dnd`: 5 decimals, |b| < 1e-4 → 0, children ordered by lowest leaf index), (2) re-reads it with single-precision lengths and (3) roots it with `Tree::reRoot` (the branch giving the shallowest tree whose root-to-leaf mean difference is smallest) before `Tree::createSets` lists the merges in post-order, left subtree first. The canonical NJ builder (with `TieOrder = SecondIndexMajor` = ClustalW's `NJTree::generateTree` loop nest) supplies the unrooted tree; `SequenceAligner.GuideTree.cs` ports steps (1)-(3) line by line (`createTree`/`insertNode`/`reRoot`/`calcMean`/`insertRoot`/`groupSeqs`, clustalw 2.1+lgpl-7 `src/tree/Tree.cpp`, `ClusterTreeOutput.cpp`). With `MsaDistanceMode.ClustalWAffine` the distances are ClustalW's single-precision `(100f − 100f·count/min)/100f`.

Verification: 420 DNA sets (families, two clades, duplicate sequences, two-letter alphabets, tiny sequences; 2-11 sequences) — the unrooted tree equals the `.dnd` of the installed `clustalw` 2.1 (`-ALIGN -MAXDIV=0 -NEWTREE`; edge for edge, branch lengths ≤ 1.5·10⁻⁵) and the sizes of the progressive merges equal the "Group n: Sequences: s" lines (0 mismatches; the ordinary first-index tie order fails 21 sets). The canonical NJ equals Biopython 1.88 `DistanceTreeConstructor().nj` and the canonical UPGMA equals scipy `linkage('average')` on 400 random matrices each (Biopython's own `upgma()` averages without cluster sizes — WPGMA — and is not the reference).

### 4.6 ClustalW 2.1 multiple-alignment stage (audit A1-10b / A1-15b)

`SequenceAligner.MultipleAlignClustalW(sequences, ClustalWOptions?, ScoringMatrix?)` is a step-by-step port of `clustalw -TYPE=DNA -ALIGN` (ClustalW 2.1+lgpl-7 sources: `Clustal.cpp`, `tree/Tree.cpp`, `tree/NJTree.cpp`, `tree/TreeInterface.cpp`, `multipleAlign/{MSA,MyersMillerProfileAlign,ProfileBase,ProfileStandard,ProfileWithSub}.cpp`, `substitutionMatrix/SubMatrix.cpp`, `pairwise/FastPairwiseAlign.cpp`; Thompson, Higgins & Gibson 1994; Larkin et al. 2007). It is a separate method (not an `MsaOptions` switch of the Seqeron profile aligners) because the result is defined by ClustalW's own arithmetic, not by a scoring model:

1. **Pairwise distances** — the full DP stage (§4.2, `ClustalWOptions.PairwiseMode = Full`, `-PWGAPOPEN/-PWGAPEXT`, `-TRANSWEIGHT` also moves the C-M / C-N scores of IUB codes) or the **fast k-tuple stage** `ClustalWQuickPairwiseAlign` (`PairwiseMode = Quick`, A1-15b, below), stored as in ClustalW's `DistMatrix` (double; the full stage computes `(100 - 100·count/MIN(len1,len2))/100` in single precision).
2. **Guide tree** — ClustalW's neighbour-joining arithmetic (`ClustalWNeighborJoining`, a port of `NJTree::generateTree`: height-corrected matrix, update `(d_ik + d_jk)/2`, pair = `fnseqs2·d_ij + 2·sumd − diq − djq` in a jj-outer / ii-inner scan with strict `<`), 5-decimal print, single-precision re-read and `Tree::reRoot` (A1-12). The exact arithmetic matters for tied distances (fast-mode scores and duplicate sequences tie often): the canonical `PhylogeneticAnalyzer` NJ differs from ClustalW on such ties by rounding noise and gave a different topology on 2 of 700 oracle sets once the fast mode was included, so the ClustalW guide tree uses the ported arithmetic (the canonical builder stays the oracle-checked implementation of Saitou-Nei NJ for everything else).
3. **Sequence weights** (`Tree::calcSeqWeights`, Thompson 1994): w_i = ⌊100·Σ_branches on the path leaf→root (branch length / number of leaves below it)⌋ (single precision, root edge excluded), normalised to `INT_SCALE_FACTOR` = 1000 (Unix build) with a minimum of 1; `-NOWEIGHTS` = equal weights 1000/k. The pairwise identities used from here on come from the TREE (`Tree::calcSimilarities`: 100 − 100·(path length), clamped to [0.01, 1]), not from the pairwise stage.
4. **Progressive order and delayed divergent sequences** (`MSA::multiSeqAlign`): the internal nodes of the rooted tree in post-order (left subtree first) are the alignment steps. A sequence whose best (tree-derived) identity to any other sequence is ≤ `-MAXDIV` (30 %) is skipped in this first pass; afterwards the remaining sequences are added one at a time, the closest to the aligned set first, with weights = tree weight × identity to the new sequence, renormalised.
5. **Profile alignment** (`MyersMillerProfileAlign::profileAlign`, `ProfileBase::calcGapCoeff`, `ProfileWithSub`, `ProfileStandard`): the larger group is profile 1; profile 1 holds, for every column, `⌊(Σ_aa weight_aa·M[aa][res]/Σ weights)·(non-gap fraction)⌋` for every residue, profile 2 holds `⌊10·weight fraction⌋`; the column score is Σ p1·p2 / 10. **Position-specific gap penalties**: gap open = ⌊100·GAPOPEN⌋ = 1500, extension = ⌊100.0·GAPEXT⌋ with GAPEXT a float (6.66f → 665, not 666); a column that already holds gaps (end gaps do not count) gets ⌊(non-gap fraction)·open⌋ and ⌊0.5·extension⌋ (so alignments open gaps where gaps already are); every penalty is at least 1; the penalties at both ends of a profile are 0 (end gaps are free). **Matrix**: IUB × 100 shifted to be non-negative (−(lowest score) = +900 on every residue pair unless `-NEGATIVE`), then A-G, C-T, C-U := ⌊`TRANSWEIGHT`·M[A][A]⌋ (0.5 → 950). The two profiles are aligned by Myers & Miller (1988) with ClustalW's midpoint rule (`progDiff`).
6. For **DNA** ClustalW's residue-specific (Pascarella & Argos), hydrophilic-run and variable-region gap penalties and the gap-separation distance (`-GAPDIST`, `-NOPGAP`, `-NOHGAP`, `-NOVGAP`) are guarded by `if (!_DNAFlag)` in `calcGapCoeff`; they do not exist for DNA and are therefore not options of `ClustalWOptions`; they are the protein profile stage below.

**PROTEIN profile stage (audit A1-10c part b, B09 F63; `MultipleAlignClustalW(IEnumerable<ProteinSequence> | IEnumerable<string>, ClustalWProteinOptions, MatrixScoring?)`).** The same steps 1-5 (distances from the PROTEIN pairwise stages of §4.2 / A1-15b b: GONNET250 / BLOSUM30 / PAM350 / ID, `-PWGAPOPEN 10 -PWGAPEXT 0.1`, fast k-tuple 1), with the protein branches of `MyersMillerProfileAlign::profileAlign`, `SubMatrix::getProfileAlignMatrix` and `ProfileBase::calcGapCoeff`:

- **Matrix series chosen per profile pair** by the mean tree-derived percent identity `pcid` of the two groups (`Σ distMat(i, j) / count`, i in group 1, j in group 2) and the shorter average profile length `minLen`: BLOSUM (`-MATRIX=BLOSUM`, scale 0.75) BLOSUM80 above 80 %, BLOSUM62 (`blosum62mt2` = 2 × BLOSUM62) above 60 %, BLOSUM45 above 40 %, BLOSUM45 scale 0.5 above 30 %, BLOSUM45 scale 0.6 above 20 %, else BLOSUM30 scale 0.6; PAM PAM20 / PAM60 / PAM120 / PAM350 at > 80 / > 60 / > 40 / else; GONNET (default; tenth-bit tables, intScale 10, scale 0.375) GONNET80 (scale 0.1875) above 35 %, between 25 and 35 % GONNET250 (profiles shorter than 100) or GONNET120, else GONNET350 or GONNET160; ID = the identity matrix; `-NEGATIVE` uses BLOSUM40 / PAM120 / GONNET250 for every pair and keeps the signed matrix. The table is placed on the 25 residue codes (O and U have no row and score 0), multiplied by intScale (100; GONNET 10), and shifted to non-negative scores by the lowest cell of the lower triangle without column A (a quirk of the C++ loop `j = 1..i`) unless `-NEGATIVE`. `PrfScaleValues.scale` / `intScale` are single-precision `float`s in ClustalW, so the gap-opening product below is evaluated in float (it decides 174 versus 175 in a case of the oracle).
- **Gap opening / extension** (profileAlign): `len1`, `len2` = ⌊average number of residues per sequence of the group⌋ (float division); `logmin = 1/log10(min(len1, len2))`, `logdiff = max(0.9, 1 + 0.5·log10(shorter/longer))` (both 1 when a length is 0); open = `⌊100·GAPOPEN⌋` and extend = `⌊100·GAPEXT⌋` with `-NEGATIVE`; otherwise open = `⌊100·(float)(GAPOPEN + logmin)⌋` when the matrix average score `matrixAvgScore` (= −⌊off-diagonal sum / ((22² − 22)/2)⌋, as in the pairwise stage) is ≤ 0 (identity matrix), else `⌊scale · matrixAvgScore · (float)(GAPOPEN / (logdiff · logmin))⌋`; extend = `⌊100·GAPEXT⌋` (PROTEIN defaults `-GAPOPEN 10 -GAPEXT 0.2`; a profile of one-residue sequences has `logmin = ∞`, the C++ cast gives INT_MIN and is reproduced).
- **Per-column gap penalties** (`calcGapCoeff`): the column opening penalty is `localPenalty(open)` = ⌊open × W⌋ with W the product of the **residue-specific** factor (`calcResidueSpecificPen`: mean over the group's sequences of `180 − P(res)` for the 20 Pascarella & Argos 1992 residues, in percent; switched off by `-NOPGAP`), applied only when the column is not in a **hydrophilic run** (`calcHydrophilicPen`: a run of more than three consecutive residues of `-HGAPRESIDUES`, default `GPSNDQEKR`, at most 9 letters, in a sequence adds 100 to its columns; the mean over the sequences > 0 halves the opening penalty; `-NOHGAP` switches it off) and, with clustalw's `-NOVGAP` (sic: it switches the variable-region penalties ON), the **variable-region** factor (`calcVPenalties`: identity of the first two sequences within ± 5 columns scaled to [0.5, 1], only for profiles of exactly two sequences of more than 60 % identity, in which case the residue-specific and hydrophilic factors are off). The **gap-separation distance** `-GAPDIST` (default 4; 0 = off) marks the columns within that distance before / after a gap (gapPos < 0) and multiplies their opening penalty by `2 + 2·(gdist + gapPos)/gdist`; columns that already hold gaps keep `⌊non-gap fraction·open⌋` and `⌊0.5·extend⌋`. End gaps stay free (`-ENDGAPS` on the command line only writes `useEndGaps = false`).
- **Known residual (undefined behaviour of ClustalW).** With `-NOVGAP` and a two-sequence profile of more than 60 % identity `ProfileBase::calcGapCoeff` reads the member `gdist`, which `ProfileBase` never initialises; the profile objects are heap-allocated per alignment step and the member keeps whatever the recycled heap chunk held — 0 (never-used memory), the user's `-GAPDIST` (the chunk of an earlier profile object) or a stale residue code of a freed sequence row (the forced values found below are 0, 4, 5, 16, 20, 30, i.e. residue codes). The port emulates the usual outcome (0 for the first profile pair, afterwards `GapSeparationDistance`, with the LIFO order of the two freed profile objects); `ClustalWProteinOptions.UninitialisedGapDistances` lets a caller force the values of a specific run. Counts: of the 1 000 committed oracle sets (189 with `-NOVGAP`) 998 are reproduced by the emulation; the other 2 (both `-NOVGAP`; ids 368 and 915) are reproduced row for row with the forced values locked in the test (368: 0, 4, 0, 0; 915: 5, 0, 20) — found by scanning gdist per profile against the binary's own `-DEBUG=5` dump of every opening / extension penalty and every profile column. A 3 000-set development panel (another seed) differed on 4 sets, all with `-NOVGAP`; for two of them one forced value (16, resp. 0) explains the whole dump; for the other two the first forced values (30, resp. 0) move the first mismatch to a later profile (the scan was not carried on). A set of the 700-set development panel (gapdist 12) needed the forced value 5. Residual rate: 7 of 4 700 protein sets (0.15 %; the 1 000 committed sets, a 700-set and a 3 000-set development panel), every one with `-NOVGAP`; none without it.
- **End-gap options (audit A1-10d part 2, B09 F67; `ClustalWOptions.UseEndGaps / EndGapPenalties`, `ClustalWProteinOptions.UseEndGaps / EndGapPenalties`, DNA and PROTEIN).** `UserParameters::useEndGaps` (`ProfileBase::calcGapCoeff`: gaps at the ends of a sequence count as gaps in the position-specific penalties; menu "Toggle End Gap Separation") and `UserParameters::endGapPenalties` (`profile[0][GAPCOL] = gapCoef`, `profile[0][LENCOL] = lencoef`, and `openPenalty* / extPenalty* / gapPenalty*` no longer return 0 at the profile ends: the terminal gaps of a profile alignment are charged) are not reachable from the command line (`-ENDGAPS` only executes `setUseEndGaps(false)`), so the oracle is the Debian 2.1+lgpl-7 source built with the single edit that the `-ENDGAPS` handler reads `CW_USEENDGAPS` / `CW_ENDGAPPEN` (Docker package `docs/Validation/review-2026-09/handoff/A1-10d`, run by the user on x86-64; its control runs equal the installed binary on 340 / 340 sets). **ClustalW's abort:** `MSA::multiSeqAlign` returns -1 when the score of a profile alignment of the FIRST pass (the guide-tree steps among the non-delayed sequences; score = Myers-Miller optimum / 100, `int` division) is negative, and `Clustal::align` then returns without writing anything (exit status 0, no output file); the second pass (delayed sequences) ignores the score. With free end gaps the all-end-gap alignment costs 0, so the optimum cannot be negative; with `EndGapPenalties` it can (34 of the 340 oracle sets: 31 DNA + 3 protein). The library reports the abort as **`ClustalWAbortedException`** (an `InvalidOperationException` with `Group` = number of the profile alignment and `Score`) instead of returning an alignment ClustalW itself never produces; MCP `multiple_align_clustalw` (`useEndGaps`, `endGapPenalties`) surfaces it as a tool error.
- **Not reachable from the command line / not ported:** `-ENDGAPS` on the command line is a no-op (verified on 80 + 54 oracle sets); user matrices are the next two paragraphs.

**User-defined matrix files (audit A1-10d file part, B09 F64; `ClustalWUserMatrix`, `ClustalWMatrixFile`, `ClustalWProteinOptions.UserMatrix` / `UserMatrixSeries`, `ClustalWProteinPairwiseOptions.UserMatrix`).** Ports of `SubMatrix::readUserMatrix`, `readMatrixSeries` and the `userMat` / `matSeries` branches of `getProfileAlignMatrix` / `getPairwiseMatrix` (ClustalW 2.1+lgpl-7 `SubMatrix.cpp`; the built-in tables now go through the same `getMatrix` port, `ClustalWGetMatrix`):

- **File layout read by ClustalW** (NCBI / EMBOSS style and ClustalW's own): lines starting with `#` and blank lines are skipped; the first other line is the header, its **alphabetic characters** are the residues (any other character, e.g. the `*` of the NCBI files, is not a residue and must still own one more row: ClustalW requires exactly *letters + 1* data rows, so a file without a `*` row is rejected "wrong format in matrix"); each row has an optional leading label token (a token whose first character is a letter), then the values; **only the lower triangle is read** (junk above the diagonal is ignored); at least as many tokens as residues are required; a line starting with `#` or `!` ends the matrix. The value scale is decided **per row**: if the first value token contains a `.` every value of the row is multiplied by 10 (`(short)(f·10)`, truncated), else it is a truncated integer. A letter ClustalW does not know (J, lower case) only warns "residue ... not recognised" and shifts the stored values of the following rows - reproduced (`Cross` = -1), as are matrices with two or three residues (`maxRes < 3`: the average score becomes an x86 INT_MIN).
- **`getMatrix`** (unchanged for built-ins): the values are scattered through `Xref` into the symmetric 32 x 32 matrix over residue codes (x `intScale` 100; the pairwise matrix is never shifted, the profile matrix is shifted by its lowest cell unless `-NEGATIVE`), `matrixAvgScore = -(int)(S / ((float)(maxRes² - maxRes)/2))` over the off-diagonal cells of the 25 residue codes, unlisted residues score 0.
- **Profile stage:** a single user matrix has `intScale` 100 and gap-penalty scale 0.75; a **`CLUSTAL_SERIES` file** (`MATRIX llimit ulimit file` lines, at most 10 = `MAXMAT`, limits 0-100 with `ulimit > llimit`, other lines ignored) picks the first entry with `llimit <= pcid <= ulimit` (the first entry when none matches, with ClustalW's warning) and the scale `0.5 + (pcid - llimit) / ((ulimit - llimit)·2)` (a `float`). `-PWMATRIX=file` is a single matrix only (a series file is "single matrix expected").
- **Verification.** `clustalw_user_matrix_oracle.tsv` (`scripts/alignment/generate_clustalw_user_matrix_oracle.py`): 240 sets (single `-MATRIX` files, series of 2-4 entries with tiled / gapped / overlapping limits, `-PWMATRIX` files, both; integer / `%.1f` / `%g` rows, labelled / unlabelled, tab separated, header subsets and shuffled residue order, junk in the upper triangle, trailers, J / lower-case / 2-3 residue quirk matrices; BLOSUM / PAM / GONNET / JONES / DAYHOFF / ... from Biopython 1.88 and random matrices, plus the option variants of the protein oracle): every output row and every printed pairwise `Score:` (2 000+ pairs) equals the installed `clustalw`; a development run of 800 further sets (seed 31337) differs only on the two `-NOVGAP` sets of the documented `gdist` residual.

### 4.6a ClustalW options and commands added by audit A2-14 (B09 F101 / F102 / F103)

`ClustalWOptions` and `ClustalWProteinOptions` alike:

- **`-CLUSTERING=UPGMA`** (`Clustering = ClustalWClustering.Upgma`, MCP `clustering='upgma'`; `SequenceAligner.ClustalWUpgma.cs`): ClustalW's own rooted UPGMA tree - `UPGMAAlgorithm::doUPGMA` on the packed lower-triangular distance rows (`getNodeWithMinDist`: first minimum wins; the relative epsilon 1e-14 of `computeDistsForNodesAfterNode2`), `Node::merge` (height = distance / 2, both children get the height of the join), `RootedGuideTree::doWeightCalc` weights in single precision, the UPGMA join order as progressive steps, similarities `100 - 100 d` without the NJ path's clamping, and the `-NEWTREE` text (`ClustalWUpgmaGuideTreeText`: `RootedTreeOutput::printPhylipTree`). **Verification: 600 / 600 rows and 600 / 600 guide-tree files** of the unmodified Debian source built at `-O0` (user-run Docker package `handoff/A2-14-clustalw-upgma`, `clustalw_upgma_oracle.tsv`); the installed Debian binary and an `-O2` build of the same source segmentation-fault on every UPGMA run (undefined behaviour of the program), so the oracle is the `-O0` build. With two sequences `treeFromDistMatrix` stores no step, but `multiSeqAlign` finds no aligned sequence after the empty first pass and aligns the pair in its second pass - the rows are the pairwise alignment, as for NJ.
- **`-ITERATION=TREE | ALIGNMENT` / `-NUMITER`** (`Iteration`, `NumIterations`, default `None` / 3, MCP `iteration` / `numIterations`; `SequenceAligner.ClustalWIteration.cs`): the "remove first" iteration of `Iteration.cpp`. For every sequence i of the finished alignment (`ALIGNMENT`) or of every profile step of the progressive alignment (`TREE`) a copy is made, i is moved to the front, its gaps are stripped (the one-sequence profile 1 loses every column in which it has a gap) and the all-gap columns of the other sequences (profile 2) are removed; after an initial profile alignment with equal weights (`MSA::calcPairwiseForProfileAlign`) the sequences are weighted (profile 1: 1000; profile 2: the neighbour-joining tree weights) and re-aligned (`MSA::doProfileAlign`); the re-alignment replaces the alignment when its `ObjectiveScore` is LOWER than the best so far (BLOSUM45 x 100 pair sums over the columns between the first and last non-double-gap column plus the gap penalties added as positive numbers, single precision, truncated to a long). The program only recognises the lower-case words on its command line; `-NUMITER` > 1 changes nothing (alnPtr is only updated after the loops, so a second pass repeats the first). ### 4.7 Exact sum-of-pairs optimum (audit A1-11, B09 F60)

`SequenceAligner.MultipleAlignExact(sequences, scoring, MsaOptions)` (and `MultipleAlignExactWithStatistics`, which also returns the heuristic lower bound and the size of the problem solved; MCP `multiple_align_exact`; [SequenceAligner.MultipleExact.cs](../../../src/Seqeron/Algorithms/Seqeron.Genomics.Alignment/SequenceAligner.MultipleExact.cs)) returns an alignment whose `SumOfPairsScore` is the **maximum over all alignments**, under either objective of the heuristic methods: `MsaGapModel.Linear` (column sum of pairs, `GapExtend` per gap position, gap-gap 0) or `MsaGapModel.Affine` (Altschul 1989 natural affine sum of pairs).

- **k = 2** is `GlobalAlign` / `GlobalAlignAffine` (delegated; rows equal).
- **k >= 3: k-dimensional dynamic program.** The optimum is the best path of the lattice `0 <= x_i <= len_i` from the origin to the far corner; a step is any non-empty subset of the sequences that each consume one residue (the `2^k - 1` neighbours of Needleman-Wunsch generalised to k sequences, Altschul & Lipman 1989; for k = 3 the 7-neighbour three-dimensional recurrence). Linear gaps: the column cost depends on the subset only. Natural affine gaps: the cost of a gap column of a pair depends on whether the pair's previous projected column was a gap of the same row, so the program keeps one value per (cell, gap-history state); the state of the pair (a, b) is decided by which of the two moved last, so the whole state vector is the weak order of the sequences by the time of their last move (13 / 75 / 541 states for k = 3 / 4 / 5, enumerated from the origin) - the exact state-per-pair program, with no profile approximation.
- **Carrillo-Lipman bound** (Carrillo & Lipman 1988, SIAM J Appl Math 48:1073, used by the MSA program of Lipman, Altschul & Kececioglu 1989): every alignment through the cell x scores at most `sum_{a<b} U_ab(x_a, x_b)`, `U_ab(i, j)` = the best pairwise alignment of the two sequences through (i, j) (forward + backward Gotoh tables, `BuildPairBounds`); an alignment of score `L` (the best of the star, progressive and iterative aligners) is known, so a cell whose bound is below `L` cannot lie on an optimal path and is never created. The program additionally drops a state value `v` at x when `v + sum_ab G_ab(x_a, x_b | the pair's state) < L` (`G` = best pairwise suffix given the pair's gap state; the usual A*-style tightening from the same tables). Both tests discard only paths that cannot reach `L`; the heuristic alignment itself is a path of the surviving lattice, so the optimum is exact. `MsaOptions.ExactCarrilloLipman = false` evaluates the whole lattice (used as an oracle).
- **Complexity guard.** The problem is NP-complete (Wang & Jiang 1994); the lattice has `prod (len_i + 1)` cells. At most 8 sequences (linear) / 6 (affine); the program throws `ArgumentException` ("complexity limit ... `MsaOptions.ExactMaxStateCells`") as soon as it holds more than `ExactMaxStateCells` values (surviving cells x states, default 50 000 000 = about 200 MB), never an out-of-memory failure. Similar sequences give a thin corridor (k = 4, 100 nt, ~10 % divergence: 110 million lattice cells, a few hundred evaluated, 30 ms); unrelated sequences explode.
- **Sources actually opened:** Shamir's lecture notes on the Carrillo-Lipman bound (`cs.tau.ac.il/~rshamir/algmb/98/scribe/html/lec03/node11.html`: pairwise budget `B(u,v) = c' - sum_{(i,j) != (u,v)} D(x_i, x_j)` and pruning when the through-cell pairwise bound exceeds it - the pairwise form of the sum test used here, which it implies); WebSearch records of Carrillo & Lipman 1988 (SIAM J Appl Math 48:1073), Altschul & Lipman 1989 (SIAM J Appl Math 49:197) and Konagurthu & Stuckey 2006 (J Comput Biol); the papers' full text was not retrieved, so correctness rests on the proof above and on the oracle below, not on a transcription.
- **Oracle** (`TestData/Alignment/msa_exact_oracle.tsv`, `scripts/alignment/generate_msa_exact_oracle.py`): 804 random sets (k = 2..5, lengths <= 12 for k = 3, <= 26 for related k = 3 sets, both objectives, 11 scoring schemes incl. zero gap open / extend); the optimum of two **independent** Python programs (lattice DP over `2^k - 1` neighbours; DP over the position vector and the run state of every pair, 3^pairs states) equal to each other, to the exhaustive enumeration of every alignment of the tiny sets and (k = 2) to Biopython 1.88; the C# optimum equals it with and without the bound and its rows score to it (`SumOfPairsScore`); a further exhaustive check in C# on 120 tiny sets (k = 3, 4).
- **How often the heuristics are optimal** (k = 3..4, total length <= 30, 309 sets per objective): linear - star 218, progressive 276, iterative 276, consistency 186, anchored 187, best of the five 285 (92 %); affine - star 212, progressive 227, iterative 228, consistency 164, anchored 178, best of the five 265 (86 %). No heuristic ever exceeds the optimum.

### 4.9 MUSCLE 3.8 progressive alignment (audit A1-10c part a, B09 F65)

`SequenceAligner.MultipleAlignMuscle(IEnumerable<DnaSequence> | IEnumerable<ProteinSequence> | IEnumerable<string>, MuscleOptions?, MatrixScoring?)` (`SequenceAligner.Muscle.cs`, `SequenceAligner.MuscleMatrices.cs`) is a step-by-step port of **MUSCLE 3.8.1551** (Edgar 2004, NAR 32:1792; the final v3.8 release; source = Debian `muscle3` 3.8.1551-2, `sources.debian.org`: `domuscle.cpp`, `alpha.cpp`, `fasta2.cpp`, `mhack.cpp`, `fastdistmafft.cpp`, `fastdistnuc.cpp`, `fastclust.cpp`, `upgma2.cpp`, `clwwt.cpp`, `profilefrommsa.cpp`, `msa2.cpp`, `aligngivenpath.cpp`, `aligntwoprofs.cpp`, `scorepp.cpp`, `termgaps.cpp`, `nwsmall.cpp`, `bittraceback.cpp`, `makerootmsa.cpp`, `refinetreee.cpp`, `difftreese.cpp`, `realigndiffse.cpp`, `msadistkimura.cpp`, `params.cpp`, `vtml2.cpp`, `mpam200.cpp`, `nucmx.cpp`) for the command lines `muscle -maxiters 1` and `-maxiters 2`. The installed `muscle` is **5.1**, a different program (PPP / probcons-like pipeline), so the oracle is the 3.8.1551 binary built from the same source by the Docker hand-off package `docs/Validation/review-2026-09/handoff/A1-10c-muscle/`, run by the user: **rows and output order equal on 420 / 420 sets** (`SequenceAligner_MuscleOracle_Tests`, F69; platform caveat: 1-ulp `logf` differences between libm versions are possible in principle, none occurs). The options of §4.9a are verified on the second round (630 / 630 recorded sets, F76).

1. **Input** (`fasta2.cpp`, `alpha.cpp`): letters upper-cased, gaps `-`/`.` and white space dropped, other characters rejected here (MUSCLE ignores them with a warning); the alphabet is `MuscleSequenceType` (`Auto` = `SeqVect::GuessAlpha`: nucleotide when >= 95 % of the first 100 residues are A, C, G, T/U, N); letters outside the alphabet become the wildcard (X protein, N nucleotide); **methionine hack** (`mhack.cpp`): with at least two sequences a leading M of a protein is aligned as X and restored in the output. An empty sequence is an error (MUSCLE silently drops empty FASTA records).
2. **Distance and guide tree** (`DistKmer6_6` over the six MAFFT residue groups `AGPST / ILMV / NDQEBZ / RHK / FWY / C` for proteins, `DistKmer4_6` over `A C G T other` for nucleotides: sextets counted with 8-bit saturation, `common(i, j) = Σ_unique sextets of j min(n_i, n_j)`, `d = min(3·(c_ii - c_ij)/c_ii, 3·(c_jj - c_ij)/c_jj)` in single precision; the source's `ResidueGroup` table lists B and Z where the enum has X and B: X → group 2, B → 2, Z → 0, reproduced) then **UPGMB** (`UPGMA2`: O(N²) with nearest-neighbour rows, ties = lowest row, linkage `0.1·average + 0.9·minimum` = `-sueff`; edge length = height difference, height = half the cluster distance, root = last merge).
3. **Weights** (`CalcClustalWWeights`): strength = edge length / leaves below, weight = path sum (< 0.0001 → 1), normalised to 1; two sequences 0.5 / 0.5. Leaf profiles use the single weight renormalised to 1 (`f = 1/w; w·f`, single precision).
4. **Profiles** (`ProfileFromMSA`, `GetFractionalWeightedCounts`): per column weighted residue frequencies (gaps counted in the occupancy; protein wildcards B → D + N, Z → E + Q, others w/20 over the 20 residues; **nucleotide wildcards follow the source's literal `case AX_R` / `AX_Y` comparison: letter 14 (X) counts as G + A, every other wildcard w/20 over A, C, G, T**), counts normalised by the non-wildcard weight for the LE score, gap-open / gap-close penalties `occupancy·gapopen/2` (position-specific, "once a gap, always a gap" is replaced by the fraction of sequences that open / close a gap there), `AAScores[i] = Σ_j f_j·M[i][j]`. Merged profiles are built from the **frequencies** of the two children (`AlignTwoProfsGivenPath` with the weights `wA/(wA+wB)`, `wB/(wA+wB)`), their LL / LG / GL / GG gap statistics along the path, and `ProfScoresFromFreqs` (penalties recomputed in double precision from LG / GL).
5. **Profile-profile score** (`scorepp.cpp`): the **log-expectation** score (Edgar 2004) `ln(Σ_i f_i·AAScores_B[i]) - center` weighted by the occupancy product, `-2.5` when the sum is 0, with the VTML200 likelihood-ratio matrix, `center -0.52`, gap open -2.9 (`-le`, default for proteins); `-sp` (PAM200 + 20, gap -1439), `-sv` (VTML240 + 22, gap -300) use the sum of pairs `Σ f_i·AAScores_B[i] - center`; nucleotides use **SPN** (BLASTZ matrix + 60, gap open -400, RNA -420 with center -300). `-gapopen`, `-gapextend`, `-center` override.
6. **Dynamic program** (`NWSmall`, `BitTraceBack`): a Gotoh-type affine program with position-specific open (`PA[i].open`) and close (`PA[i].close`) penalties, extension `-gapextend` (default 0), terminal gaps half-open (`TERMGAPS_Half`: the first open and the last close penalty are zero), `MM >= DM >= IM` and `MI >= II`, `DD > MD` tie rules, boundary rows / columns as in the source (including the single-column special cases), single precision, `MINUS_INFINITY = -1e37f`. The returned path decides the merged profile and the rows.
7. **Iteration 2** (`RefineTreeE`, `-maxiters 2`, not for two sequences, `-maxtrees 0` switches it off): the distance of the rows of the draft is the **Kimura** distance of the pairwise identity (`-ln(1 - p - p²/5)`; above 75 % divergence the ClustalW `dayhoff.h` table, 10 above 93 %), a second UPGMB tree is built over the rows **in the order of the draft** (the depth-first leaf order of the first tree; ties depend on it), `DiffTreesE` marks every node whose set of leaves also exists in the old tree as unchanged (their profiles, rows and weights are reused; the weights are NOT recomputed from the new tree), the changed nodes are realigned bottom-up with `AlignTwoProfs`, the rows are collected along the new tree. The final alignment is written in input order; `MuscleOptions.TreeOrder` returns the order muscle writes (the depth-first leaf order of the final tree).
8. **Further options and command lines** - §4.9a. A1-10c(a2) in B09.md (F70, F76): verified on 630 recorded sets of the binary.

**Verification status.** `-maxiters 1 | 2` with the options of round 1 (`-le/-sp/-sv`, `-gapopen/-gapextend/-center`, `-distance1 kmer6_6`, `-cluster1/-cluster2`, `-sueff`, `-maxtrees 0`) equals the binary on 420 / 420 sets (rows and output order). In addition `SequenceAligner_Muscle_Tests` (20 tests) locks the definitions and the source itself: the LE score of single-residue columns (`ln(VTML_LA[a][b]) + 0.52`), the SPN matrix (BLASTZ + 60), the wildcard count rules incl. the nucleotide `AX_R` quirk, the Kimura formula and the `dayhoff.h` comment values, the test matrix of `upgma2.cpp`, UPGMB linkage arithmetic, the worked example of `clwwt.cpp`, the k-mer distance definition, and the optimality of `NwSmall` against an exhaustive enumeration of all alignments (480 random profile pairs).

### 4.11 Kalign 3.3.5 (audit A2-20, B09 F118)

`SequenceAligner.MultipleAlignKalign(sequences, KalignOptions)` / `KalignRun` (`SequenceAligner.Kalign.cs`) and `KalignProgram` (command line) are a step-by-step port of Kalign 3.3.5 (Lassmann 2019, *Bioinformatics* 36:1928; Debian `kalign` 1:3.3.5-1, `lib/src/*.c`):

1. **Input** (`msa_io.c`, `msa_op.c`): letters are residues, every other ASCII character is a gap and is removed, sequences without residues are dropped (`kalign_essential_input_check`); the alphabet is detected from the letter counts by a log-likelihood (`detect_alphabet`: DNA model `acgtunACGTUN`, protein model of the 20 amino acids; the type option does not choose it, it is checked against it).
2. **Distances** (`sequence_distance.c`, `bpm.c`): the semi-global edit distance of the shorter sequence (first 255 residues) against the best window of the longer one, computed with Myers' (1999) bit-vector algorithm on 256-bit words (`bpm_256`, the AVX2 build of the Debian package); proteins use the 13-letter reduced alphabet (L/M, I/V, K/R, E/Q, A/S/T, N/D, F/Y, B with N/D, Z with E/Q), DNA ACGTN. The matrix adds `min(10000, mean length) / 10000` (shorter sequences first).
3. **Guide tree** (`bisectingKmeans.c`): fewer than 100 sequences: UPGMA with the program's update `(d(a,j) + d(b,j)) / 2 + 0.001` in single precision; otherwise bisecting 2-means on the distances to 32 anchors (sorted by length with glibc's merge sort and the program's non-strict comparator), 40 tries of 4 splits per level, Euclidean distance reduced like `edist_256`.
4. **Progressive alignment** (`aln_run.c`, `aln_setup.c`, `aln_controller.c`, `aln_seqseq.c`, `aln_seqprofile.c`, `aln_profileprofile.c`, `weave_alignment.c`): sequence-sequence, sequence-profile and profile-profile alignment with the affine three-state dynamic program (single-precision scores; profile columns hold 23 residue counts, 23 substitution scores and the gap penalties scaled by the number of sequences), Hirschberg divide and conquer (forward and backward halves, meet-up with the `|middle - i| / 1000` tie-break), alignment merged by `update_n` / `make_seq`.
5. **Parameters** (`aln_param.c`): `RNA` (default for nucleotides): 283 + {91, -114, -31, -123 ...} matrix, gap open 217 / extension 39.4 / terminal extension 292.6; `dna`: 5 / -4, 8 / 6 / 0; `protein` (default): CorBLOSUM66_13plus, 5.5 / 2 / 1; `divergent`: GON250, 55 / 8 / 4.

Quirks of 3.3.5 that are reproduced (and locked by the oracle): `--tgpe` is applied only when `--gpe` is also given (`aln_param.c` tests `gpe >= 0` twice), `--type internal` means RNA (the program's `strstr(in, "rna")` matches "internal" first), the gap-open flags of `add_gap_info_to_path_n` are never set (its marking loop tests `o_path[j] != 3` right after storing 3), so columns inserted into a profile cost only extension penalties, `-n 1` uses the serial recursion (`do_align_serial`: no shorter-first swap of sequence pairs) while more threads use the OpenMP recursion, `aln_runner` falls through into `aln_runner_serial` for windows below 500 columns and the `gb -> gb` case always continues through `aln_runner`.

Limits: the distance of the portable (non-AVX2) build is `bpm_block` (pattern limit 1 024 instead of 255); sequences whose shorter member exceeds 255 residues can differ between the two builds (the committed oracle is the AVX2 build). Letters outside the alphabet of the detected type, non-ASCII characters, one sequence only and a zero-column alignment (the program reads before its path array) are refused with `ArgumentException` (the program leaves codes undefined, segfaults or runs into undefined behaviour). MSF / Clustal input and output of the command line (`KalignIo.cs`: `read_msf` / `read_clu` / `detect_alignment_format`, `write_msa_msf` with the GCG checksums and the date line, `write_msa_clu`; the non-quiet banner, log lines with the stopwatch lines, the aligned / unaligned warnings and the `-n 1` alignment steps; several inputs merged as `merge_msa` does) equal the installed program on 251 / 251 command lines (audit A2-20b, F222; the MSF header prints the residue count of the first sequence and always `!!NA_MULTIPLE_ALIGNMENT` / `Type: N`, as `write_msa_msf` does).

### 4.12 MAFFT 7.505, stage 1: the alignment of two sequences (audit A2-19, B09 F119)

`SequenceAligner.MultipleAlignMafft(sequences, MafftOptions)` (`SequenceAligner.Mafft.cs`, `SequenceAligner.MafftTables.cs`) is a step-by-step port of the two-sequence case of MAFFT 7.505 (Katoh & Standley 2013, *MBE* 30:772; Debian `mafft_7.505.orig.tar.gz`, `core/*.c`) for `mafft --anysymbol [--nuc|--amino] [--op x] [--ep y] [--bl n] in.fa`:

1. **Front end** (`replaceu.c`, `io.c`): the alphabet is guessed from the letters (`countATGC`: more than 75 % of the letters A, C, G, T, U, N = nucleotides; `--nuc` / `--amino` force it); with `--anysymbol` every character except blanks and `-` is a residue, those outside the usual alphabet are replaced by X (amino acids) or n (nucleotides) and restored in the output (`restoreu.c`); the guess is made again on the replaced letters (`disttbfast`); the plain command keeps only letters and `.` and writes nucleotides in lower case, amino acids in upper case.
2. **Scoring** (`constants.c`, `blosum.c`): amino acids - the BLOSUM table (`--bl`; the table is the active `#else` definition of `blosum.c`), minus the frequency-weighted mean, times 600 / (frequency-weighted mean diagonal), minus the offset, rounded to integers; nucleotides - the Kimura (kappa 2) 200-PAM matrix, log10 odds x 1000, centred, scaled to 600 / mean diagonal, IUPAC codes by averaging (`ambiguousscore`). Penalties are integers: `(int)(600/1000 x (int)(-op x 1000 - 0.5) + 0.5)` (x 3 for nucleotides), extension 0, offset from `--ep` (the script passes `-h -ep`), free end gaps (the script passes `-O`).
3. **Dynamic program** (`Galign11.c` `G__align11`, `Atracking`): the gap-open-only affine recurrence with "best earlier cell" trackers (`mi`, `m[j]`; `>=` for the trackers, `>` for the cells), the end of the alignment chosen among the last row and column.

The default FFT-NS-2 / `--nofft` / `--retree 1` strategies give the same rows for a pair (the `Falign` fast path falls back to the same program): 884 / 884 committed pairs up to 1 500 residues. Not ported (registered DOABLE, B09.md A2-19b / A2-19c): three or more sequences (6-mer distances `disttbfast.c`, guide tree, `treebase`, group-group `A__align` of `Dalignmm.c`, `Falign.c` + `fft.c`), `--maxiterate`, `--localpair`, `--globalpair`, `--genafpair`, `--auto`, `--jtt` / `--tm`, `--lop` / `--lep`, `--6merpair`, `--parttree`. T-Coffee's `mafft_pair` (`TCoffeePairMethod.MafftPair`) uses this port.

### 4.13 MAFFT 7.505, stage 2: three and more sequences, the progressive strategies (audit A2-19b, B09 F283)

`SequenceAligner.MultipleAlignMafft` / `RunMafft` (`SequenceAligner.Mafft*.cs`) now align any number of sequences like `mafft [options] in.fa` for the plain progressive methods FFT-NS-2 (default), FFT-NS-1 (`--retree 1`), NW-NS-2 / NW-NS-1 (`--nofft`) and `--retree 3`:

1. **Front end** (`replaceu` with `--anysymbol`, `getnumlen`): the alphabet from the letters (nucleotide above 75 % of A, C, G, T, U, N), unusual letters replaced by X / n and restored, '-' of the input positions kept in the lengths and removed by `gappick0`.
2. **Distance** (`disttbfast.c`): amino acids in six classes, nucleotides in four, 6-mers (10-mers with `--10merpair`); `d = 2 (1 - c_ij / min(c_ii, c_jj)) / (shorter / longer * 0.1 + 10000 / (longer + 10000) + 0.01)` (constants for nucleotides 2500 / 2500 or 10^6 / 10^6, 0.0 / 0.1).
3. **Guide tree**: the UPGMA of MUSCLE with mixed linkage `d(ij, k) = min * (1 - s) + (d_ik + d_jk) * s / 2` (`s = 0.1`; `--averagelinkage` s = 1, `--minimumlinkage` s = 0), ties = the first node; weights `w_i` = the branch lengths on the path from leaf i to the root, the j-th branch counted from the leaf weighted by 2^-j (+0.001, normalised to 1; `--unweight` = all 1).
4. **Progressive alignment** (`treebase`): for each node the two groups (rows with weights normalised to 1) are aligned by `Falign` when `nlen > number of sequences` for both (the FFT stage: score vectors of polarity / volume (amino acids) or of the letter `a` (nucleotides), cross-correlation by the FFT, the 20 best shifts, windows of 20 (amino acids) or 100 (nucleotides) columns above `0.8 x 600 x window`, the best chain of anchors by `blockAlign2`, the segments between the anchors by the dynamic programs below) or directly by the dynamic programs: `G__align11` for two single sequences (gap opening = the integer penalty, free end gaps, `>=` for the trackers and `>` for the cells), `A__align` for groups (`A+` of the program: the penalty of every opening / closing is `0.5 (1 - frequency of gap starts / ends) x penalty x frequency of non-gaps` of the column of the other group; profile history for groups of more than 20 sequences).
5. **Second round** (`-E 2`): distances from the first alignment (`2 (1 - sp score / min(self))`, at most 10), a second UPGMA tree, the sequences are aligned again.
6. **Scoring**: BLOSUM `--bl` (30 ... 100, 0), JTT / TM PAM matrices (`--jtt n`, `--tm n`: `rsr x frequency`, `pam1^n`, `log10 x 1000`, centred, scaled to 600 / mean diagonal, offset `--ep`), the Kimura matrix for nucleotides (`--kappa`, `--kimura n`, `--fmodel`, `--nwildcard`), integer penalties `0.6 x (-gap opening)` (x 3 for nucleotides), `--exp` extension.

Differences from the library's own aligners (why this is not `MultipleAlignProgressive`): the weights, the integer-scaled matrices, the profile-based `A__align` penalties, the FFT anchors and the 6-mer distance are MAFFT's own; they decide the co-optimal paths, so rows are equal to the program only through this port (6 530 / 6 530 committed sets, rows and standard error). Not ported (registered, B09.md A2-19b / A2-19c): `--parttree` family, `--add` / `--merge` / `--seed`, the iterative refinement `--maxiterate` and the pair-library strategies.

### 4.13b MAFFT 7.505, stage 3: `--maxiterate` (FFT-NS-i, audit A2-19c, B09 F284)

With `MafftOptions.MaxIterate = N` (at most 16 iterations run, like the script) the progressive alignment is refined as `mafft --maxiterate N` does: `dndpre -M 2` writes the distances between the rows of the alignment (`maxdist x (1 - score / min self-score)`, three decimals), `dvtditr` builds a UPGMA tree from them (with the complete member lists), cuts the alignment at the anchor windows (`searchAnchors`: 20 columns, 65 %), and `TreeDependentIteration` re-aligns the two groups of every branch (forward and backward) with `Falign` in its `kobetsubunkatsu` form (no FFT; the segments are freed of all-gap columns), weighting the sequences by the products of the branch weights of the unrooted tree (`treeCnv`, `calcBranchWeight`, `weightFromABranch`); a new alignment is kept when `intergroup_score` does not fall. Rows and standard error equal the program on 5 360 / 5 360 sets. With threads the program's iterative step is non-deterministic; the port refuses `Threads > 0` unless `ThreadsIterate = 0`.

### 4.13c MAFFT 7.505, stage 4: the pair-library methods (G-INS-1, L-INS-1, E-INS-1; audit A2-19c, B09 F285)

With `MafftOptions.PairLibrary` = `Global` / `Local` / `Genaf` (and `MaxIterate = 0`) the alignment is `mafft --globalpair` / `--localpair` / `--genafpair`: `tbfast` calls `pairlocalalign`, which aligns every pair of sequences (`G__align11`, `L__align11` with free ends and restarts below `-offset`, or `genL__align11` with a second, dearer gap opening `penalty_OP` for jumps of any length), the ungapped blocks of these alignments become the library (`putlocalhom2`: `opt` = mean matrix score per column), the distances `2 (1 - score / min(self score))` give the UPGMA guide tree, and the group-group dynamic program `A__align` adds the importance of the blocks (`calcimportance_half`: the mean number of weighted sequences that have a block at the residue, times `opt`; `fillimp`: x weights of the two sequences x `--weighti`) to its match scores. The matrix of each step is shifted by `makedynamicmtx` with the offset of the distance of the step from the tips (zero for non-negative distances). Rows and standard error equal the program on all committed sets (F285). The iterative refinement with a pair library is described in 4.13d.

### 4.13d MAFFT 7.505, stage 5: the iterative pair-library methods (G-INS-i, L-INS-i, E-INS-i; audit A2-19c, B09 F286)

`MaxIterate` > 0 with a pair library runs `mafft --maxiterate N --globalpair | --localpair | --genafpair`: after the progressive alignment of F285 `tbfast` writes the library (blocks and distances) to files, `dvtditr -l` takes the UPGMA tree of the distances (three decimals), computes the importance of the blocks with the weights of this tree, and refines the whole alignment (no cutting at anchors) branch by branch like FFT-NS-i (F284) with two differences: the groups are re-aligned by `Falign_localhom` with `partA__align`, whose match scores include the importance of the blocks of the pair library (read through the gap maps of the compacted piece), and the old and new alignments are compared by the sum of pairs plus the importance (of the diagonal of the groups' alignment / of the path of the new one). Rows and standard error equal the program on all committed sets (F286). With threads in the iterative step the program is non-deterministic (F284).

### 4.13e MAFFT 7.505, stage 6: `--auto` (audit A2-19c, B09 F287)

`MafftOptions.Auto` chooses the method like the script: fewer than 100 sequences of fewer than 3 000 letters (the longest sequence without gaps) = L-INS-i (`--localpair --maxiterate 1000`); fewer than 200 of fewer than 1 000 = `--localpair --maxiterate 2`; fewer than 500 of fewer than 10 000 = FFT-NS-i with 2 iterations and two guide trees; fewer than 20 000 = FFT-NS-2; larger inputs (memory-saving tree, `--parttree`) are refused. ### 4.13 ProbCons 1.12 (audit A2-23, B09 F127)

`SequenceAligner.MultipleAlignProbCons(sequences, ProbConsOptions)` / `ProbConsRun` / `ProbConsPairs` / `ProbConsTrain` (`SequenceAligner.ProbCons.cs`), `ProbConsParameters` and `ProbConsProgram` (command line, `ProbConsProgram.cs`) are a step-by-step port of ProbCons 1.12 (Do, Mahabhashyam, Brudno & Batzoglou 2005, *Genome Res* 15:330; Debian `probcons` 1.12-14, `Main.cc`, `ProbabilisticModel.h`, `SparseMatrix.h`, `EvolutionaryTree.h`, `MultiSequence.h`, `Sequence.h`, `ScoreType.h`, `Defaults.h`):

1. **Input** (`Sequence.h`, `MultiSequence.h`): `>header` lines, residues are the letters, `*` and `-` (`.` becomes `-`, white space is skipped, `-` is removed when reading FASTA); an empty sequence ends the file; a file that does not start with `>` is read as MSF / Clustal (`ParseMSF`: letters upper-cased, gaps kept, a last line without a newline lost). Letter case is kept in the output.
2. **Pair-HMM** (`ProbabilisticModel.h`): a match state and two pairs of insertion states (`-DNumInsertStates=2` of the Debian build); single-precision log-space forward / backward recursions with the `LOOKUP` polynomial approximation of log(1 + e^-x) and the piecewise polynomial `EXP`; match posterior `EXP(min(0, f + b - total))`. The recursions are **the engine of T-Coffee's `proba_pair`** (`TcProbaForward`, `TcProbaBackward`, `TcLogPlusEquals`, `TcLogAdd`, `TcExp`, `TcProbaTotal`, the `TcProbaTables` parameters - verified equal to `Defaults.h`): reused through the shared `TcProbaModel` (a second constructor takes the character-indexed emission tables); the one difference of ProbCons 1.12 - its backward initialisation does not add the emission of the last cell - is the parameter `endMatch`.
3. **Sparse matrices and consistency transformation** (`SparseMatrix.h`, `DoRelaxation`): cells with posterior >= 0.01 are kept; `-c` rounds of P'(x_i - y_j) = (2 P + sum_z sum_k P(x_i - z_k) P(z_k - y_j)) / |S|, masked to the cells of the original matrix.
4. **Guide tree** (`EvolutionaryTree.h`): distance = (maximum-expected-accuracy score of the pair) / (shorter length); the tree merges the largest value and averages `(d_ik + d_jk) x d_ij / 2`.
5. **Progressive alignment and refinement** (`ProcessTree`, `AlignAlignments`, `BuildPosterior`, `ComputeAlignment`): the posterior of two profiles is the sum of the transformed matrices of their members (`-co` is subtracted over the columns 0 .. length-1 of the other sequence, as in the source); the alignment is the maximum-expected-accuracy path (tie order D, L, U); `-ir` rounds of randomized-partitioning refinement take their bipartitions from glibc's `rand()` at the default seed 1 (`GlibcRandom`, the TYPE_3 additive feedback generator).
6. **Options**: `-pre` (EM re-estimation of the transition probabilities of the whole input: `ComputeNewParameters`, `exp` in single precision), `-t` / `-e` (training on several files, emissions), `-p` (parameter files), `-a`, `-annot` (the column score `(int)(200 x mean posterior)`), `-pairs` / `-viterbi` (pairwise alignments, files `h1-h2.fasta` / `.aln`), `-clustalw` (the program's Clustal-like writer with the conservation line `GetAnnotationChar`), `-go` / `-ge` / `-co`, `-v` (progress lines of standard error). Number reading follows `strtol` base 0 / `strtod`; the standard-error text (heading, the parameter set printed with `%.10g` = `CFormat.General`, "Loading sequence file", tree) is reproduced byte for byte.

Quirks of the program that are reproduced (and locked by the oracle): letters outside the 20 amino acids have the emission defaults 1e-5 / 1e-10; lower and upper case have the same probabilities; the Debian patch `mayhem.patch` ("Zero sequences delivered to function DoAlign()", exit status 0 when no file is named); a training run on one sequence averages over zero pairs and prints `-nan` parameters.

Limits (documented, not simplifications): `-go` / `-ge` with two profiles of different size overflow a heap buffer in the program (`openingPenalty2` is allocated `(numSeqs1 + 1) x (numSeqs2 + 1)` but filled `(numSeqs2 + 1) x (numSeqs1 + 1)`; the runs of the first oracle generation with three or more sequences died with status -11), so the port implements the intended algorithm and the oracle covers the equal-size merges (two sequences; four sequences with `-ir 0` and a balanced tree); MSF / Clustal input **with gap characters** makes the program overflow `BuildPosterior`'s mapping arrays (status -6 / -11 or garbage), the port refuses nothing but the oracle contains only gap-free alignment files; `-v` for the interleaving of "Loading ..." and training lines is reproduced for one and several files.

Input contract (audit A3-1, F129): the library entry points read their residues like the program's FASTA reader - white space, `-` and `.` (a gap character) are dropped (`"AC-GT"` is aligned as `ACGT`; installed probcons: `>a ACGTACGT`, `>b AC-GT` -> `ACGTACGT` / `----ACGT`), letters and `*` are residues, anything else is `ArgumentException("Unknown character encountered")`. The program drops a record that is empty after that; the API refuses it (`ArgumentException`) because its result has one row per input. MSF / Clustal input records keep their gaps in the program, which then reads past its sequence arrays (Segmentation fault in 2 of 5 probes, mis-aligned rows otherwise: undefined behaviour); the port aligns the gap-free sequences.

### 4.14 POA 2.0 partial-order alignment (audit A2-26, B09 F128)

`SequenceAligner.MultipleAlignPoa(sequences, PoaOptions)` / `PoaRun` (`SequenceAligner.Poa.cs`), `PoaScoreMatrix` and `PoaProgram` (command line, `PoaProgram.cs`) are a step-by-step port of POA V2 (Lee, Grasso & Sharlow 2002, *Bioinformatics* 18:452; Lee 2003, *Bioinformatics* 19:999; Debian `poa` 2.0+20060928: `main.c`, `lpo.c`, `buildup_lpo.c`, `align_lpo_po2.c`, `heaviest_bundle.c`, `lpo_format.c`, `seq_util.c`, `fasta_format.c`, `create_seq.c`). **This is the POA program (Lee et al.) with its own matrix files and gap model - not spoa / abPOA (different implementations of the partial-order idea, not ported).**

1. **Input**: FASTA records (`read_fasta`: name = first word of the header, at most 31 characters, title = rest or `untitled`; `#` lines are comments, `*` lines ignored); `limit_residues` maps every letter that is not a symbol of the matrix to the matrix's first symbol (lower-case nucleotides are symbols of the shipped matrix, lower-case amino acids are not: `-toupper`), `index_symbols` maps the symbols to indices (unknown: the last symbol).
2. **Partial-order graph** (`lpo.c`): letters with ordered left / right link lists, an ordered source list (sequence index, position), a circular alignment ring and its minimum index; the order of links and ring members is visible in the PO file and is therefore kept.
3. **Alignment** (`align_lpo_po2.c`): dynamic programming over two graphs (rows = nodes of y, columns = nodes of x in topological order; every combination of a predecessor of x and a predecessor of y for a match, one predecessor for an insertion), integer scores, the affine gap model of `read_score_matrix` (gap open, first extension up to the truncation length, optional linear decay, second extension; the extra state `max_gap_length + 1` = free initial gap in local mode, an ordinary gap in global mode), initial nodes left-linked to a virtual start so that a global alignment can begin on any branch, the alignment ends at the best cell (local) or at a cell where both nodes end a sequence (global), ties: the smaller (x, y); traceback through the stored predecessor choices.
4. **Fusion** (`lpo.c` `fuse_lpo`, `reindex_lpo_fusion`): the aligned letters of y are fused into the node of x only when the residues are identical, otherwise they share an alignment ring; unaligned stretches of y are inserted before the next aligned x letter so that every ring stays one contiguous block of the linear order; `-fuse_all` re-pairs identical letters on rings (`fuse_ring_identities`).
5. **Merging order** (`buildup_lpo.c`): without `-do_progressive` / `-read_pairscores` every sequence is merged into the first one in input order (iterative); `-do_progressive` merges along the descending list of pairwise alignment scores (ties by ascending (i, j)), `-read_pairscores` along the scores of a file; `-preserve_seqorder` re-indexes the sources (`reindex_lpo_source_seqs`) and prints the permutation.
6. **Heaviest bundle** (`heaviest_bundle.c`): DP over the right links choosing the largest number of sequences passing from one node to the next; sequences with at least `-hbmin` of their residues on the path join the bundle (weight 0), the path is added as the source `CONSENS<n>`; bundling ends when a path is shorter than 10 nodes.
7. **Output** (`lpo_format.c`): the PO file (`write_lpo`), FASTA-PIR (`.` gaps, `>name title`, 60 columns, bundle selection with `-best`), CLUSTAL (indent 36, 50 columns, two blank lines between blocks, no conservation line).

Quirks of the program that are reproduced (and locked by the oracle): letters outside the matrix are replaced by its first symbol (a lower-case protein becomes a run of `A`); the FASTA reader drops a record without residues and stops at a `#` line after the first sequence; `-hbmin` is read with `atof` into a float; `-printmatrix` lists the last matching symbol of a row.

Input bytes (audit A3-1, F129): the program reads BYTES, so a non-ASCII character is its UTF-8 bytes, every byte one residue outside the matrix and therefore the matrix's first symbol (`MultipleAlignPoa(["ACG\u017fT", "AC\u0131GT"])` -> `ACGAAT` / `ACAAGT`, as the installed `poa`; U+00A0 / U+0085 are two residues, not white space; `-tolower` / `-toupper` touch ASCII only). The port applies the same byte view (`PoaEngine.PoaByteView`), also to the file text of `PoaProgram`.

MSA / PO file input (audit A2-26b, F223): `-read_msa`, `-read_msa2`, `-read_msa_list`, `-subset` / `-subset2`, `-remove` / `-remove2` (`SequenceAligner.PoaInput.cs`: `read_msa_select` with the format detected from the first line, `read_clustal`, `read_pir`, `lpo_from_aln_mat` (rows fused into a consensus row and stripped again), `filter_sequence_set`, `read_lpo`, `read_lpo_select`, `strip_seq_from_lpo`, `lpo_index_symbols`; `fgets` pieces of 510 characters, `fscanf` conversions of the program, the PIR blank-line quirk that re-uses the previous row) equal the installed program on 687 / 687 command lines. An alignment row name beyond 31 characters (the program aborts in `strcpy`), a row without residues (exit 255), links / sources outside the PO file and unclosed alignment rings (the program loops or reads outside its arrays) stop the run here. `spoa` / `abpoa` are separate programs (registered A2-26c).

### 5.2 Current Behavior

All five aligners handle empty and single-sequence inputs before any heuristic work. The public `TotalScore` is always recomputed from the final aligned strings by `ComputeSumOfPairsScore`. The final consensus includes gaps in the vote and prefers a nucleotide over a gap on ties. Validation (independent Python references, B09): the rows of `MultipleAlign`, `MultipleAlignProgressive`, `MultipleAlignIterative` and `MultipleAlignConsistency` equal an independent re-implementation of each method on 300 random sets (k = 2..6, three scoring schemes) with no mismatch; every alignment degaps to its input, has no all-gap column and re-scores to `TotalScore`; for k = 2 the star, progressive and iterative scores equal the Biopython 1.88 `PairwiseAligner` optimum.

### 5.3 Conformance to Theory / Spec

**Implemented (verbatim from the cited theory/spec):**

- Common-length aligned outputs with gap removal restoring the original sequences.
- Column-based SP scoring on the final multi-sequence alignment (match/mismatch from the matrix, residue-gap = `GapExtend`, gap-gap = 0).
- Center-star alignment (Gusfield 1993): optimal pairwise alignments to the pair-score center, merged by once-a-gap-always-a-gap (`MultipleAlign`).
- Progressive alignment along a guide tree (Feng & Doolittle 1987; Higgins & Sharp 1988; Thompson et al. 1994): all pairwise NW alignments → ClustalW distance → UPGMA → profile-profile NW, single pass (`MultipleAlignProgressive`).
- MUSCLE Stage 3 "tree-dependent restricted partitioning" iterative refinement (Edgar 2004): visit guide-tree edges in order of decreasing distance from the root, split into two sub-profiles, re-align with profile-profile NW, keep only on a strictly higher SP score, repeat until convergence or the iteration cap (`MultipleAlignIterative`).
- Note on the refinement variant: `MultipleAlignIterative` is the MUSCLE Stage 3 scheme as published (Edgar 2004), which partitions by guide-tree edge; the earlier Barton-Sternberg (1987) scheme removes one sequence at a time and re-aligns it to the profile of the rest. They are two published refinement schemes, so this is a choice of published method, not a deviation of the MUSCLE implementation.
- T-Coffee (Notredame, Higgins & Heringa 2000, `MultipleAlignConsistency`): primary library of global (NW) and local (SW) pairwise alignments weighted by percent identity (aligned columns only, integer division — T-Coffee `get_seq_sim` sim1) and combined by signal addition (p.207); library extension by the triplet consistency transformation for every residue pair, extended weight = direct weight + Σ min(W1, W2) (p.209, worked example 88 → 165; `residue_pair_extended_list`); progressive alignment with the extended-library weights as position-specific substitution scores and zero gap penalties (p.210).

**Intentionally simplified / declared deviations (each with its consequence):**

- **Gap model.** The default stays the linear model (every gap position costs `GapExtend`, `GapOpen` unused, column sum of pairs). The affine model is the additive option `MsaGapModel.Affine` (§4.2): exact natural affine objective, exact for two sequences, heuristic optimisation for k ≥ 3 (position-specific profile DP; the natural cost cannot be tracked by a three-state DP). ClustalW's own multiple-alignment stage (`prfalign.c`: sequence weights, residue-specific and hydrophilic gap penalties, gap-separation distance, delayed divergent sequences) is the separate `MultipleAlignClustalW` (§4.6, audit A1-10b / F56) and MUSCLE's profile scoring the separate `MultipleAlignMuscle` / `MuscleRun` (§4.9, audit A1-10c / F63 / F65 / F69 / F76); the Seqeron aligners of this section keep their own scoring.
- The star methods build no guide tree; the progressive family uses UPGMA by default (Higgins & Sharp 1988 CLUSTAL; the historical behaviour) and neighbour-joining as ClustalW/T-Coffee on request (`MsaOptions.GuideTree = NeighborJoining`, A1-12, §4.5). The UPGMA tree comes from the canonical `PhylogeneticAnalyzer` builder; since A1-10b the NJ tree uses ClustalW's own NJ arithmetic (`ClustalWNeighborJoining`, same topology as Saitou-Nei, ties resolved as clustalw does) instead of the canonical NJ plus tie order (the private UPGMA copy and the "circular reference" it was justified by are gone). With `NeighborJoining` + `ClustalWAffine` the unrooted tree equals the `.dnd` file of `clustalw -ALIGN` and the progressive merge order equals ClustalW's (420 DNA sets); the final rows of ClustalW's own profile stage are produced by `MultipleAlignClustalW` and equal the program (audit A1-10b, F56: 1 000 DNA sets, later the protein stage and the options, §4.6).
- The default guide-tree distance is computed from the repository's linear NW alignment; `MsaDistanceMode.ClustalWAffine` reproduces ClustalW's own pairwise stage (full-DP mode, exact; §4.2) and `MsaDistanceMode.ClustalWQuick` its fast k-tuple mode (`-QUICKTREE`, exact; §4.6, audit A1-15b). ClustalW's PROTEIN pairwise stages (GONNET / BLOSUM30 / PAM350 / identity matrix, gap 10 / 0.1, fast k-tuple 1) are ported as well (§4.2, audit A1-15b part (b)). The Seqeron profile aligners (`MultipleAlignProgressive/Iterative`) remain Seqeron's own occupancy-scaled models; ClustalW's own profile stage is the separate, exact `MultipleAlignClustalW` (§4.6).
- `MultipleAlignConsistency` implements the published formula by default. The T-Coffee 13.41 program's progressive stage differs (library relaxation `-relax_lib 1` = `trunc((w_back + Σ min(w1, w2)) / min(deg1, deg2))` with weights ≤ 10 dropped; sparse "linked pair-wise" DP over scored column pairs with gap open = gap extend = 0; `-extend_mode` has no effect on it): it is available as `MsaOptions.ConsistencyEngine = MsaConsistencyEngine.TCoffeeLinked` (this repository's library and guide tree) and, for an explicit library and binary guide tree, as `SequenceAligner.MultipleAlignTCoffee(sequences, TCoffeeLibrary, TCoffeeTreeNode, relaxLibrary)`, whose rows equal `t_coffee -lib -usetree` on 800 of 800 random DNA sets (A1-13). The program's own primary libraries (`proba_pair` = the default, `slow_pair`, `lalign_id_pair`), its k-tuple NJ guide tree and the whole pipeline are `MultipleAlignTCoffeeProgram` (A1-13b, §4.10): rows, trees and libraries equal the program on 1 480 + 820 + 2 committed sets.
- **T-Coffee primary library options of the paper path (audit A2-16, B09 F93).** By default the library holds the single best local alignment per pair and no redundancy weights, as in the paper. `MsaOptions.PrimaryLocalAlignments = N` (default 1) feeds the Waterman-Eggert top-N non-intersecting local alignments of `LocalAlignTopN` (the Lalign library of the paper, T-Coffee's `lalign_id_pair`, `-lalign_n_top`) into the library, each weighted by its own percent identity and signal-added with the global alignment; `MsaOptions.SequenceWeights = MsaSequenceWeights.TCoffee` applies `-seq_weight t_coffee` (`compute_t_coffee_weight`, the function of the program path verified in F66; the extended weight of a pair is multiplied by the smaller of the two sequence weights, after the extension as `re_weight_constraint_list` does after the relaxation); both are used by the `PaperExtension` and the `TCoffeeLinked` engine (MCP `multiple_align_consistency`: `primaryLocalAlignments`, `sequenceWeights`). **Verification:** the top-N alignments are oracle-verified (EMBOSS matcher, F47); the weight function is the program path's (F66 oracle); the library built from them equals an independent re-derivation (global NW + every top-N alignment at its own integer percent identity, signal-added; `SequenceAligner_ConsistencyOptions_Tests`). The paper-formula engine as a whole cannot be compared with a `t_coffee` run (the program's own pipeline, with SIM id-matrix libraries, integer weights and relaxation, is `MultipleAlignTCoffeeProgram`, §4.10, already equal to the program).
- `MultipleAlignAnchored` is a heuristic: anchor chaining constrains the path, so pairwise alignments (and the SP score) can fall below `MultipleAlign`'s.

**Not implemented:**

- Exact optimal MSA for more than 8 (linear) / 6 (affine) sequences or beyond the cell budget (NP-complete; Wang & Jiang 1994); below that the exact optimum is `MultipleAlignExact` (§4.7).
- ClustalW's tree commands (`-TREE`, `-BOOTSTRAP`, `-OUTPUTTREE`, ...) and the input formats other than FASTA / CLUSTAL / GDE: audit items A2-14f / g, DOABLE (the guide-tree files, `-OUTORDER`, output formats and structure masks are ported, §4.6b). ### 6.2 Limitations

The star result depends on the chosen center and is not SP-optimal (Gusfield's 2 − 2/k bound is for metric distances). The progressive method is single-pass and inherits the "once a gap, always a gap" behaviour; `MultipleAlignIterative` removes that limitation by re-splitting and re-aligning, but it is SP-guided and restricted to guide-tree edge partitions, so it improves on but does not guarantee the global SP optimum. `MultipleAlignConsistency` optimises the T-Coffee consistency objective over a greedy progressive merge order, so it does not guarantee the global optimum of that objective. Memory: the exact center-star (`MultipleAlign`) aligns every sequence to the center with the exact linear-space pairwise program (identical rows to the full-matrix Needleman-Wunsch, [Linear_Space_Alignment.md](Linear_Space_Alignment.md)) and has no quadratic matrix; the progressive / iterative / consistency profile alignments keep an `O(m·n)` double matrix of profile columns and throw `ArgumentException` above `SequenceAligner.ProfileMatrixMaxCells` = 50 000 000 cells (400 MB) instead of an `OutOfMemoryException`. The scalar-scoring overloads accept `DnaSequence` only; protein / IUPAC / any-alphabet input goes through the `MatrixScoring` overloads (§4.8).  `MultipleAlignClustalW` reproduces ClustalW 2.1 for DNA and PROTEIN; the one undefined behaviour of the C++ (uninitialised `gdist` with `-NOVGAP`) is emulated, not reproduced for every heap state (§4.6).

### 7.x nucmer anchor clustering vs the anchored aligner (A3-9a, B09 F150)

`NucmerClusters.Cluster` / `GenomicAnalyzer.FindNucmerClusters` / MCP `nucmer_clusters` are the clustering stage of MUMmer 3 `nucmer` (`mummer | mgaps`): unique (or maximal) exact matches are joined when their diagonals differ by at most `max(D, d * separation)` within the largest separation `g`, cut into chains of maximum score, and reported when they reach the minimum cluster length `c` (758 / 758 `mgaps` inputs and 700 / 700 `mummer | mgaps` pipelines equal the installed 3.23). `AnchorBasedAligner` differs on purpose: it keeps one MEM per matching diagonal run, chains by maximum weight with no distance or diagonal limit and then aligns EVERY gap with Needleman-Wunsch, whereas nucmer clusters near-diagonal neighbours only, drops short clusters and extends with banded Smith-Waterman until the score drops (`postnuc`, not ported: A3-9b). The anchors of the anchored aligner are a subset of the `mummer -maxmatch` matches (A2-30); no defect of `AnchorBasedAligner` was found.

### 7.y minimap2 chaining (A3-9c, B09 F151)

`Minimap2Chaining.CollectAnchors` / `Chain` / `MapChains` / MCP `minimap2_chains` are the seeding and chaining stage of minimap2 2.26: (k, w)-minimizers of the targets and the query (`mm_sketch`), the anchors of every query minimizer that occurs in a target (position of the last base of the seed, on the forward or reverse strand), and the chaining dynamic program `mg_lchain_dp` (step score `min(min(dq, dr), span)` minus `0.8 * 0.01 * k * |dr - dq| + 0.5 * log2(|dr - dq| + 1)`, distance and bandwidth limits, at most 5000 predecessors per anchor, a stop after 25 non-improving ones) with its peak-drop backtracking. 450 / 450 related random pairs equal `minimap2 --print-seeds --print-chains` (anchor arrays, chains) and the PAF chain scores. This is a second, documented chaining mode next to the weighted colinear chain of `AnchorBasedAligner` (Abouelhoda-Ohlebusch, maximal matches): minimap2 chains short minimizer seeds with a gap penalty that grows with the diagonal difference, while the anchored aligner maximises the number of matched bases of maximal matches and then aligns every gap exactly. The base-level alignment of `minimap2 -c` (ksw2 between and beyond the anchors, `Ksw2Aligner`) is ported in A3-9c2 (F187): see [Minimap2_Base_Alignment.md](Minimap2_Base_Alignment.md).

### 7.z minimap2 seeding options, frequent minimizers, primary / secondary hits (A4-7, B09 F165 / F166)

`Minimap2Chaining.CollectSeeds(targets, query, MinimapSeedOptions, targetNames, queryName)` is the seed stage with the options of minimap2 2.26: `-k -w -H` (homopolymer-compressed sketch), the hidden `-T` (sdust masking of the query minimizers), `-f` / `-U` / `-e` / `--q-occ-frac` (the frequent-minimizer rules: `mid_occ`, the streak selection `mm_seed_select` that keeps up to `(pe - ps) / occ_dist` of the least frequent minimizers of a streak, `max_max_occ` = 4095, the repeat length `rl`), `-X` (skip the diagonal / dual hits of equal names, which also means all chains and no long join) and `--for-only` / `--rev-only`; `CollectAnchors` calls it with the defaults and no longer refuses a frequent minimizer. `Minimap2Chaining.Map(targets, query, MinimapMapOptions, ...)` is `mm_map_frag` without `-c`: seeding, `mg_lchain_dp` (or `mg_lchain_rmq` for `--rmq`), the long-join re-chaining of `-r b,B` with `B > b` (`mg_lchain_rmq` over the AVL tree with range-minimum queries of `krmq.h`), `mm_gen_regs` (hits ordered by score and the chain hash of the query name), `mm_set_parent` / `mm_select_sub` (primary and secondary hits: `--mask-level`, `--mask-len`, `--hard-mask-level`, `-p`, `-N`, the opposite-strand retention), `mm_est_err` (`dv`) and `mm_set_mapq`: the PAF fields `tp cm s1 s2 dv rl` and columns 3 - 12 of every line. Verified on 1 980 seed cases and 1 320 PAF cases of the installed program (Evidence ALIGN-MULTI-001, A4-7). The base-level alignment (`-c`) is ported in A3-9c2 (F187), see [Minimap2_Base_Alignment.md](Minimap2_Base_Alignment.md).
