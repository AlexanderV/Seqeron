## The pipeline (`nucmer ref.fa qry.fa`)

1. `prenuc`: the reference records are joined, an `x` after each (no match can span two records).
2. `mummer -mum | -mumreference | -maxmatch -b | -r | (forward) -l L -n` for every query record: the exact matches (only A/C/G/T match), `GenomicAnalyzer.FindCommonRegions` modes; matches against the concatenated reference, so `-mum` / `-mumreference` uniqueness is measured over **all** reference records.
3. `mgaps -l c -s g -d D -f F` = `NucmerClusters.Cluster` (F150): clusters per query record and strand; the first cluster of a block is printed after a `> id` (`> id Reverse`) line, later ones after a `#` line.
4. `postnuc [-b breaklen] [-B banding] [-e] [-t] [-s] [-d] ref qry pfx < mgaps` (`NucmerPostnuc.Run`): the coordinates of the concatenation are mapped back to the reference records; every (reference record, query record) pair gets its clusters sorted by their first start (**the unstable `std::sort` of libstdc++**, reproduced by `LibstdcxxSort`: introsort, median of three, depth limit 2 floor(log2 n), insertion sort below 16 elements, heap sort fallback; equal starts - the forward and the reverse cluster of a palindrome - keep the order that algorithm gives them); every cluster is extended: the matches of a cluster are joined, the cluster is extended backward off its first match (`alignSearch`, backward) toward the best earlier alignment (`getReverseTargetAlignment`) and forward off its last match toward the best later cluster (`getForwardTargetCluster`) or to the end of the sequences, clusters shadowed by an earlier alignment are skipped (`isShadowedCluster`, unless `-s`), and the alignments of a pair are written as the delta file with error counts (`parseDelta`: mismatches, similarity errors, non-alphabetic characters; `x` and N count as mismatches, N never matches).

`NucmerSwAlign.AlignEngine` is `_alignEngine` of `sw_align.cc` line by line: anti-diagonals of the edit matrix with three affine scores per node (match +3 / mismatch -7, gap open -10, extend -7), nodes more than 3 x break length below the best score are trimmed, an optional hard band (`-B`, the diagonal difference of `--banded`), forward and backward *search* (only the end where the score stops improving is kept) and the targeted forward alignment whose traceback gives the delta vector; `OPTIMAL` backtracks to the best score, `SEQEND` (`--nooptimize`) forces the alignment to the end of the shorter sequence when it gets within the break length. 64-bit scores wrap as in C (`-LONG_MAX` is added to).

Read like the program: records are read by `Read_String` (first word of the header, residues lower-cased, every character that is not a letter or `*` becomes `x`, white space skipped; a header longer than 1023 characters or without newline is an assertion failure -> `FormatException`); `mummer` refuses an empty file, a file without a header line and a file whose only record is empty (`FormatException`); `-o|--coords` returns the coords file (`show-coords -r` of the delta; an error with `--nodelta`); `--mum --maxmatch` together is the script's "Multiple matching algorithms selected" error (`--mumcand` is `--mumreference`).

## Delta file and graph

`MummerDeltaFile.Parse` reads the delta file as `DeltaReader_t` does (stream extraction of the tokens; the percentages are computed in `float` exactly as the program: `idy = (total - idyc) / total * 100.0`, `total` counts the insertions). `MummerDeltaGraph` is `DeltaGraph_t`: reference and query nodes ordered by id (`std::map<string>`), one edge per delta record, one edgelet per alignment; the filters `flagScore` (-i -l), `flagUNIQ` (-u), `flagQLIS` / `flagRLIS` (-q -r), `flagGLIS` (-g), `flagMtoM` (-m), `flag1to1` (-1), `clean` (with the order-changing `std::partition` of libstdc++) and `outputDelta`. The longest-increasing-subset scores use `pow (idy, 2)` and the `long` truncation of the program; the choice among equally good chains calls glibc `rand ()` after `srand (1)` (`delta-filter` and `show-diff` never reseed), reproduced by `GlibcRandom`. `delta-filter` order of operations: `-i -l -u -q -r -g -m -1`.

## `show-coords`, `show-aligns`, `show-snps`

`MummerShowCoords` (`-b -B -c -d -H -I -k -l -L -o -q -r -T -g -G -w`): human table / tab-delimited / btab, the percent columns printed with `%8.2f` / `%.2f` of the `float` values (`CFormat.Fixed`), `-b` merges overlapping alignments, `-o` annotates [IDENTITY] / [CONTAINED] / [CONTAINS] / [END] / [BEGIN], the hidden `-w` marks [DUPLICATE] / [CONTAINS] / [SHADOWED] / [OVERLAPS]; `-g` / `-G` (longest ascending subset) break ties with `rand ()` seeded by `srand (time (NULL))` - the port takes the seed as an option (the oracle runs the programs with `time ()` fixed to 1700000000 by an `LD_PRELOAD` shim), the btab date is `Nov 14 2023` in the same way. `MummerShowAligns` draws the three-row alignments (`^` under a difference, `.` for an indel, blocks of the screen width, `-w`, `-q`, `-r`). `MummerShowSnps` finds substitutions (IUPAC-aware: `CompareIUPAC` is the program's asymmetric table) and indels, [BUFF], [DIST], the conflict counts [R] / [Q] (`-C`), context (`-x`), `-S` alignment selection, `-I`, `-l`, `-q` / `-r`, `-T`, `-H`. PROmer (amino-acid) delta files are read by all of them (`show-aligns` / `show-snps` on amino acids: see [Mummer_Package_Programs.md](Mummer_Package_Programs.md), A3-9d; `promer` itself is ported there too).

## `show-diff`, `show-tiling`, `dnadiff`

`MummerShowDiff` reads the delta without the vectors, flags the many-to-many mapping (`flagMtoM`, default epsilon = random choice with `rand ()` seeded 1), `clean`s the graph and walks every reference (`-r`, default) or query (`-q`) record along the longest chain: BRK (a stretch of the sequence without alignment), GAP (consecutive alignments of one pair: the gap in both sequences and their difference), JMP (a jump in the same pair), INV (the next alignment has the other slope), DUP (an alignment outside the chain), SEQ (the next alignment belongs to another sequence; the two neighbour ids), `-f` AMOS layout, `-H`. The program compares the *addresses* of the graph nodes to group the alignments of one sequence: the port uses the order of first appearance (only the grouping matters). `MummerShowTiling` places the contigs (the per-reference longest consistent subset with the maximum gap `-g`, the coverage rules `-v -V -i`, the overhang variant, `-c` circular references, `-R` random placement of repeats with the seeded `rand ()`), links them (`linkContigs`), and prints the path / `-a` alignments / `-x` XML (DATE is `ctime`, PARAMETERS the command line) and the files `-t` (TIGR contig list), `-u` (unusable contigs), `-p` (pseudo molecule: the used contigs in link order, N runs for gaps, overlaps cut from the contig with the less junk sequence). `GenomicAnalyzer.Dnadiff` is the perl script: `nucmer --maxmatch` (or a given delta), `delta-filter -1` / `-m`, `show-coords -rclTH`, `show-snps -rlTHC`, `show-diff -rH` / `-qH`, then the report (sequence and base counts, 1-to-1 and M-to-M alignment statistics from the coordinate files, breakpoints, relocations / translocations / inversions / insertions / tandem insertions from the diff files, SNP and indel tables with the 12 substitution classes, the "good" ones with a buffer of at least 20) and `.unref` / `.unqry`. **Non-deterministic part of the program:** the per-substitution lines of the SNP / indel blocks and the `.unref` / `.unqry` lines come out in perl's hash order, which changes with every run (hash-seed randomisation; proof: 6 runs of the installed `dnadiff` on one input wrote 6 different reports), so the port writes them in a fixed order (`. A C G T`, then other symbols) and the oracle compares those blocks as sets of lines; every other line of the report and every other file is byte-equal.
