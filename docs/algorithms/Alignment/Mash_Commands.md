# Mash text commands — `bounds`, `dist`, `triangle`, `screen`, `taxscreen`, `sketch` / `info` / `paste`

Implementation: `Seqeron.Genomics.Analysis/MashCommands.cs` (`MashCommands.Bounds`, `Dist`, `Triangle`) on top of the MinHash sketching of `KmerAnalyzer` (`CreateMinHashSketch`, `CompareMinHashSketches`: Ondov et al. 2016, Genome Biol 17:132; Mash 2.3 `Sketch.cpp`, `hash.cpp`, `MinHashHeap.cpp`, `CommandDistance.cpp`). MCP tools `mash_bounds`, `mash_dist`, `mash_triangle`.
Audit item A5-10 (B09 F174). Sources read: marbl/Mash v2.3 `CommandBounds.cpp`, `CommandDistance.cpp`, `CommandTriangle.cpp` (raw.githubusercontent.com, User-Agent `Seqeron-review/1.0`).

## What is ported

| Command | Options | Output |
|---|---|---|
| `mash bounds` | `-k` (1-32), `-p` (0-1) | the two tables (Mash distance, screen distance) of the error of the lower Jaccard bound for sketch sizes 100 ... 10^6 and distances 0.05 ... 0.4: the smallest `x` with `BinomialCdf(x, s, m2j) > (1-p)/2` (the program scans `x` linearly with `gsl_cdf_binomial_P`; the port bisects the monotone CDF with `StatisticsHelper.BinomialCdf`), `j2m = -ln(2je/(1+je))/k` (screen: `1 - je^(1/k)`), printed as `j2m - dist` |
| `mash dist` | `-k -s -S -n -i -t -v -d` | one line per (query, reference) pair that passes `-v` (p-value) and `-d` (distance): `reference TAB query TAB distance TAB p-value TAB shared/total`; `-t`: the `#query` header and a row of distances per query (blank when a pair fails) |
| `mash triangle` | `-k -s -S -n -i -E -v -d` | Phylip lower-triangular matrix (`TAB count`, then `name TAB d ...`) or, with `-E` (implied by `-v` / `-d`), the edge list |

Numbers are printed as C++ `cout << double` does (`%g`, six significant digits, `inf` / `nan`). With `-i` a sequence shorter than `k` is not sketched (no row for it).

**Refusals (A6-6).** Without `-i`, an input file that has no record of at least `k` symbols stops the program with exit status 1: `WARNING: All fasta records in input files were shorter than the k-mer size (k).` when records were skipped, `ERROR: Did not find fasta records in "input files".` when the file has none (the program prints the words "input files", not the file name: `Sketch.cpp` `sketchFile`); the port throws an `ArgumentException` with that text (parameter `references` / `queries` / `inputs`). Two more crashes of the program have no output to reproduce and are refused the same way: `mash dist -i` with no reference sequence of `k` symbols (SIGFPE) and `mash triangle -i` of sequences all shorter than `k` without `-E` (`std::out_of_range` abort). Null list elements, a `MashInput` without `Name` / `Records`, a record without `Sequence` (or without `Id` with `-i`) are `ArgumentNullException` / `ArgumentException` naming the parameter (A6-4). `Dist` / `Triangle` take a `CancellationToken` (polled per input, per 4096 sketched windows and per compared pair; the MCP tools `mash_dist` / `mash_triangle` pass theirs).

**Sketching cost (A6-1).** The sketch builders of `KmerAnalyzer` stream the k-mers of every record through a rolling 2-bit forward / reverse-complement pair (k <= 32; two byte buffers above) and keep only the `s` smallest distinct hashes (Mash's `MinHashHeap`: a bounded sorted set with an O(1) threshold test), exactly as `mash sketch` does; no string is built per k-mer. 4 Mbp random genome, `-k 21 -s 1000`: < 16 MB allocated (the previous implementation: about 250 bytes per distinct k-mer, 1.2 GB for 5 Mbp, 40 s / 4.1 GB for 20 Mbp as measured by the round-6 auditor).

## Verification

`scripts/alignment/generate_mash_commands_oracle.py` runs the installed `mash` 2.3 on 220 random cases per command plus 80 `error` rows (A6-6: the program's non-zero exits are kept, status and message compared) (families of related genomes 0.5-25 % divergent, unrelated ones, 1-3 records per file, `k` 4-32, sketch sizes 5-2000, seeds, `-n`, `-i`, `-t`, `-E`, `-v`, `-d`; for `dist` the references are sketched first with `mash sketch -o`), the whole stdout is compared as text (`TestData/Alignment/mash_commands_oracle.jsonl.gz`, `MashCommands_Oracle_Tests`): 660 / 660 equal, 80 / 80 error rows equal.

## `mash screen` (A5-10b, B09 F185)

`MashCommands.Screen(queries, mixtures, k, s, seed, canonical, individual, winnerTakesAll, minIdentity, maxPValue)` / MCP `mash_screen` (`CommandScreen.cpp`, marbl/Mash v2.3): the query files are sketched as `mash sketch -k -s -S -n -i` writes them into the query `.msh`; the hashes of the queries are counted in every window of the mixture (`KmerAnalyzer.ScanMashMixture`: the same rolling canonical / forward hash stream as the sketch, plus the bottom-`s` heap of the mixture, whose largest hash gives `MinHashHeap::estimateSetSize` = `2^bits * n / max`, truncated). One line per query: `identity` = `(shared / hashes)^(1/k)` (1 when all are shared, 0 when none), `shared/hashes`, the median multiplicity of the shared hashes (`depths[shared / 2]` after sorting), the p-value `P(X >= shared)` of Binomial(hashes, setSize / 4^k) (1 without a shared hash), the query ID and its comment (`name comment` of the first record of a file, `[N seqs] ... [...]` for several records; the record's own for `-i`). `-w` winner-takes-all (a hash goes to the query with the best identity, ties to the longer query), `-i` minimum identity (-1 writes every query, 0 only those with a shared hash), `-v` maximum p-value. Verified against the installed mash 2.3 on 240 random screens (`generate_mash_screen_oracle.py`, seed 20261223: reads with 0 - 5 % errors from related genomes and random reads, contigs, k 4 - 32, s 5 - 2000, seeds, `-n`, `-i`, `-w`, `-i` / `-v` filters, 1 - 4 queries, 1 - 2 mixtures): **240 / 240 byte-equal**. Not part of this port: amino-acid queries (6-frame translation of the mixture).

## Read sets and comments (A5-10b, B09 F186)

`MashCommands.MashReadsOptions(MinCopies, TargetCoverage, GenomeSize)` passed to `Dist` / `Triangle` (MCP `reads`, `minCopies`, `targetCoverage`, `genomeSize` of `mash_dist` / `mash_triangle`) is `mash ... -r -m -c -g` (`Sketch.cpp` `sketchFile`, `MinHashHeap::tryInsert`): `KmerAnalyzer.CreateReadsMinHashSketch` keeps a hash in the bottom-`s` set only after it was seen `m` times (pending counts below the set's largest hash; pending hashes above an evicted hash are dropped), takes the reads in order until the mean multiplicity of the kept hashes reaches `-c`, and gives the sketch the length `-g` or the estimated number of distinct k-mers (`2^bits * n / largest hash`, truncated), which enters the p-value; the comment of a read-set sketch counts the reads taken (`[N seqs] name comment [...]`). `-i` with `-r` is refused as the program does. `-C` (`showComments`): `name:comment` for `dist`, the comment instead of the id for `triangle` (the comment of a file sketch is `name comment` of its first record, `[N seqs] ... [...]` for several, the record's own with `-i`). One `Sketches` function now serves `dist`, `triangle` and `screen` (the private query sketcher of `screen` is gone). Verified against mash 2.3 on 260 random runs (`generate_mash_reads_oracle.py`, seed 20261224: read sets of 1 - 12x coverage with errors, `-m` 1 - 5, `-c` 1 - 8, `-g`, `-C`, `-n`, `-v`, `-d`, `-t`, `-E`, k 4 - 32, s 5 - 2000): **260 / 260 byte-equal**. 

## The sketch file, `sketch -o`, `info`, `paste` and `.msh` inputs (A5-10b, B09 F193)

`MashSketchFile.Write` / `Read` is the Mash sketch file (`x.msh`): a Cap'n Proto message of `MinHash.capnp` (unpacked, one flat message) built by `capnp::MallocMessageBuilder`. The writer reproduces the builder byte for byte: the root pointer and root struct (3 data words: `kmerSize` / `windowSize`, `minHashesPerWindow` + the bits concatenated / noncanonical / preserveCase, `error` + `hashSeed` XOR 42; 4 pointers: `referenceListOld` (seed 42) or `referenceList` (any other seed), `locusList`, `alphabet`), the reference list (a composite list: tag word + 9 words per sketch: `length64`, name, comment, `hashes32` or `hashes64`, `counts32` of a read set), the empty locus list and the alphabet text, allocated in the order of `Sketch::writeToCapnp` in segments of 1 024, 1 024, 2 048, ... words (`SUGGESTED_FIRST_SEGMENT_WORDS`, `GROW_HEURISTICALLY`); an object that does not fit into the segment of its pointer goes to the segment last created if it fits there or to a new one behind a one-word landing pad that a far pointer references. `Read` follows any segmentation (single and double far pointers).

`MashCommands.Sketch` / `SketchFile` = `mash sketch -o` (`-k -s -S -n -i -r -m -c -g -I -C -l`; a read set of several files is one sketch fed from the files in rotation, one record each; the `-S 4294967295` of the command line is stored as 0), `Info` = `mash info` (`-H -t -c -d`; the table is `printColumns`: indent 2, spacing 2, `-` for an empty field, every row followed by a blank line; the terminal width the program reads is uninitialised memory when the input is no terminal - measured: unlimited, and 0 for a file without sketches), `Paste` = `mash paste` (first file's parameters; a later file with another alphabet / seed / k / strand mode or a smaller sketch size is skipped, a larger sketch is reduced; counts are dropped). A `MashInput.SketchFile` (MCP: an input text `msh:` + base64) among the inputs of `Dist` / `Triangle` / `Screen` is used as it is: the k-mer size, seed, strand mode and sketch size of the first reference sketch file are inherited and later incompatible files are skipped. A FASTA record without a comment keeps the comment of the nearest earlier record of its file that had one (kseq, measured). Oracle: 120 sketch files (`mash_msh_oracle.jsonl.gz`: byte-equal, read-set files up to the order of the counts) + `mash info` in five modes (600 / 600) + 160 `paste` / `dist` / `triangle` / `screen` runs with sketch files (`mash_msh_commands_oracle.jsonl.gz`). MCP `mash_sketch`, `mash_info`, `mash_paste`.

## The order of the counts of a read-set sketch (A5-10b3, B09 F194)

A read-set sketch stores the multiplicities (`counts32`) in the iteration order of Mash's `robin_hood::unordered_map` (`HashSet::toCounts`), while the hashes are sorted: the counts are not parallel to the hashes. `RobinHoodMap` is a port of the flat table of robin_hood.h 3.9.1 (the header bundled with Mash 2.3): `hash_int` (two 64-bit multiplications and a rotation; the 32- or 64-bit key widened to 64 bits), a power-of-two table of at least 8 buckets with the 80 % load factor and the info byte per bucket (5 hash bits + the distance; `try_increase_info` halves the increment), insertion by `doCreateByKey` (skip while the info is less, `shiftUp` over the run), the rehash by `insert_move` in bucket order, the backward-shift erase, `clear`. `KmerAnalyzer.CreateReadsMinHashSketch` feeds it with the insert / erase sequence of `MinHashHeap::tryInsert` and returns the counts in bucket order. Verified (a) against the compiled header on 150 operation streams (`robin_hood_order_oracle.tsv`: bottom-s heap streams with 32- and 64-bit keys and random insert / erase streams: size and FNV-1a of the (key, value) pairs in iteration order), (b) on 140 read-set `.msh` files of the installed `mash sketch -r` (`mash_reads_msh_oracle.jsonl.gz`) and the 120 files of F193: byte-equal.

## The Bloom filter `-b` (A5-10b2, B09 F197)

`mash sketch -b SIZE` (`MashReadsOptions.BloomFilterBytes`; SIZE with `MashCommands.ParseSize`: a whole number with an optional k / K / m / M / g / G / t / T = x 1000 ... 10^12, read with `stof`) implies `-r` and excludes `-m`: `MinHashHeap::tryInsert` asks `bloom_filter` whether the hash was seen; a hash seen before (or a false positive) enters the set with the count 2, a new one only sets its Bloom bits. `MinHashHeap` builds the filter with `projected_element_count = 10^9` and `false_positive_probability = 0`, for which `compute_optimal_parameters` finds -infinity bits for one hash function; the conversion of -infinity to `unsigned long long` is an out-of-range value that is cut to `maximum_size` = 8 x the memory bound, so the filter has ONE hash function over exactly `bytes x 8` bits (the x86-64 build: measured, files byte-equal) - the salt is 0xAAAAAAAA squared plus the low 32 bits of the seeded random seed, the hash is `hash_ap` of the 4 (32-bit sketches) or 8 (64-bit) little-endian bytes of the k-mer hash (`MashBloomFilter`). Oracle: `mash_bloom_msh_oracle.jsonl.gz`, 130 read sets (filters of 8 bytes - 2 MB, with and without `-r`): the whole `.msh` file byte-equal. MCP `bloomFilter` of `mash_sketch` / `mash_dist` / `mash_triangle`.

## The alphabet options `-a`, `-z`, `-Z` and `screen` of amino-acid queries (A5-10b2, B09 F214)

`MashAlphabet` is `setAlphabetFromString` + `sketchParameterSetup.cpp`: `-a` is the 20-letter alphabet `ACDEFGHIKLMNPQRSTVWY` (implies `-n` and `-k 9` unless `-k` is given), `-z TEXT` the distinct characters of TEXT (upper-cased unless `-Z`; implies `-n`; `-a` wins over `-z`), `-Z` keeps the case (the letters of the sequence are not folded and a letter whose case is not in the alphabet is skipped: `-z acgt -Z` sketches lower-case DNA only). A window holding a character outside the alphabet is skipped (`addMinHashes`), `use64 = alphabetSize^k > 2^32` (`pow` in doubles), the k-mer space of the `dist` / `triangle` / `screen` p-value is `alphabetSize^k` (`MinHashSketch.AlphabetSize`, `KmerAnalyzer.MashPValue(..., kmerSpace)`), the alphabet text and the case flag are written into the sketch file and inherited from the first `.msh` input (a sketch file with another alphabet STRING is skipped). The hash is that of the nucleotide path (h1 of MurmurHash3_x64_128 over the k bytes, the low 32 bits below 2^32 states). Canonical k-mers (`-Z` alone) take the complement table of `Sketch.cpp` indexed as the program does (`complement[c - 'A']` out of range: the 256 bytes around the table of the installed build are embedded, `MashAlphabet.Complement`).

`mash screen` / `taxscreen` of a query sketch with the alphabet `ACDEFGHIKLMNPQRSTVWY` translate the mixture in six frames (`CommandScreen.cpp` `hashSequence`): the records of all mixture files are read round-robin (one record of each open file in turn; a file that ends leaves the rotation and the turn skips the file after it: measured), appended to a chunk as `'*'` + sequence (a record shorter than k is not appended), a chunk is hashed when the next record would make it longer than 2^20 characters and at the end (`MashScreenScan.Chunks`); the six frames count from the start of the CHUNK (frame 0 - 2 forward, 3 - 5 of the reverse complement of the whole chunk), codons are translated with the standard code (upper-case A, C, G, T only; anything else, the `'*'` separators included, is a stop), and a window is hashed when it holds no stop. The table of the mixture is built BEFORE the program sets the case flag of the sketch, so its letters are upper-cased whatever `-Z` says: a `-z abc -Z` query sketch screens nothing. Two empty mixture files are no error (`count` also counts the end of a file: the program prints the queries with 0 shared hashes; one empty file is the error "Did not find sequence records in inputs").

Not defined by the program (refused): `-z` with a character of 0x80 or more (the alphabet table is indexed with a signed `char`: a byte of 0xFC writes into the `kmerSize` field of the parameter structure just before the table - measured: `-z $'AC\xfc'` gives k = 1 -, one below the table writes outside the object).

Oracle (`generate_mash_alphabet_oracle.py`): 300 sketch files (`-a`, `-z` with 15 alphabets incl. `AB`, `ACGU`, `abc`, `ACGTacgt`, the 20 letters plus `*`, `-Z`, `-n`, genomes, `-i`, read sets with `-r -m -c -g -b`, k 1 - 32, s 1 - 1000: the whole `.msh` byte-equal and `mash info`), 300 `dist` / `triangle` runs (`-t -v -d -C -E -i -r`) and 300 `screen` runs (protein queries against nucleotide reads / contigs of 1 - 3 files incl. mixtures over 2^20 characters and an empty file, `-w -i -v`, `-z` / `-Z` / `-n` nucleotide queries): **all equal**. MCP `protein`, `alphabet`, `preserveCase` (and a nullable `k`: 21, or 9 with `protein`) of `mash_sketch`, `mash_dist`, `mash_triangle`, `mash_screen`.

## `mash taxscreen` (A5-10b2, B09 F215)

`MashTaxScreen.Run` is `CommandTaxScreen.cpp` + `taxdb.hpp`: the pass of `screen` over the pool (`MashCommands.ScreenPass`), the taxonomy dump read with the program's stream operations (`>>`, `ignore`, `getline`: a malformed line ends the read as it ends the C++ loop), the taxonomy ID of a reference from the mapping file (`taxid`, one separator character, the name up to the end of the line) or the number after the word `taxid` of its comment, the lowest common ancestor (`getLowestCommonAncestor`: the root is excluded from the path, an ID missing from the dump gives 1) of the references that hold a hash, taken in the iteration order of the program's `robin_hood` containers (`hashCounts`: `RobinHoodMap` fed reference by reference; the references of a hash: a second `RobinHoodMap`), the counts per taxon in a `std::unordered_map<TaxID, TaxCounts>` whose node list is WALKED while the loop inserts the ancestors (a rehash in the middle re-links the nodes, so the walk may visit a taxon twice or not at all: `LibstdcxxHashMap`, the node list of libstdc++ 13 - identity hash, buckets 1, 13, 29, 59, 127, ..., new node in front of its bucket or of the list, rehash in the order of the old list - checked against g++ 13), and the report (`writeReport`: the header `%\thashes\ttaxHashes\thashesDB\ttaxHashesDB\ttaxID\trank\tname`, one line per taxon from taxon 1 with `%.4f` percent, the counts as `%i`, the name indented by two blanks per level, the children sorted by clade count with libstdc++ `std::sort` (`LibstdcxxSort`, not stable above 16 children) and listed until one has no count). The options `-i` and `-v` are read by the program and never used; `-t DIR` is the pair of dump texts (`MashTaxonomy`; no download: a taxonomy of your own in the NCBI dump format works), `-m FILE` the mapping text. A node whose parent is missing from `nodes.dmp` is refused: the program leaves the `parent` pointer of that entry uninitialised (valgrind: "Conditional jump or move depends on uninitialised value(s)", "Invalid read"), so it has no defined output.

Oracle (`generate_mash_taxscreen_oracle.py`): 300 runs on synthetic taxonomies in the NCBI dump format (4 - 300 taxa; random, deep and star-shaped trees with up to 45 equal children, synonyms / unique names / common names, ranks), nucleotide and amino-acid queries, `-i` sketches, mapping files with several separators, `taxid` comments, references without a taxonomy ID or with one missing from the dump: **300 / 300 reports equal**; 132 of them rehash the table during the walk and 27 depend on the tie order of `std::sort` (a snapshot walk fails 117 rows, a stable sort 27: the emulation is exercised). MCP `mash_taxscreen`.

## Not ported

`-z` with a non-ASCII character (undefined in the program, see above); `taxscreen` with a dump whose parent is missing (undefined). The warnings of `-w` / the random-match probability go to the error stream of the program and are not produced.
