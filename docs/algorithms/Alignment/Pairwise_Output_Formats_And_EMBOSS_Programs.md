# Pairwise alignment output formats and the EMBOSS programs needle, water and stretcher

**Units:** ALIGN-GLOBAL-001, ALIGN-LOCAL-001, ALIGN-MULTI-001 (audit A2-27 / A2-28 / A2-29, B09 F120 - F126).
**Code:** `EmbossAlignmentWriter`, `EmbossAlignFormat`, `EmbossAlignOptions`, `EmbossPairAlignment`, `EmbossAlignedSequence` (`EmbossAlignmentTypes.cs`), `SequenceAligner.StretcherAlign`, `SequenceAligner.NeedleAlign`, `SequenceAligner.WaterAlign`.
**MCP:** `write_alignment`, `needle_align`, `water_align`, `stretcher_align`, `supermatcher_align`, `needleall_align`, `ksw2_extend`, and the `format` / `names` parameters of the pairwise and multiple-alignment tools.

## 1. EMBOSS `-aformat` writers (F120)

`EmbossAlignmentWriter` reproduces the 29 alignment formats of EMBOSS 6.6.0 (`ajax/core/ajalign.c` `alignFormat[]`) byte for byte:

* pairwise layouts (exactly two rows): `pair`, `simple`, `unknown`, `multiple`, `srspair`, `srs`, `markx0`, `markx1`, `markx2`, `markx3`, `markx10`, `match`, `score`, `sam`, `tcoffee`. They print the program header (`Program`, `Rundate`, `Commandline`, `Align_format`, `Report_file`), the sequence list (with `-aaccshow` / `-adesshow` / `-ausashow`), `Matrix`, `Gap_penalty`, `Extend_penalty`, the statistics block (`Length`, `Identity`, `Similarity`, `Gaps`, `Score`, computed in single precision as `ajAlignSetSubStandard` does) and, once per file, the tail;
* sequence-set layouts (any number of rows, the `ajseqwrite.c` writers): `fasta`, `a2m`, `msf` (GCG checksums, `CompCheck`), `clustal` (CLUSTAL W 1.83 layout), `mega`, `meganon`, `nexus` / `paup`, `nexusnon` / `paupnon`, `phylip`, `phylipnon`, `selex`, `treecon`.

Facts established from the source and confirmed by the binaries: the number columns of `markx0` use the `%*d` running widths of `alignWriteMark` (the `num[]` flag persists over blocks); `markx2` shows the second row with `.` where it equals the first; the T-Coffee percent identity is 0 unless the program stored statistics (stretcher does); stretcher prints integer scores and drops the descriptions; EMBOSS prints dates as `Thu 19 Nov 2026 21:43:53` (`%2d` day) in headers and `dd/mm/yy` in MSF / MEGA / NEXUS; the type that MSF / NEXUS / MEGA print comes from the output set (`seqret`) or from the residues (alignment programs: NEXUS always `datatype=DNA`, MEGA `Protein` for every protein-compatible text); `ajStrAssignSubS` clamps a start behind the end to the last character (MEGA blocks of rows of different length).

Verification: `emboss_aformat_oracle.tsv` (`scripts/alignment/generate_emboss_aformat_oracle.py`): needle / water / stretcher, 29 formats x 114 alignment sets (all matrices, gap penalties, `-awidth`, `-aglobal`, `-adesshow`, `-aaccshow`, `-ausashow`, one sequence against up to three, faked run dates through `scripts/alignment/faketime.c`), 3 303 files identical; `emboss_seqout_oracle.tsv` (`generate_emboss_seqout_oracle.py`): `seqret -osformat` of 11 formats on gapped sets of 1 - 9 rows, 1 309 files identical. Not implemented (EMBOSS needs the `cons` consensus): the pair-markup formats for three or more sequences; `debug` (memory trace); `mase` is not an `-aformat`.

## 2. stretcher (F121)

`StretcherAlign` ports `emboss/stretcher.c`: the Myers-Miller (1988) linear-space divide-and-conquer with the program's integer arithmetic, its midpoint rules (`CC + RR >= midc` with the gap-closed test, then the type-2 scan from the right), the edit-script macros and `stretcher_Calcons`. A gap of length k costs `gapopen + (k - 1) * gapextend`; defaults 16 / 4 (nucleotide, EDNAFULL) and 12 / 2 (protein, EBLOSUM62). Oracle `stretcher_oracle.tsv`: 689 / 689 pairs equal (rows and score).

## 3. needle and water (F122)

`NeedleAlign` ports `embAlignPathCalcWithEndGapPenalties` + `embAlignWalkNWMatrixUsingCompass` in single precision (float matrices, gap penalties rounded by `ajRoundFloat` to 16 mantissa bits, so 0.1 becomes 0.10000038), including `-endweight`, `-endopen`, `-endextend` and the traceback tie rules (`U_FEPS` 1.192e-6). `WaterAlign` ports `embAlignPathCalcSW` + `embAlignWalkSWMatrix` (float path, double maxima, the last cell within `U_FEPS` of the maximum, gap walk-back within 0.01). Oracles `needle_oracle.tsv` (887 / 887 pairs, 100+ with end weights) and `water_oracle.tsv` (860 / 860 pairs, rows, starts and scores).

Both programs are not always optimal: their recurrences forbid some gap-state transitions and mis-initialise the boundary of a one-residue sequence (needle prints score 0), so the plain affine optima (`GlobalAlignAffine`, `SemiGlobalAlignAffine(EndGaps.All)`, `LocalAlignAffine`) are upper bounds that the programs reach on more than 90 % of the committed pairs.

## 4. ksw2-style dual affine gaps and band (F123)

`GlobalAlignDualAffine` / `LocalAlignDualAffine` (`DualAffineScoring`, `SequenceAligner.DualAffine.cs`) score a gap of length k as `max(open1 + k ext1, open2 + k ext2)` (the two-piece model of ksw2 `ksw2_extd2`, minimap2 default `-O 4,24 -E 2,1` = `DualAffineScoring.Minimap2`) with Gotoh's O(m n) recurrence over H, E1, F1, E2, F2 and an optional diagonal band (ksw2 `w`: cells |i - j| <= band). Oracle `dual_affine_oracle.tsv`: 1 600 cases (global / local x full / banded, 400 each), scores equal Biopython 1.88 `PairwiseAligner` with the callable gap score and an independent Waterman-Smith-Beyer program (banded variant), every traceback re-scores to its score and its coordinates are consistent. The original ksw2 sources were not compiled or compared; z-drop, end bonus and extension alignment are registered as A2-29b.

## 5. supermatcher and needleall (F124)

`SequenceAligner.Supermatcher` ports `supermatcher.c` with `embword.c` (`embWordGetTable` incl. its window-skipping of `N` / `X`, `embWordRabinKarpInit`, `embWordRabinKarpSearch` with the `lastlocation` cursor and the match extension, `embWordMatchFirstMax`) and `embaln.c` (`embAlignPathCalcSWFast`, `embAlignWalkSWMatrixFast`, `embAlignReportLocal`): the longest word match of a query against the targets fixes a diagonal, a Smith-Waterman of `-width` cells runs along it from the sequence starts to the first sequence end (single precision, `ajRoundFloat` gap penalties), reported when its score is above `-minscore`; the error file text (`No wordmatch start points for A vs B. No alignment`) is returned. The program is a heuristic, not an optimum. The formats that do not show sequences (`match`, `score`) get the plain-rows alignment with the TARGET first (`ajAlignDefineCC`). `SequenceAligner.NeedleAll` = every B sequence against every A sequence by `NeedleAlign` (minimum score default 0: the ACD help says 1.0, the value is 0; error line `Alignment score (S) is less than minimum score(M) for sequences A vs B`); `-nobrief` is `SequenceAligner.SimilaritySubHeader` (`embAlignCalcSimilarity`; a pair without gap-free column prints the x86 `-nan`). The score table of needle / water / supermatcher is one class (`EmbossScoreTable`). Oracle `emboss_multi_oracle.tsv` (`generate_emboss_multi_oracle.py`): 260 supermatcher + 260 needleall runs, whole output files in 12 `-aformat`s and the error files, byte for byte, 520 / 520.

## 6. ksw2 extension alignment (F125)

`Ksw2Aligner.ExtendZ` / `ExtendD` (scalar `ksw_extz` / `ksw_extd`) and `ExtendZ2` / `ExtendD2` (`ksw_extz2_sse` / `ksw_extd2_sse`, minimap2 v2.26) give the global or extension alignment with `q + k e` or `min(q + k e, q2 + k e2)` gap cost, band `w`, Z-drop (`ksw_apply_zdrop`: row-wise for the scalar functions, per anti-diagonal for the SIMD ones), end bonus, the ambiguous-base score (`mat[m*m-1]`, `-e` / `-e2` when 0) and the CIGAR (`ksw_backtrack`, left / right gap placement, reversed output). The SIMD functions are ported lane by lane (16-lane blocks past the band, byte wrap-around, one `mem` buffer with the C layout). Verified against an independent Gotoh program (max, mqe, mte, score, every CIGAR re-scored along its path; 330 cases per variant). Facts: the SIMD band is blurred to 16-lane blocks and `w = 0` ends at the second anti-diagonal; `e2 == e` leaves the long-gap boundary values undefined; the real C program is needed for Z-drop, the approximate flags and banded SIMD cases: `docs/Validation/review-2026-09/handoff/A2-29b-ksw2` (Docker package).

## 7. Biopython `Bio.Align` text formats (F126)

`AlignmentFormats` (+ `BioAlignment`, `BioAlignmentRecord`, `AlignmentWriteOptions`, `AlignmentFileFormat`) writes `fasta`, `a2m`, `clustal`, `phylip`, `nexus`, `stockholm` byte for byte as Biopython 1.88 `Bio.Align.write` and reads them as `Bio.Align.parse` (ids, descriptions, printed rows, `alignment.annotations`, `column_annotations`, record annotations, letter annotations, dbxrefs; all-gap columns disappear as in `Alignment.parse_printed_alignment`). Python `textwrap.fill` (Stockholm long text) is ported (`PythonTextWrap`). Oracle `biopython_msa_oracle.tsv`: 210 written alignment sets per format (1 - 3 alignments, 1 - 8 rows, up to 1 500 columns, quoted ids, descriptions, Stockholm GF / GS / GR / GC annotation, nexus interleave) and the files Biopython can read back (a2m 210, nexus 210, stockholm 197, fasta 128, phylip 125, clustal 124). The EMBOSS writers (`EmbossAlignmentWriter`) and the ClustalW program layouts (`ClustalWAlignmentWriter`) are different dialects (widths, headers, name rules) and are not merged: the MCP `format` parameter selects between them (`emboss:` prefix for the formats the two share: fasta, a2m, clustal, nexus, phylip).

## 8. Reading the input sequences like EMBOSS (A4-3, B09 F153)

Every EMBOSS port reads a PLAIN input sequence through one shared cleaner, `EmbossSequenceReader.Clean` (Infrastructure): only the letters `A-Z a-z` and `*` survive; `-` `.` `~` `?` `#` `+` `_`, digits, blanks, punctuation, control characters and every non-ASCII character are dropped BEFORE any length check, coordinate or score, so positions and `Length` count the cleaned sequence (`needle` of `AC-GTTAGC.TT*` and `ACGTTAGCTT`: score 58, `Length: 11`; the gapped text scored 43 before). Source (EMBOSS 6.6, `ajax/core`): `ajseqread.c` `seqAppend` keeps letters and `* . ~ ? # + -`, `ajseqtype.c` `ajSeqTypeCheckIn` calls `ajStrRemoveGap` for every ungapped ACD type (`any`, `dna`, `nucleotide`, `protein`, `stopprotein`: all the programs below) and `ajstr.c` `ajStrRemoveGap` keeps exactly `A-Z a-z *`. Measured on the installed binaries (`scripts/alignment/measure_emboss_reader_chars.py`): with any of the 252 other characters inserted into a sequence the output of needle, water, stretcher, matcher, merger, megamerger, seqmatchall, fuzznuc, fuzzpro, fuzztran, etandem, equicktandem, dotmatcher and palindrome is identical to the output without it (199 characters dropped, both sequences, nucleotide and protein). A sequence that is empty afterwards is "Unable to read sequence" (zero length) in every program.

The programs that read an ALIGNMENT (consambig, showalign, cons, distmat; ACD type `gapany`) keep `. ~ -` as gaps and read `? # +` as the unknown residue (the three are interchangeable: measured), every other non-letter is dropped (`EmbossSequenceReader.CleanGapped`); rows that become unequal are padded with trailing gaps as the program does.

Ports using the cleaner: `NeedleAlign`, `WaterAlign`, `StretcherAlign`, `Merger`, `NeedleAll`, `Supermatcher`, `LocalAlign(Affine)TopN(.., TopNTieOrder.Sim)` (matcher), `DotMatcher.Compute`, `GenomicAnalyzer.MegaMerge`, `SeqMatchAll`, `FindPatternHits` (string overloads; fuzznuc), `FindProteinPatternHits` (fuzzpro), `FindTranslatedPatternHits` (fuzztran), `FindTandemRepeatsEtandem` / `FindTandemRepeatsEquicktandem`, `MotifFinder.GenerateEmbossConsensus` / `GenerateEmbossAmbiguousConsensus`, `MultipleAlignmentDisplay.ShowAlign`, `MultipleAlignmentStatistics.CalculateDistanceMatrix` (distmat). The non-EMBOSS-named entry points (`GlobalAlign`, `LocalAlign`, `FindMotif`, the `DnaSequence` overloads ...) keep every character literally. `EmbossSequenceReader.IsNucleotide` is the single `ajSeqIsNuc` rule (default matrix / alphabet of the programs above; it replaces the copies in `DotMatcher`, `MotifFinder`, `StretcherAlign`).

Oracle `emboss_gap_oracle.tsv` (`generate_emboss_gap_oracle.py`): 18 programs x 240 rows whose inputs contain such characters (4 320 rows) equal on all (`EmbossGapCharacters_Oracle_Tests`).

## 9. Sequence-input qualifiers (A5-7, B09 F172)

Every EMBOSS program reads its sequences through the ACD sequence types, which accept `-sbegin -send -sreverse -slower -supper -scircular -snucleotide -sprotein` (and `-sformat`, `-sask`) for each input (`-sbegin1`, `-sbegin2`, ... for two inputs). The ports implement them ONCE: `EmbossSequenceQualifiers` (Infrastructure record; `Parse("-sbegin1 3 -send1 -2 -sreverse1")` reads a command-line fragment) and `EmbossInputSequence.Read` (Alignment: `ajSeqTypeCheckIn`, `ajSeqFmtUpper/Lower`, `ajSeqReverseDo`, `ajSeqTrim`, `ajCvtSposToPosStart`), returning an `EmbossSequenceView` (trimmed residues, `Offset`, `Offend`, `Reversed`, ...). Sources: EMBOSS 6.6 `ajacd.c`, `ajseq.c`, `ajseqread.c`, `ajseqtype.c`, `ajmath.c`, `ajalign.c`, the 16 program sources (raw.githubusercontent.com/kimrutherford/EMBOSS), all measured on the installed 6.6.0.

* **Range**: 1-based, negative = from the end, clipped into the sequence, an end before the begin gives one residue; `-sreverse` reverse-complements a NUCLEOTIDE sequence (case kept, `X` -> `N`, `U` and `T` -> `A`; a protein is never reversed) and mirrors the range, so the range refers to the original strand.
* **Forced type**: `-snucleotide` / `-sprotein` set the sequence type; under a nucleotide ACD type (`dna`, `nucleotide`) a protein letter of a sequence forced to nucleotide becomes `N`, `-sprotein` is refused ("Sequence is not nucleic"), a protein ACD type refuses `-snucleotide`; the second sequence of an alignment is `nucleotide` or `stopprotein` by the type of the first.
* **Reported coordinates**: the alignment report counts the ORIGINAL strand (a reversed sequence is numbered down: `b 36 ... 1`; the two offsets swap sides, `EmbossAlignedSequence.WithView`). The later sequences of a `seqall` stream carry the first sequence's offsets when only an end is given (the AJAX object is reused: measured); a `seqset` decides the reversal once from its first member.
* **Per program** (all measured): needle / water / stretcher / matcher / supermatcher / needleall (`NeedleProgram`, `WaterProgram`, `StretcherProgram`, `MatcherProgram`, `Supermatcher` / `NeedleAll` with `EmbossSequence.Qualifiers`): the alignment of the trimmed sequences, offsets added, `MatrixName` / default penalties by the first sequence's type; fuzznuc / fuzzpro (`FindPatternHits(.., qualifiers, ..)`, `FindProteinPatternHits`): search the range, report the ORIGINAL strand (the strand flips for `-sreverse`); fuzztran: cuts the reversed text at the begin / end AS GIVEN (not mirrored), numbers from its first position, prints negative numbers for the reverse frames (`S - |frame| - 3 start + 4`; frame -3 of `-frame R / 6` uses the END as `S`: a defect of the program, reproduced); etandem ignores `-sbegin` / `-send` and numbers a reversed sequence on the reverse strand; equicktandem searches the range and adds the begin; dotmatcher scans the WHOLE length over the cut text (the range, a NUL, then the old text behind it); seqmatchall ignores the range and only LABELS a reversed set (words matched on the original, positions numbered from the end); distmat ignores the range and reverse-complements every row of a nucleotide set.
* **merger / megamerger** (`SequenceAligner.MergerProgram`, `GenomicAnalyzer.MegaMerge(EmbossSequence, EmbossSequence, ..)`; measured): merger does NOT trim - the whole (possibly reverse-complemented, case-changed) sequences are merged, `-sbegin` / `-send` have no effect, the conflict positions count the sequences as used, a protein pair uses BLOSUM62; megamerger (ACD type `dna`) merges the TRIMMED texts (range cut after the reversal) and its report counts positions of the trimmed texts; both write the merged sequence in lower case with the conflict bases upper case.
* **Not covered**: `-scircular` has no effect on any of the sixteen programs (measured); `-sformat` (the formats of the residue strings are B20's parsers).

Oracle `emboss_seqopts_oracle.tsv` (`generate_emboss_seqopts_oracle.py`): 16 programs x 180 rows with random begin / end (inside, at, beyond the ends, negative, zero, reversed ranges), reverse, case, circular and type overrides, also the refused combinations: all equal (`EmbossSequenceQualifiers_Oracle_Tests`). MCP parameter `sequenceQualifiers` of `needle_align`, `water_align`, `stretcher_align`, `supermatcher_align`, `needleall_align`, `dotmatcher`, `find_pattern_hits`, `fuzzpro`, `fuzztran`, `find_tandem_repeats_emboss`, `seqmatchall`, `alignment_distance_matrix`.

### 9.1 The qualifier TEXT of the MCP tools (A6-2, B09 F177) and matcher / supermatcher options (A6-3, A6-5)

The text of `sequenceQualifiers` is what follows the sequence arguments of the command line, resolved by the ACD library of the program (`AcdCommandLine`, a port of `acdArgsParse` / `acdIsQual` / `acdFindQual*` over the qualifier universe of each program, `EmbossAcdProfiles.g.cs`; `EmbossSequenceQualifiers.ParseInputs(program, text)` returns one entry per sequence input). Rules, all measured: names are case-insensitive, `-` / `--` / `/` prefixes, `-sbegin=5` (also `sbegin=5`), `-nosreverse1`, boolean values `y yes t true 1` / `n no f false 0` (a separate value token only when it is one of those words), integers `strtol` decimal saturated to int; a number selects the input (`-sbegin1`; `1` is valid for a one-input program); an UNNUMBERED qualifier belongs to the sequence parameter that precedes it (after two files: the second, `-sbegin 3` = `-sbegin2 3`), a numbered qualifier of another input or a qualifier of the program ends that tie, afterwards (and for an abbreviation that the general search resolves to another item, `-sbe 3`) an unnumbered qualifier applies to ALL inputs; an abbreviation must be unique among ALL qualifiers of the program (`-se` is ambiguous in a one-sequence program, `-s` always); `-sformat -sask -squick -sdbname -sid -iquery -ufo -fformat -fopenfile` are accepted without effect, `-ioffset` must be 0, any other qualifier or a stray word is refused. Oracles: `emboss_acd_args_oracle.tsv` (2 080 rows from the program's ACD processing log), `emboss_seqopts_text_oracle.tsv` (640 report rows).

`MatcherProgram` takes `-gapopen`, `-gapextend`, `-alternatives` as the ACD integers (below the minimum: the program's warning in `EmbossProgramResult.StandardError` and the minimum; non-integer: `ArgumentException`); `-gapopen` below `-gapextend` is legal (SIM's `q = gapopen - gapextend` < 0; `matcher_gap_oracle.tsv`, 872 rows). `Supermatcher` with a word length above every target returns the program's `Error: no kmers found` (`StandardError`) without the Rabin-Karp loops (`supermatcher_wordlen_oracle.tsv`, 260 rows).


## 10. Feature-report texts (A5-8, B09 F176)

`EmbossReportWriter` (Alignment; see 10.1 for every format) writes `-rformat gff` and `-rformat excel` for fuzznuc, fuzzpro, fuzztran, etandem and equicktandem from the `EmbossReport` that `EmbossReports.Fuzznuc / Fuzzpro / Fuzztran / Etandem / Equicktandem` build from the hits: one canonical layer, no per-program writer. ### 10.1 Every `-rformat`, the report options, several sequences, `-origfile` (A5-8b, B09 F184)

- **Facts measured on 6.6.0 and reproduced** (the installed binary is the authority where the 6.6.0 git source differs: dasgff scores print `%f`): the header lines (`# Program`, `# Rundate` of the faked clock, `# Commandline` with the echo rules of `acdArgsParse`, `# Max_hits_total`, `# Max_hits_sequence`, `# Report_format` as typed, `# Report_file`), the per-sequence header (`from` / `to`, `(Reversed)`, `# Accession`, `# Description`, `# HitCount`, the program's header text with the `# ` block rules) and tail (`HitLimit: m/n` of `-rmaxseq`), the footer (`# Total_sequences`, `# Total_length` = the TRIMMED lengths, `# Reported_*`, `# Unreported_hitcount`, `# Max_hitcount`, `# Maxhits_stop`); `-rmaxall` stops the run at the first sequence it cannot write (the program reads no further sequence); the limited copy of `-rmaxseq` keeps the table length and group count (`debug`); the tables of fuzzpro after the first sequence are reset tables (the GFF header reads `DNA`, tagseq names the types as for nucleotides); `listfile` switches the report to USAs for the rest of the run; ordering of range patterns (start descending; on the complement strand end descending, with mismatches end ascending; for a reversed sequence in the coordinates of the searched reverse complement); a reversed sequence stores `+` / `-` explicitly (NUL for the forward strand otherwise); fuzztran's reverse-frame (negative) coordinates are read as unsigned by `dbmotif` / `motif` / `regions` / `seqtable` / `srs` / GFF (`1 -28`, the `##sequence-region` end near 2^32); a feature that makes `dbmotif` / `motif` write ~2^32 blanks (the program runs for minutes) is refused with `NotSupportedException`.

- **Verification:** `emboss_report_formats_oracle.jsonl.gz` (`generate_emboss_report_formats_oracle.py`, seed 20261221): 5 programs x 24 formats x 100 runs = **12 000 report files byte-equal** (run date faked by `faketime.c`; multi-sequence files, descriptions / accessions of FASTA headers, `-sbegin -send -sreverse`, every report option, the `-origfile` text, refused formats with their message); `distmat_file_oracle.jsonl.gz` (300).

### NCBI-style FASTA identifiers and pattern files (A5-8c, B09 F192)

The `fasta` input format of EMBOSS 6.6.0 is `seqReadNcbi`: a header whose first word contains `|` is parsed by `ajSeqParseNcbi` (database prefix, accession / version, identifier, description: `gb|AB123456.1|locus desc` is the sequence `locus`, accession `AB123456`), every other header by `ajSeqParseFasta`; the name goes through `seqSetName` (the last non-empty `:` part; `,` `/` `\` become `_`) and a sequence without a name is called `EMBOSS_001`, `EMBOSS_002`, ... (`EmbossNcbiHeader`, `EmbossFastaReader`). A header with exactly two barred tokens (`xx|yy`) takes the program ~28 s (an unsigned loop of 2^32 steps) and leaves the sequence unnamed; the port returns at once.

`-pattern @file` (`EmbossPatternList.Read` = `ajPatlistSeqRead`): one pattern per line, or FASTA style (`>name` or `>name<mismatch=n>`, the pattern over one or several lines); the first line decides unless `-pformat simple` (`-pformat fasta` is the program's "format 0" = decided by the first line); blank lines of a simple file count in the numbering `pattern<n>` (`-pname` replaces the prefix) and an empty pattern is dropped. The report header has a row `Pattern_name Mismatch Pattern` per pattern, the features are the hits of every pattern in the order of the list (fuzznuc: the forward hits of every pattern, then the complement hits of every pattern; fuzztran: frame by frame). 1 110 / 1 110 report files equal the installed programs (`emboss_ncbi_pattern_oracle.jsonl.gz`).

## 12. Protein patterns with mismatches, diffseq, wordmatch (A5-8c2 / A5-8c3 / A2-28d, B09 WP47 F195 / F196 / F198)

## `est2genome` (A2-28d, B09 F203)

`EmbossEst2genomePrograms.Run` / MCP `est2genome` (`emboss/est2genome.c` over `nucleus/embest.c`, EMBOSS 6.6.0, Richard Mott's `est_genome`): the spliced alignment of EST sequences to an unspliced genomic sequence. The dynamic program runs over the genomic sequence (columns) and the EST (rows) with three moves - diagonal (+match / -mismatch), a base deleted from either sequence (-gappenalty) and an intron: a jump from the best earlier cell of the same EST position that costs `intronpenalty`, or `splicepenalty` when the cell before the jump is a donor (GT, CT for a reversed gene) and the landing cell an acceptor (AG, AC); N never scores. `mode both` aligns the forward EST and the reverse-complemented EST with forward-gene sites, redoes the better one with reversed-gene sites and keeps the best (the Note line says which); alignments below `minscore` are dropped; `-align -width` draws the alignment. When `(genome + 1) x (EST + 1) / 4` exceeds `space` megabytes the linear-space recursion (`estAlignMidpt`: the cell of the middle EST position that the best path crosses, then the two halves) is used, the matrix of a half that fits is aligned in the global mode. The engine is a port statement by statement (`EmbossEstAlign.cs`), including the defects of the program (the shuffle does not shuffle, `-nobest` with one strand crashes, `-width 0` never ends). Verified against the installed est2genome on 330 runs (byte-equal `-outfile` text): docs/Evidence/ALIGN-LOCAL-001-Evidence.md.

## 13. The bridge from `AlignmentResult` to coordinates, CIGAR, MD and cs (audit R14-9, B09 F302)

`AlignmentResultCoordinates` (namespace `Seqeron.Genomics.Alignment`, extension methods of `AlignmentResult`) connects the rows of every pairwise aligner to the block-coordinate world of Biopython's `Bio.Align.Alignment`:

| Member | Result |
|---|---|
| `ToBioCoordAlignment(name1, sequence1, name2, sequence2)` / `(name1, length1, name2, length2)` | `BioCoordAlignment` (target first, query second, `score` = `ExactScore`); the coordinates are the runs of aligned pairs, insertions and deletions of the rows; the residues before / after a row come from `EmbossAlignedSequence.Flanks`, so the `End` convention of the result is irrelevant; with lengths only the residues of the rows are known |
| `ToCigar(extended)` | the CIGAR of the columns: `M` (or `=` / `X`), `I` = residue of the query against a gap, `D` = residue of the target against a gap; `*` for an empty alignment |
| `ToCigar(length1, length2, extended)` | with the soft clips (`S`) of the query as the SAM line of `Bio.Align` |
| `ToMd` | the SAM `MD` tag of the writer (one implementation, shared with the SAM writer) |
| `ToCs(longForm)` | the minimap2 `cs` string (the `mm_gen_cs` port, one implementation) |
| `Format(name, ...)` | `bed`, `bed3` .. `bed12`, `psl`, `chain`, `maf`, `sam`, `sam:md`, `exonerate`, `exonerate:cigar` as `alignment.format`, and `cigar`, `cigar:eqx`, `md`, `cs`, `cs:long` |

## 14. Biopython `Bio.Align`: the PairwiseAligner and the operations of the Alignment object (audit R14-10, B09 F303)

**`PairwiseAligner`** holds the settings of Biopython's class: `Mode` (`global`, `local`, `fogsaa`), `MatchScore` / `MismatchScore` or a `SubstitutionMatrix`, `Wildcard` (a letter that scores 0 against every letter, scalar scoring only), `Epsilon`, the twelve gap scores (`OpenInternalInsertionScore` ... `ExtendRightDeletionScore`; `SetGapScore(name, value)` takes every name of Biopython's property tree, e.g. `open_gap_score`, `left_gap_score`, `target_extend_gap_score`, `end_insertion_score`) and gap-score functions; `Algorithm` names the algorithm Biopython selects. `Score` and `Align(sequenceA, sequenceB, strand)` run the library's aligners (insertion = a gap in the target A, deletion = a gap in the query B; strand `-` aligns A with the reverse complement of B, swaps the left and right end gap scores and gives decreasing query coordinates); `Align` returns every optimal alignment as a `BioCoordAlignment` (the library enumerates in its own order; compare with `AlignmentOperations.Compare`). FOGSAA (Chakraborty & Bandyopadhyay 2013) is a port of the branch-and-bound of `_pairwisealigner.c`: one optimal global alignment, found with upper / lower score bounds in a priority queue; Biopython's warnings (match below mismatch, a gap score above the mismatch score) are in `Warnings`. Verified: 698 configurations equal (the FOGSAA alignment itself on 233).

**`AlignmentOperations`** works on `BioCoordAlignment` (sequences and the block coordinates of any number of rows): `Count`, `Length`, `Shape`, `Row` / `Rows` (`alignment[i]`, `numpy.array(alignment)`), `Letter`, `Row(…, columns)`, `Column`, `Slice(rows[, columns])` (`alignment[a:b:c, d:e]`, column lists), `Aligned`, `Indices`, `InverseIndices`, `Frequencies` (weights from the record annotation), `Substitutions`, `ReverseComplement`, `Sort`, `Add`, `Compare` / `AreEqual`, `ParsePrintedAlignment`, `FromAlignmentsWithSameReference`, `Map`, `MapAll` and `Format` (`str(alignment)`, with a matrix for the `:` marks). `Counts(alignment[, wildcard | matrix | aligner])` returns `AlignmentCounts` (aligned, identities, mismatches, positives, the twelve gap counters opened / extended x left / internal / right x insertion / deletion, the gap / substitution / total score, the text of `str(counts)`); for more than two sequences the counts add up over every pair (the program keeps the gap run of the previous pair, as Biopython's C code). MCP: `pairwise_aligner`, `alignment_counts`, `alignment_operation`. The co-optimal enumerators (`GlobalAlign[Affine]CoOptimal`, `LocalAlign[Affine]CoOptimal` with a `GapScoreProfile`) take the direction- and position-specific gap scores of the dynamic program that finds the single alignment.

Gap-score functions and gap scores above zero (audit R14-10b, B09 F307) are available through the same `Score` / `Align` (see section 15).

## 15. Biopython `PairwiseAligner` with gap-score functions and gap scores above zero, `CodonAligner`, the legacy `MultipleSeqAlignment` (audit R14-10b, B09 F307)

**Gap-score functions** (`PairwiseAligner.SetGapFunction("gap_score" | "insertion_score" | "deletion_score", f)`, `f(position, length)`; `GapScoreFunctions.Create(kind, p)` builds the named families `lin`, `log`, `sq`, `pos`, `step`, `tab`, `zero`, `bonus` for the MCP tool): the aligner then runs the Waterman-Smith-Beyer algorithm of `_pairwisealigner.c` (`Aligner_watermansmithbeyer_*`): three matrices (M, Ix, Iy) whose gap states look back over every gap length, the traceback lists with the epsilon ties of the C code, strand `-` (`position` of a deletion counts from the other end; the insertion functions keep the position of the target), the local variant (a gap cell that falls below epsilon is cleared, the zero-score extensions are pruned in a second pass, the end points are marked with the `maximum` that gap cells raise as well) and `Algorithm` = "Waterman-Smith-Beyer global / local alignment algorithm". FOGSAA ignores the functions as in Biopython.

**Gap scores above zero** (a positive `open_*` / `extend_*` score, or an open score above its extend score): Biopython leaves the fast paths of the aligners there. Global alignment uses the single-matrix `Needleman-Wunsch` when open = extend and the three-matrix `Gotoh` otherwise; **local** alignment with a positive gap score uses `Smith-Waterman` (open = extend; `SmithWatermanScore` / `SmithWatermanAlign`: flags DIAGONAL / HORIZONTAL / VERTICAL, ENDPOINT only on a diagonal move, no gap in the last row and column) or `Gotoh` local with the floors of its three states (`GotohLocalScore` / `GotohLocalAlign`). The end-point bookkeeping is reproduced exactly, including its defects: with a positive gap score the reference can list end points that were never cleared (alignments that score less than the optimum) and can miss the optimum (Biopython 1.88: local, match 3, mismatch -1, gap_score +1, `GTTCA` / `TTACC`: score 11, alignments `[[1,3],[0,2]]`, `[[1,1,2],[0,1,2]]`, `[[0,1,2],[1,1,2]]`, not `[[1,3,3,4],[0,2,4,5]]`); the port lists exactly what the reference lists.

**`CodonAligner`** (`_codonaligner.c`): the protein is aligned to the three translated frames of the nucleotide sequence (`Bio.Seq.translate` of the string with the generic codon table: DNA or RNA codons, never mixed, a codon of IUPAC letters that is no codon of the table is `X` without any ambiguity resolution, a letter outside IUPAC is `TranslationError`); every residue takes one codon; between two codons the nucleotide position advances by 1, 2, 4 or 5 instead of 3 at `frameshift_minus_two` / `minus_one` / `plus_one` / `plus_two` (all -3 by default; `FrameshiftScore` and the pair setters of Biopython are properties); leading and trailing nucleotides are free (the first row of the matrix is 0 everywhere); the wildcard letter scores 0. `Align` returns the alignments in the order of the `PathGenerator` iterator as vertices (a frame shift is two vertices of the same residue position). The iterator of Biopython reads the `path` bit field of cells its traceback never wrote when the optimal alignment skips leading residues (the traceback then ends below the first row but `PathGenerator_create_path` starts in the first row): it lists a one-vertex alignment for ever and overflows the tuple it allocated; those inputs (5 to 7 % of random inputs) are refused with `InvalidOperationException`, `Score` is defined for all of them. A protein of length 0 or a nucleotide sequence shorter than 3 gives the column count of the C code (`3 n + 2` for the sequences of 0 to 2 letters).

**`MultipleSeqAlignment` / `SeqRecord`** (the legacy class of Biopython 1.88): a list of `SeqRecord` rows of one length with `annotations` and per-column annotations (the restricted dictionary: a string or an array with one entry per column, whose length is the alignment length at the time the dictionary was created). Members: construction / `Append` / `Extend`, `GetAlignmentLength`, `Count`, indexing (`Row`, `Rows`, `Row(i, columns)`, `Cell`, `Column`, `Slice(rows, columns)` with `PySlice`), `RemoveRow(s)`, `Add` (`+`: pairwise `SeqRecord.Add`, common annotations kept, column annotations concatenated), `Sort(key, reverse)`, `Substitutions` (weighted letter pairs), `ToCoordinateAlignment` (the `alignment` property), `ToString` (`str(alignment)`: at most 20 rows and 50 letters), `ToBioAlignment` (for the text writers). **Defect of Biopython reproduced by default:** the `alignment` property copies each row with `copy.copy`, which shares the letter-annotation dictionary with the source row, and then clears it: the property empties the letter annotations of the source rows (`keepSourceLetterAnnotations: true` leaves them). Sequence features (`SeqFeature`) and file output through `Bio.AlignIO` (`format(alignment, "fasta")` etc.: the AlignIO writers differ from the `Bio.Align` writers of `AlignmentFormats`) are not part of the class.


## 15. The parasail score API (audit R14-11, B09 F304)

`ParasailAligner` gives the score of the best alignment without building it: `Run(query, reference, open, gap, matrix, mode, ends, output)` (also `Nw`, `Sw`, `Sg(variant)`) returns the optimal score and its end coordinates (`EndQuery`, `EndReference`; global: the last residues; local: the best cell of the smallest reference index; semi-global: the best cell of the last row / column that the free ends allow), with `ParasailOutput.Statistics` the number of identical pairs, positive pairs and columns of the optimal alignment (`matches`, `similar`, `length`: parasail's `*_stats`, no traceback), with `Table` the score (and statistics) of every cell, with `RowCol` the last row and column. The gap model is parasail's: a gap of length k costs `open + (k - 1) * gap` (compare `GlobalAlignAffine`: `GapOpen = -(open - gap)`, `GapExtend = -gap`). The program keeps O(min(m, n)) cells: the longer sequence is the outer loop, so a 30 000 x 10 residue problem needs arrays of 11 cells; the tie rules of the original loop order are reproduced (diagonal, vertical gap, horizontal gap; local end: smallest reference index; two free ends: the last row before the last column). `ParasailProfile(query, matrix)` encodes the query once for `Score` / `ScoreBatch` over many references (`parallel` uses all cores). MCP: `parasail_score`. Verified against parasail 1.3.4: 520 pairs x 13 functions x 6 result kinds.

## 16. Banded and X-drop alignment (audit R14-12, B09 F305)

The dynamic programs of the library fill O(m · n) cells (above 25 000 000 cells in exact linear space, which is still O(m · n) time). When the optimum lies near a diagonal (similar sequences, a seed), only the diagonals j - i between `DiagonalLow` and `DiagonalHigh` need to be computed (Ukkonen 1985; Chao, Pearson & Miller 1992): `BandedAlign(a, b, BandedAlignOptions)` for global, local and semi-global alignment, linear or affine gaps, scalar or matrix scoring, in O(m · band) time and memory. The band is stored per Gotoh state (`int[m + 1][width]`), the recurrences are the library's, the traceback is the library's `AffineTraceback` over the band (a linear gap model is the affine program with `GapOpen = 0`), so when the full program's alignment lies inside the band the result is the same row for row (score, rows, coordinates, ties); otherwise it is the best alignment inside the band, never better than the full optimum. Wrappers: `GlobalAlign[Affine]Banded(a, b, scoring, bandWidth)` (diagonals min(0, n - m) - w .. max(0, n - m) + w), `LocalAlign[Affine]Banded(a, b, scoring, low, high)`, `SemiGlobalAlign[Affine]Banded(a, b, scoring, endGaps, low, high)`. `GlobalAlignBandedExact` doubles the band until the result is proven to be the full optimum: a path that leaves a band of half-width w has at least G = |n - m| + 2(w + 1) gap columns, so its score is at most ((m + n - G) / 2) · maxPair + G · gapExtend (gap opens are not positive); when the banded score is strictly above that bound the alignment equals the full program's. `XDrop` prunes cells more than X below the best score seen so far (the BLAST gapped extension; a heuristic that equals the band for a large X). MCP: `banded_align`. Timing (Debug, 30 000 x 30 000, 2 % divergence): affine global w = 100 0.9 s against 98 s for the full program; exact mode 16 s (the worst-case proof bound needs w = 1 024).

The conversion of a PROSITE pattern (`PrositeToRegExp`: `x` is `[^BJOUXZ]`, `(n,m)` is `{n,m}`, `{..}` is `[^..]`, `<` / `>` anchor; the text of the brackets is copied) and the search (`PatMatchFind`) are ports of `embpat.c`; the regular expression is compiled and run by `EmbossPcre`, a port of the PCRE 7 behind `ajRegComp` / `ajRegExecC` (leftmost Perl-compatible backtracking match; the compile errors have the messages and offsets of PCRE 7; an expression PCRE refuses makes the reference die by a segmentation fault and is refused with the message). ## 17. EMBOSS data resource programs and the DRCAT lookup (audit A5-8c3h / WP62, B09 F309)

**The lookup.** A USA `db:id` of a database that the configuration does not define is looked up by `queryDbfind` in the data resource catalogue `DRCAT.dat` (`EmbossDrcat`, 675 entries): an entry that has a `Query` line whose format (a name, or the EDAM term of a format) the sequence reader knows defines the database - format, method `url`, the URL of that line, no accession field - and the entry is fetched over HTTP; the port has no network and reports the failed fetch exactly as the library does without network ("Unable to read sequence"). The standard configuration of the library (`EmbossNames.ParseWithStandard`: `emboss.standard` of the installation, then the user's definitions; `Defined` = `standard` / `user` / the include file) makes `taxon:x`, `go:x`, `chebi:x` ... give the messages of the program ("Database taxon type(s) 'taxonomy' do not match query type 'sequence'"); a USA that names a server and a database (`mrs:x`) is answered by the server and not part of the port.

**`drfinddata`** (`EmbossSequencePrograms.Drfinddata`; MCP `drfinddata`): for every keyword of `-query` (comma separated) the terms of the ontology `edam` whose identifier (`edam-id`), accession (`edam-acc`: the full name and alternate identifiers) or a word of the name or a synonym (`edam-nam`; the words of the index are lower case, `*` is a wildcard, `?` is one only in `id`) equals it, with `-subclasses` (default) all descendants by `ajOboGetTree` (depth first, children from the database named by the prefix of the term's identifier: `EDAM_data-isa:1300`, which is the alias `edam_data` with `namespace: data|identifier`, the hits merged with the hits of the namespace by `ajTableMergeAnd`); every catalogue entry whose `EDAMdat` line lists such a term (`drcat-edat:ID`, first the entries of the first term) is written once to `-outfile` (default `drfinddata.` + `-oformat`) in the format drcat (the entry as in the file), basic (identifier, name, URL) or list (`drcat:ID`). The order of every list is the order of the hash tables of the library (`ajTablePutClean`, 13 buckets, hash of `offset + dbno`, head insertion).

**`dbtell`** (`Dbtell`; MCP `dbtell`): the definition of a database of the standard configuration (`# name is defined in standard` / `is an alias for`, the access levels from `namMethod2Scope` over the method tables of `ajaxdb`, the attributes in the order of the attribute table), `-full` adds the aliases; a name only the catalogue defines gives `DBNAME x [ comment: "defined in DRCAT" ]`. **`showdb`** (`Showdb`; MCP `showdb`): the table of the configured databases, sorted by definition file and name, grouped by type (protein, nucleotide, sequence, feature, taxonomy, resource, obo, xml, text), columns by qualifiers, `-html`, `-database`.
