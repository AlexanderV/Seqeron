## Confirmed fixes

### F1 — ONCO-NEO-001: stop-gain substitution produced windows containing '*'
- **Defect:** `GenerateNeoantigenPeptides("MKTAYIAKQRSTVWLNDEFGH", 5, '*')` returned 35 windows such as `MKTA*IAK`, but translation terminates at the stop, so these are not real peptides. An unsourced fuzz test locked the old behaviour.
- **Source opened:** pVACtools `lib/fasta_generator.py` (raw.githubusercontent.com, griffithlab/pVACtools master). A `'*'` in the mutant amino acid sets `stop_codon_added`, the mutant sequence is truncated to `wildtype[:start] + mutant_aa.split('*')[0]`, and the variant is skipped with "This variant does not result in any novel epitopes". Also opened: `output_parser.py`, `run_utils.py`, `pipeline.py` and `run_argument_parser.py` (default lengths `[8,9,10,11]`).
- **Reference cross-check:** pVACseq's missense windowing logic was re-run in Python. Y5\*, V13\* (k=9) and H21\* (k=8) all give 0 epitopes. For missense variants, 3 000 random cases compared against the C# method: 3 000 identical, 0 different.
- **Fix:** `mutantResidue == StopCodonSymbol` now returns an empty list. It reuses the existing private constant from `OncologyAnalyzer.Fusions.cs`. XML docs updated.
- **Tests:**
  - R1: E18K, k=9 gives exact windows at starts 10–13.
  - R2: pVACseq default lengths 8–11 give 20 peptides.
  - R3: stop-gain returns empty at 3 positions.
  - The fuzz test was re-sourced as `StopGainSubstitution_YieldsNoPeptides_NoCrash`.
- **Documented divergence (not a limitation):** pVACseq drops a variant whose mutant k-mers all occur in the local wild-type window, which only happens in low-complexity repeats. That filtering belongs to later steps.
