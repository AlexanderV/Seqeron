## Confirmed fixes

### F1 — ASSEMBLY-OLC-001: layout ignored in-degree / cycles
- Repro: 6-mers of GTACGTACGAT (l=4) → 5 contigs; reference GREEDY (Langmead greedy_scs, raw.githubusercontent.com/kywertheim/Greedy_shortest_common_superstring/main/main.py; Blum et al. 1994 via snippets) → `GTACGTACGAT`. Duplicate reads formed an unmerged 2-cycle; `TTTTCATGCA,GGGGGATGCA,CATGCAAAAA,TGCACCCCCC` → 3 contigs vs reference `TTTTCATGCAAAAA`,`GGGGGATGCACCCCCC`.
- Fix: edge-GREEDY (sort overlaps desc, take edge iff head/tail free and no cycle; union-find). Tests: `AssembleOLC_GtacgtacgatSixMers_GreedyRejectsCycle_ReconstructsGenome`, `AssembleOLC_TakenHead_TailUsesNextBestSuccessor`, `AssembleOLC_DuplicateReads_AssembleIntoOneContig`.
### F2 — ASSEMBLY-OLC-001: contained reads became spurious contigs
- Source: Myers 2005 (contained reads removed from string graph; snippet). Fix: containment removal before layout, re-placed for consensus. Test: `AssembleOLC_ContainedRead_DoesNotProduceExtraContig`.
### F3 — ASSEMBLY-OLC-001: consensus kept first read's bases
- Repro `ACGTTGCTAC,TGCAACGGAT,GCAACGGATT` (l=5,id=0.8) → `ACGTTGCTACGGATT`; reference (Biopython 1.79 `dumb_consensus`, raw.githubusercontent.com/biopython/biopython/biopython-179/Bio/Align/AlignInfo.py) → `ACGTTGCAACGGATT`. Fix: layout → canonical `ComputeConsensus`. Tests: `AssembleOLC_MismatchInOverlap_ResolvedByMajorityVote`, `AssembleOLC_TwoReadTieInOverlap_EmitsAmbiguitySymbol`.
### F4 — ASSEMBLY-OLC-001: zero-length overlaps accepted
- `minOverlap ≤ 0` chained all reads. Now `ArgumentOutOfRangeException` for minOverlap<1 or minIdentity∉[0,1]/NaN in FindOverlap, FindAllOverlaps×2, AssembleOLC. Test: `OverlapThresholds_OutOfRange_Throw` (5 cases).
### F5 — ASSEMBLY-OLC-001: documented defaults ignored
- `parameters ?? new AssemblyParameters()` zero-initialised the record struct. Added `SequenceAssembler.DefaultParameters` (20, 0.9, 31, 100). Test: `AssembleOLC_NoParameters_UsesDocumentedDefaults`.

### F6 — ASSEMBLY-DBG-001: duplicate/overlapping reads gave chimeric contigs
- Old model: one Eulerian walk per component over every k-mer *occurrence*, so each read copy added a parallel edge and the walk spelled k-mers absent from the input. Repro (k=3/4/3): `ACGT,ACGT` → `ACGGTT` (oracle `ACGT`); `ATGGCGT,GGCGTGCA` → `ATGGCGGTTGCA` (oracle `ATGGCGTGCA`); `AAABBB,AABBBC` → `AAABBBBBBC` (oracle `AAA,AABB,BBB,BBC`).
- Sources: Rosalind BA3K/BA3M (Compeau & Pevzner ch.3: contigs = maximal non-branching paths, isolated cycles included); Zerbino & Birney 2008 Velvet paper (PDF opened: redundancy does not add nodes; RC recorded with each k-mer; merge rule). Two independent Python oracles (BA3M verbatim; Velvet merge) agree on 13 inputs and reproduce both Rosalind samples (code in Evidence).
- Fix: distinct k-mers (Core `SequenceExtensions.CountKmersSpan`, case-insensitive, upper-case output); new public `FindMaximalNonBranchingPaths`; opt-in `AssembleDeBruijn(reads, params, includeReverseComplement)` (Velvet double strand; each contig/RC pair reported once as the smaller string). `BuildDeBruijnGraph` unchanged (textbook multigraph, BA3K reproduced). MCP `assemble_de_bruijn` gains optional `includeReverseComplement`.
- Tests: `AssembleDeBruijn_OverlappingReads_AssembleIntoGenome`, `_DuplicateReads_DoNotDoubleTheGenome`, `_SharedKmersAcrossReads_CountedOnce`, `_IsolatedCycle_IsEmitted`, `_LoopThroughBranchNode_EmittedAsPath`, `_ALongRepeat_SplitsAtRepeatBranches`, `_ToEveryK4_SplitsAtTurnRepeat`, `_ToEveryK3_ContigsPartitionTheKmerSet`, `_MixedCaseReads_JoinCaseInsensitively`, `_ReadShorterThanK_IsSkipped`, `_ReadOrder_DoesNotChangeContigs`, `_ReverseComplementOption_*` (2), `FindMaximalNonBranchingPaths_Ba3mSample`, `_Ba3kSample_OverKmerMultigraph`, `_EmptyGraph_NoPaths`, `_NullGraph_Throws`; fuzz `AssembleDeBruijn_RandomReads_ContigsPartitionDistinctKmers` (600 trials). Behaviour change: a single read no longer re-spells itself through repeats (`AAABBBA`,k=3 → `AAA,AABB,BBA,BBB`, the textbook answer); unit/fuzz/property/MCP expectations updated accordingly.
### F7 — ASSEMBLY-DBG-001: null parameters threw instead of using the defaults

### F14 — ASSEMBLY-MERGE-001: invalid overlap length silently concatenated
- `MergeContigs("BAA","AAB",-2)` → `BAAAAB`; `("AC","GTAA",3)` → `ACGTAA`. Source: Langmead `CG_SCS.ipynb` (`overlap()` ∈ [0, min len], merge `sup += y[olen:]`); old fallback matches no source. Fix: negative or > shorter length → `ArgumentOutOfRangeException` (F4 precedent); 0 = plain join. Tests: `MergeContigs_OverlapExceedsMinLength_Throws` (2), `_NegativeOverlap_Throws`, `_OverlapEqualsBothLengths_ReturnsSingleCopy`; fuzz `_RandomContigsAndOverlap_MatchesOracleOrRejects` (5000) + updated fuzz/property/combinatorial/legacy tests that locked the concatenation.
### F15 — ASSEMBLY-MERGE-001: overlap mismatches never resolved
- Source: EMBOSS `emboss/merger.c` (raw.githubusercontent.com/kimrutherford/EMBOSS, read in full): N yields; otherwise the base with higher local quality ((2·ACGTU + 1·IUPAC)/(2w+1), w = 5, 10, 20) wins; tie → first sequence; case-insensitive. EMBOSS binary not installable here → line-by-line Python port oracle; e.g. `AAAACCCCGGGG`+`CCCCGTGGTTTT`, l=8 → `AAAACCCCGTGGTTTT` (window-5 quality 14/11 vs 18/11); 12-case table in Evidence.
- Fix: overload `MergeContigs(c1,c2,l,resolveOverlapConflicts)` (3-arg = false, unchanged); MCP `merge_contigs` optional `resolveOverlapConflicts`. Tests: `MergeContigs_ResolveOverlapConflicts_MatchesEmbossMerger` (11), `_CaseOnlyDifference_IsNotAConflict`, `MergeContigs_DefaultMode_MismatchedOverlapKeepsContig1Bases`, MCP `MergeContigs_ResolveOverlapConflicts_UsesEmbossMergerRule`.

### F16 — ASSEMBLY-SCAFFOLD-001: predecessor links dropped; conflicts resolved by contig index
- `Scaffold(["AA","TT"],[(1,0,2)])` → `AA,TT` (ref `TTNNAA`); `(2,0,1),(0,1,1)` → `AANCC,GG` (ref `GGNAANCC`); `(1,0,1),(1,2,1)` → `AA,CCNGG` (ref `CCNAA,GG`). Source: Huson, Reinert & Myers 2002 J ACM 49:603 Alg. 5.1 (PDF opened): links in descending weight, ≤2 selected edges per contig, P1≠P2. Fix: greedy selection over end nodes (union-find), stable; scaffolds spelled from a terminal, ordered by lowest contig index.
### F17 — ASSEMBLY-SCAFFOLD-001: no contig orientation
- New `ScaffoldLink(Contig1, Contig2, GapSize, Contig1Reversed, Contig2Reversed, Weight=1)` + overload; bidirected end-node model (ABySS `A+ B-`, AGP +/-); RC via Core `TryGetReverseComplement`; reported strand = more contigs forward (SSPACE), tie → lowest-index forward; Weight<1 throws.
### F18 — ASSEMBLY-SCAFFOLD-001: negative gaps never collapsed
- Source: ABySS `MergePaths/MergeContigs.cpp`, SSPACE `SSPACE_Basic.pl` (read): collapse when the last −d bases agree. Fix via canonical `MergeContigs(tail,next,−d,resolveOverlapConflicts:true)`; else AGP v2.1 100 N. `ACGTAC`+`TACGGA`, gap −3 → `ACGTACGGA`.
- Oracle (F16–F18): independent Python oracle, 17 hand cases (Evidence) + 5000 random oriented/weighted/overlapping cases (seed 2026) 5000/5000. Tests: `Scaffold_LinkIntoLowerIndexContig_IsJoined`, `_PredecessorOfFirstContig_StartsTheScaffold`, `_SecondSuccessorOfJoinedEnd_IsRejected`, `_HeavierLinkWins_RegardlessOfInputOrder`, `_CycleClosingLink_IsRejected`, `_OrientedLink_ReverseComplementsContigs` (3), `_OrientedChain_FollowsBidirectedPath`, `_NegativeGapWithAgreeingOverlap_IsCollapsed` (2), `_NegativeGapWithMismatchedOverlap_EmitsUnknownGap`, `_NegativeGapOverlapOnReverseComplement_IsCollapsed`, `_OverlapThenGap_Chain`, `_ScaffoldsOrderedByLowestContigIndex`, `_LinkWeightBelowOne_Throws`; fuzz `Scaffold_OrientedOverlappingPieces_ReconstructGenomeOrItsReverseComplement` (1000); MCP `ScaffoldContigs_OrientationWeightAndOverlap_DelegateToGreedyScaffolder`. Fuzz oracle replaced (it replicated the index-order bug); `AssertWellFormed` / `Scaffold_PlacesEachContigExactlyOnce` bounds widened for collapsed overlaps (every contig still verbatim).

## Simplifications kept (with reason) / LIMITATIONS proposals

- ASSEMBLY-OLC-001: layout is the GREEDY superstring heuristic (exact Hamiltonian-path layout NP-complete); overlaps ungapped. **LIMITATIONS proposal:** "ASSEMBLY-OLC-001: layout is the GREEDY superstring heuristic (4-approx; repeats longer than reads may be split or mis-joined); overlaps are ungapped (substitutions only); no error-branch pruning."
- ASSEMBLY-DBG-001: **LIMITATIONS proposal:** "contigs are unitigs of the k-mer set; no graph error-cleaning (Velvet tip/bubble removal, coverage cut-off), no paired-end/long-read repeat resolution, so errors and repeats fragment the assembly; double-strand handling is opt-in." (To be re-checked by the audit loop.)
- ASSEMBLY-STATS-001 documented deviations (audit to check): U counted as a valid GC base (QUAST rejects non-ACGTN); IUPAC codes counted as bases not gaps (QUAST converts to N); auNG (auN vs genome size) has no entry point.
- ASSEMBLY-MERGE-001: **LIMITATIONS proposal:** "overlap is ungapped and caller-supplied, not re-verified; EMBOSS merger finds it by gapped global alignment; discovery is FindOverlap's job (substitutions only)." (audit to check)
- ASSEMBLY-SCAFFOLD-001: **LIMITATIONS proposal:** "end-to-end joins only; Huson Alg. 5.2 interleaving ('zipper') and happy/unhappy test need link σ which the input lacks; no edge bundling / transitive reduction / SSPACE link-ratio filter; non-agreeing overlap → AGP 100 N (ABySS tries gapped overlap alignment first)"; deviation: unresolved ≤0 gap → 100 N (ABySS/SSPACE emit one 'n'). (audit to check — σ could be an optional link field)
- Open for sweep: `GenomeAssemblyAnalyzer.AnalyzeGapDistribution` uses upper median `lengths[lengths.Count/2]` (locked by `GenomeAssemblyAnalyzerMutationTests.cs:91`).
