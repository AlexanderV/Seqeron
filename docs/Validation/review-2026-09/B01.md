## Confirmed fixes
### F1 — SEQ-COMP-001: `QualitySequence.GetComplement/GetReverseComplement` mapped S and W to N
- Defect: any base whose complement equals itself was treated as "unknown" → S/W (self-complementary IUPAC codes) became N. Repro: `new QualitySequence("ASWRN", q).GetComplement()` → `"TNNYN"` (R→Y handled, S→N — internally inconsistent).
- Source: IUPAC-IUB (Cornish-Bowden 1985, NAR 13:3021 — via WebSearch snippets: S, W, N self-complementary); Biopython `Bio/Data/IUPACData.py` `ambiguous_dna_complement` + `Bio/Seq.py` (raw.githubusercontent.com).
- Reference: Biopython 1.88 `complement("ASWRN")` = `TSWYN`, `reverse_complement` = `NYWST`.
- Fix: private `ComplementReadBase` in `Core/ISequence.cs` delegating to canonical `SequenceExtensions.GetComplementBase` (non-IUPAC → N kept).
- Test: `QualitySequence_Complement_SelfComplementaryIupacCodesPreserved` ("aswrn" → `TSWYN`, revcomp `NYWST`, qualities reversed; "A-G" → `TNC`).

### F2 — SEQ-VALID-001: IUPAC ambiguity-code validation mode missing (doc declared it "not implemented")
- Source: Biopython `Bio/Data/IUPACData.py` (raw GitHub + installed 1.88): ambiguous_dna_letters `GATCRYWSMKHBVDN`, ambiguous_rna_letters `GAUCRYWSMKHBVDN`; scikit-bio 0.7.4 DNA/RNA definite∪degenerate chars; NC-IUB 1984 (WebSearch snippet).
- Fix: `SequenceExtensions.IsValidIupacDna/IsValidIupacRna` (15 codes, ASCII case-folding, gaps rejected) + `IupacHelper.IsNucleotideCode(char)` (same set `MatchesIupac` accepts).
- Reference: Biopython and scikit-bio agree on 14 inputs ("" true/true; "ACGTNRYSWKMBDHV" any case DNA true/RNA false; "ACGUNRYSWKMBDHV" false/true; "AC-GT","AC.GT","ACGX","ACG N","ACGTE","ACGTI","ſ" false/false) — locked in `SequenceExtensions_SequenceValidation_Tests.cs`.

### F3 — SEQ-VALID-001: `IupacDnaSequence` accepted 'ſ' (U+017F) as 'S'
- Repro: `new IupacDnaSequence("ACſ").IsValid()` → true, stored "ACS" (`ToUpperInvariant` folds U+017F→'S'; brute force over all 65,536 chars shows this is the only non-ASCII→ASCII fold).
- Reference: scikit-bio `DNA("ſ", lowercase=True)` raises.
- Fix: `SequenceBase` ctor upper-cases ASCII letters only (internal `SequenceExtensions.ToUpperAscii`); now invalid, sequence kept as "ACſ"; "acgtnry" → "ACGTNRY" unchanged.


### F4 — SEQ-COMPLEX-001: Troyanskaya (2002) suffix-tree algorithm missing (declared "Simplified")
- Defect: only a substring-hash path, O(N·m²); all-length LC (m=N, Troyanskaya/Rosalind definition) impractical for long input. Doc listed the suffix-tree algorithm as not implemented.
- Source: Troyanskaya et al. 2002 Bioinformatics 18:679 (V_i = suffix-tree nodes at depth i; OUP abstract via WebSearch), Orlov & Potapov 2004 NAR 32:W628 (m-capped sum), Rosalind LING sample; universalmotif `R/sequence_complexity.R` (raw GitHub) — product form from the same V_i/V_max reproduces its Trifonov examples to 4 dp (0.6364, 0.7273, 0.01231, 0.2386, 0.0227, 0.0011), confirming V_max = min(4^i, N−i+1).
- Fix (surgical, LC methods only in B04-owned `Analysis/SequenceComplexity.cs`): for m > 12 V_i counted from the (cached) suffix tree via `ISuffixTreeVisitor` (terminator excluded); m ≤ 12 keeps hash path; shared `LinguisticComplexityFromCounts` with shift-based V_max (no 4^i overflow). Signatures and null/empty/m<1 → 0 contract unchanged.
- Reference: exact-fraction python reference (`lc_ref.py`). Tests LC-13..18 (18 cases): Rosalind ATTTGGATT → 0.875 (m=9 and m=int.MaxValue); all-length 28/31, 4/31, 33/140, 69/70; Orlov m=7 51/55, 52/55, 28/55, 9/11, 3/5, 4/11; N=m=40 → 749/761; 120-nt suffix-tree path 782/1209, 1405/1937, 1971/2251, 6427/6987; homopolymer N=200 000 closed form.

### F5 — SEQ-ENTROPY-001: `SequenceComplexity.CalculateShannonEntropy(string)` ignored RNA uracil
- Defect: `CalculateShannonEntropy("ACGU")` → log₂3 = 1.585 (U dropped silently); also exposed as MCP `complexity_shannon`. The fuzz test locking "U ignored" rested only on our own doc.
- Source: IUPAC nucleotide nomenclature — U is the RNA counterpart of T (IUPAC Gold Book N04254 / genome.gov glossary via WebSearch snippets); consistent with canonical `SequenceExtensions.CountGcAndValidNucleotides` which counts U as a valid nucleotide.
- Reference: scipy.stats.entropy(base=2) with U→T: ACGU 2.0, AAUU 1.0, acgu 2.0, ACGUN 2.0, GGGGCCCAU 1.7527152789797047, AAAAAAAAAAAAACGT 0.9933927290103627, AACGTTTGCA 1.970950594454669, ACGTNNRYacgt 2.0 (all-zero counts → 0 by documented empty-sum convention; scipy gives nan).
- Fix (surgical, B04-owned `SequenceComplexity.cs`, `CalculateShannonEntropyCore` only): counts {A,C,G,T/U} via switch; XML doc states alphabet/U rule/exclusions. Tests `CalculateShannonEntropy_RnaUracil_CountedAsFourthNucleotide`, `CalculateShannonEntropy_MatchesScipyReference`; fuzz case replaced by `ACGTR` (R ignored → 2.0).

### F6 — SEQ-GCSKEW-001: string overloads of windowed/cumulative GC skew had no window/step guard
- Defect: `CalculateWindowedGcSkew(string, 10, stepSize: 0)` and `CalculateCumulativeGcSkew(string, windowSize: 0)` never terminate (`i += 0`); negative window threw lazily from `Substring`. DnaSequence overloads and MCP wrappers already rejected <1. Biopython `GC_skew(seq, 0)` raises.
- Source: Grigoriev 1998 NAR 26:2286 (cumulative sum of per-window (G−C)/(G+C), WebSearch snippet); Lobry 1996; Biopython 1.88 `GC_skew` source (local `inspect`, run); SkewIT `gcskew.py` (raw GitHub).
- Fix: eager `windowSize >= 1` / `stepSize >= 1` checks (null/empty → no points kept). Tests (8): invalid-size cases throw immediately; Biopython `GC_skew("GGGCACGTGGCCCCAT",4)` = [0.5,0,0,−1], cumulative [0.5,0.5,0.5,−0.5], positions [2,6,10,14]; `"gggGCCCCGG"` w=4 → [1,−1] (= Biopython's complete-window prefix of [1,−1,1]).

## Duplication removed
- **SEQ-GC-001** — `CalculateGcContent` and `CalculateGcFraction` each carried their own counting loop. Added the additive public primitive `SequenceExtensions.CountGcAndValidNucleotides(ReadOnlySpan<char>)` → `(GcCount, ValidCount)`; `CalculateGcFraction` uses it and `CalculateGcContent` = `CalculateGcFraction()*100` (bit-identical, verified on 413 inputs).
- **SEQ-COMP-001** — `RnaSequence.Complement/ReverseComplement` inline A/U/C/G switch → canonical `GetRnaComplementBase`. `IupacDnaSequence` private `_complements` dictionary (duplicate IUPAC table) removed → `ComplementSymbol` delegates to `GetComplementBase` (gaps kept, unknown → N). Locked by `IupacDnaSequence_Complement_MatchesBiopythonIncludingGaps` (`ACGTRYWSKMBDHVN` → revcomp `NBDHVKMSWRYACGT`; `AC-.G` → `TG-.C`).
- **SEQ-REVCOMP-001** — `DnaSequence.Complement()`, `ReverseComplement()`, `GetReverseComplementString()` each had a private per-base loop → now `string.Create` over canonical `SequenceExtensions.TryGetComplement`/`TryGetReverseComplement` (signatures and null/empty behaviour unchanged). Locked by `GetReverseComplementString_MatchesCanonicalAndBiopython` (ACGTRYSWKMBDHVN→NBDHVKMWSRYACGT, ACTG-NH→DN-CAGT, ACGU→ACGT) and `DnaSequence_AllReverseComplementVariants_AgreeWithBiopython` (GATTACA→TGTAATC).

- **SEQ-VALID-001** — ACGT/ACGU membership loop existed 3× each (`SequenceExtensions.IsValidDna/Rna`, `DnaSequence/RnaSequence.ValidateSequence`, MCP `dna_validate`/`rna_validate` re-scan for error position). New canonical `SequenceExtensions.IndexOfInvalidDna/IndexOfInvalidRna(ReadOnlySpan<char>)`; all callers delegate (MCP wrapper bodies rewritten to delegate; signatures/outputs unchanged).

- **SEQ-COMPLEX-001** — none in ownership; MCP `complexity_linguistic` delegates correctly.

- **SEQ-ENTROPY-001** — none in ownership; both overloads share kernel `ShannonEntropyBits`; MCP `complexity_shannon` delegates.

- **SEQ-GCSKEW-001** — none; no other GC-skew implementation in repo; `SequenceStatistics` and 4 MCP wrappers delegate.

- **SEQ-ATSKEW-001** — `CalculateGcSkewCore` and `CalculateAtSkewCore` each had a two-pass LINQ count loop → single-pass private kernel `CalculateSkewCore(seq, plus, minus)` used by GC/AT skew, windowed, cumulative and `AnalyzeGcContent` (behaviour unchanged). MCP `at_skew` delegates.

## Simplifications kept (with reason) / LIMITATIONS proposals
- (SEQ-VALID-001, note) `IupacDnaSequence.IsValid()` tolerates U and '-'/'.' (container tolerance, documented; scikit-bio accepts gaps, neither reference accepts U in DNA). MCP validate tools throw on empty input (MCP-wide convention) while core returns true.

- (SEQ-COMPLEX-001, note) LC denominator assumes DNA alphabet (a=4); non-ACGT chars in the raw-string overload can push LC > 1 — documented in algorithm doc §5.3/§6.

- (SEQ-GCSKEW-001) LIMITATIONS proposal: "GcSkewCalculator windowed/cumulative GC skew report only complete windows; a trailing partial window (length mod window) is not emitted (SkewIT convention). Biopython `GC_skew` appends it, so point count can differ by one while all shared values are identical." Windowed skew is O(n·w/s) (per-window recount) — documented.
