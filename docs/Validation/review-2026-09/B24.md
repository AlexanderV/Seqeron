## Confirmed fixes

### F1 — ONCO-CNA-001: Int32 saturation made explicit (contract)
- Initial finding: `(int)Math.Ceiling(2·2^30)` / `(+∞)` could wrap to a negative CN labelled Gain. On .NET 9+ (repo targets net10.0) floating→int casts **saturate**, so no wrap was actually observable; the pre-existing fuzz contract (`OncologyCnaClassificationFuzzTests`: +∞ / 1024 → CN saturated ≥ 0, Amplification) already locked that. A first attempt (94fd191) made the call throw, which broke those fuzz tests and ONCO-CNA-003; it was reverted in the ONCO-CNA-003 commit to an **explicit** saturation (`copyNumber >= int.MaxValue ? int.MaxValue : (int)copyNumber`), independent of runtime cast semantics.
- Source: CNVkit `cnvlib/call.py` master (`absolute_threshold`, `do_call`), raw.githubusercontent.com. Reference: numpy port — ceil(2·2^29.9)=2003673093 (locked); ceil(2·2^30)=2147483648 > int.MaxValue; `int(np.ceil(inf))` raises OverflowError (not representable either way → saturate, state Amplification).
- Tests: `CallCopyNumber_VeryHighLog2WithinInt32_MatchesReference`, `CallCopyNumber_UnrepresentableCopyNumber_SaturatesAtInt32Max` (30, 1024, +∞).
