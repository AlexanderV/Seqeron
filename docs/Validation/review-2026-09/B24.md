## Confirmed fixes

### F1 — ONCO-CNA-001: Int32 saturation made explicit (contract)
- Initial finding: `(int)Math.Ceiling(2·2^30)` / `(+∞)` could wrap to a negative CN labelled Gain. On .NET 9+ (repo targets net10.0) floating→int casts **saturate**, so no wrap was actually observable; the pre-existing fuzz contract (`OncologyCnaClassificationFuzzTests`: +∞ / 1024 → CN saturated ≥ 0, Amplification) already locked that. A first attempt (94fd191) made the call throw, which broke those fuzz tests and ONCO-CNA-003; it was reverted in the ONCO-CNA-003 commit to an **explicit** saturation (`copyNumber >= int.MaxValue ? int.MaxValue : (int)copyNumber`), independent of runtime cast semantics.
- Source: CNVkit `cnvlib/call.py` master (`absolute_threshold`, `do_call`), raw.githubusercontent.com. Reference: numpy port — ceil(2·2^29.9)=2003673093 (locked); ceil(2·2^30)=2147483648 > int.MaxValue; `int(np.ceil(inf))` raises OverflowError (not representable either way → saturate, state Amplification).
- Tests: `CallCopyNumber_VeryHighLog2WithinInt32_MatchesReference`, `CallCopyNumber_UnrepresentableCopyNumber_SaturatesAtInt32Max` (30, 1024, +∞).

- Fix: `MidpointRounding.ToEven` (also property-test oracle in `Properties/OncologyProperties.cs`). Test `CallCopyNumber_NaNNonIntegerPloidy_RoundsHalfToEven`.

## Simplifications kept (with reason) / LIMITATIONS proposals

- ONCO-CNA-001: only CNVkit's pure-sample `_log2_ratio_to_absolute_pure` path is implemented (purity rescaling is done upstream by ONCO-ASCAT/PURITY); scope choice already declared in algorithm doc §5.3 — no LIMITATIONS entry needed.
- ONCO-CNA-002 LIMITATIONS proposal: "`DetectFocalAmplifications` applies GISTIC2's focal filter (arm fraction < broad_len_cutoff ∧ log2 > t_amp) to each input segment as if it were one SCNA event; GISTIC2's ziggurat deconstruction (amplitude relative to the underlying level, cohort-learned arm broad levels) is not implemented. Raw segments of an arm-level gain interrupted by a focal peak (e.g. 0.5 | 1.5 | 0.5) therefore report the flanks as focal amplifications, whereas GISTIC2 reports one broad (0.5) and one focal (+1.0) event. Arm fraction is in bp (GISTIC2 default: marker units). Oncogene mapping is arm-level, not locus overlap. Reason: deconstruction needs a cohort-level 2D event-length/amplitude likelihood model with BIC breakpoint selection (`perform_deconstruction.m`, `find_max_broad_level_by_table`); critically complex and incompatible with the per-segment API." Declared in XML doc + algorithm doc.
- ONCO-PURITY-001 LIMITATIONS proposal: "`EstimatePurity*` combine per-variant closed-form CNAqc estimates by their median — no read-depth weighting, no binomial likelihood (e.g. PurBayes), no joint ploidy fit; use `FitPurityPloidy` (ASCAT) for a genome-wide joint estimate. VAF-only overloads assume clonal heterozygous copy-neutral diploid SNVs."

- ONCO-PLOIDY-001 LIMITATIONS proposal: "`DetectWholeGenomeDoubling` divides by the reference-assembly autosomal length (UCSC chrom.sizes), whereas facets-suite divides by the sample's interrogated span (`get_sample_genome`); they agree only when segments span every autosome end-to-end. Use `DetectWholeGenomeDoublingFromSuppliedLength` for the exact facets-suite call." `EstimatePloidy` weights by bp (Patchwork); ASCAT weights by probe count (identical under uniform probe density; `AlleleSpecificSegment` carries no probe counts) — declared in doc §5.3. ASCAT's own WGD metric (`ascat.metrics`: mode of nMajor) not implemented (alternative convention).

- ONCO-ASCAT-001 LIMITATIONS proposal: "ASCAT/Battenberg run on heterozygous-locus segment summaries: germline-homozygous probes, homozygous-stretch resegmentation and the haploid X/Y (male) model are unavailable, so X/Y are excluded from the fit and emitted as diploid. Battenberg's per-SNP t-test, haplotype phasing (needs an imputation reference panel) and bootstrap CIs are not run; clonality uses maxdist only. `PurityPloidyFit.Ploidy` averages over heterozygous probes. The greedy `SegmentAlleleSpecific` is a non-ASCAT heuristic."
