## Confirmed fixes

### F1 — ONCO-CNA-001: Int32 overflow produced negative CN labelled Gain
- Defect: `CallCopyNumber(30)` / `(+∞)` → `(int)Math.Ceiling(2·2^30)` wraps negative → `Gain`; violates CN ≥ 0.
- Source: CNVkit `cnvlib/call.py` master (`absolute_threshold`, `do_call`), raw.githubusercontent.com.
- Reference: numpy port — ceil(2·2^29.9)=2003673093; ceil(2·2^30)=2147483648 > int.MaxValue; `int(np.ceil(inf))` raises OverflowError.
- Fix: throws `ArgumentOutOfRangeException` when ceil(ploidy·2^v) > int.MaxValue. Tests `CallCopyNumber_UnrepresentableCopyNumber_Throws`, `CallCopyNumber_VeryHighLog2WithinInt32_MatchesReference`.

### F2 — ONCO-CNA-001: NaN no-call rounding
- Defect: NaN log2 → CN = round(ploidy) used AwayFromZero; CNVkit `do_call` uses numpy `round()` (half-to-even). Ploidy 2.5: ref 2 / old 3 / new 2; 3.5: 4/4/4.
- Fix: `MidpointRounding.ToEven` (also property-test oracle in `Properties/OncologyProperties.cs`). Test `CallCopyNumber_NaNNonIntegerPloidy_RoundsHalfToEven`.

### F3 — ONCO-CNA-001: infinite ploidy accepted
- Defect: ploidy +∞ accepted → n=+∞ → wrapping cast. Fix: shared `ValidatePloidy` (finite, >0). Test `Log2RatioToCopyNumber_NonFinitePloidy_Throws`.
- Extra locking tests: triploid reference (ploidy 3, log2 0/0.8/1.0 → 2/6/6, CNVkit port), −∞ → CN 0.
