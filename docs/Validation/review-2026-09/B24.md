## Confirmed fixes

### F1 — ONCO-CNA-001: Int32 saturation made explicit (contract)
- Initial finding: `(int)Math.Ceiling(2·2^30)` / `(+∞)` could wrap to a negative CN labelled Gain. On .NET 9+ (repo targets net10.0) floating→int casts **saturate**, so no wrap was actually observable; the pre-existing fuzz contract (`OncologyCnaClassificationFuzzTests`: +∞ / 1024 → CN saturated ≥ 0, Amplification) already locked that. A first attempt (94fd191) made the call throw, which broke those fuzz tests and ONCO-CNA-003; it was reverted in the ONCO-CNA-003 commit to an **explicit** saturation (`copyNumber >= int.MaxValue ? int.MaxValue : (int)copyNumber`), independent of runtime cast semantics.
- Source: CNVkit `cnvlib/call.py` master (`absolute_threshold`, `do_call`), raw.githubusercontent.com. Reference: numpy port — ceil(2·2^29.9)=2003673093 (locked); ceil(2·2^30)=2147483648 > int.MaxValue; `int(np.ceil(inf))` raises OverflowError (not representable either way → saturate, state Amplification).
- Tests: `CallCopyNumber_VeryHighLog2WithinInt32_MatchesReference`, `CallCopyNumber_UnrepresentableCopyNumber_SaturatesAtInt32Max` (30, 1024, +∞).

### F2 — ONCO-CNA-001: NaN no-call rounding
- Defect: NaN log2 → CN = round(ploidy) used AwayFromZero; CNVkit `do_call` uses numpy `round()` (half-to-even). Ploidy 2.5: ref 2 / old 3 / new 2; 3.5: 4/4/4.
- Fix: `MidpointRounding.ToEven` (also property-test oracle in `Properties/OncologyProperties.cs`). Test `CallCopyNumber_NaNNonIntegerPloidy_RoundsHalfToEven`.

### F3 — ONCO-CNA-001: infinite ploidy accepted
- Defect: ploidy +∞ accepted → n=+∞ → wrapping cast. Fix: shared `ValidatePloidy` (finite, >0). Test `Log2RatioToCopyNumber_NonFinitePloidy_Throws`.
- Extra locking tests: triploid reference (ploidy 3, log2 0/0.8/1.0 → 2/6/6, CNVkit port), −∞ → CN 0.
### F4 — ONCO-CNA-002: focal thresholds not validated
- Defect: `DetectFocalAmplifications([17q 0–100k, arm 1e6, log2 1.0], new(NaN, 0.98))` → `[]` silently; `t_amp = -0.5` reported log2 −0.2 as amplified.
- Source: GISTIC2 `source/gp_gistic2_from_seg.m` (github.com/broadinstitute/gistic2): `numeric_arg(a,'ta',0.1,[0,Inf])`, `numeric_arg(a,'brlen',0.98,[0 2])`, which throw on NaN/out-of-range. Focal rule confirmed in `snputil/reconstruct_genomes.m` (arm fraction < broad_len_cutoff ∧ amplitude gate).
- Cross-check: GISTIC2 rejects / old accepted / new throws `ArgumentOutOfRangeException`; endpoints 0 and 2 accepted as in the reference.
- Fix: `ValidateFocalThresholds` in `IsFocalAmplification` and `DetectFocalAmplifications` (before the loop). Tests: `DetectFocalAmplifications_ThresholdsOutsideGistic2Range_Throw` (5), `_Gistic2RangeEndpoints_Accepted`, `_NaNLog2_NotReported`, `IdentifyAmplifiedOncogenes_DuplicateAndMixedCaseArms_DistinctInPanelOrder`; property generator t_amp range → [0,0.5].
- Note: GISTIC2 is internally inconsistent at exact equality (`gene_calls.m` `>` vs `reconstruct_genomes.m` `>=`); strict `>` kept (matches docs).
### F5 — ONCO-CNA-003: predicate crashed / depended on Int32 CN for extreme log2
- Defect: after 94fd191 `IsHomozygousDeletion(Seg("9p", +∞))` / `(…, 40.0)` threw; fuzz filter seeds 20260105/313131/777 crashed.
- Source: CNVkit `call.py` `absolute_threshold` — above the last cutoff CN = `int(np.ceil(ref*2**log2))` ≥ 4, never 0. Definition of homozygous deletion: Cheng et al. 2017 Nat Commun ("zero copies of both alleles"), cBioPortal −2 (search snippets).
- Reference (Python re-run of CNVkit): −∞→0, −2→0, −1.1→0, −1.0999→1, 0→2, 1→4, 40→2199023255552, 1e6/+∞→OverflowError, NaN→2; new code: CN0 ⇔ first three, others false.
- Fix: one private `CallCopyNumberUnbounded` (CNVkit call as integral double) shared by `CallCopyNumber` (saturates) and `IsHomozygousDeletion` (== 0). Tests `IsHomozygousDeletion_Log2BeyondInt32CopyNumber_IsFalse_WhileCallCopyNumberSaturates`, `DetectHomozygousDeletions_StreamWithExtremeAmplifications_ReportsOnlyCn0`.

### F6 — ONCO-CNA-003: validation skipped on empty input
- Defect: `DetectHomozygousDeletions([], badThresholds)` returned `[]` while sibling methods validate eagerly. Fix: thresholds/ploidy validated before the loop. Test `DetectHomozygousDeletions_EmptyInputWithInvalidParameters_Throws`.
- Note (not changed): CNVkit's CLI `ploidy_value` requires ploidy ≥ 1; the library accepts any finite ploidy > 0 (with ploidy ≤ 0.5 a NaN no-call rounds to CN 0). This is a CLI argument check, not part of the algorithm; left as-is and recorded for the orchestrator.

## Duplication removed

- ONCO-CNA-003: `IsHomozygousDeletion` and `CallCopyNumber` share a single private CNVkit `absolute_threshold` implementation (`CallCopyNumberUnbounded`).

## Simplifications kept (with reason) / LIMITATIONS proposals

- ONCO-CNA-001: only CNVkit's pure-sample `_log2_ratio_to_absolute_pure` path is implemented (purity rescaling is done upstream by ONCO-ASCAT/PURITY); scope choice already declared in algorithm doc §5.3 — no LIMITATIONS entry needed.
- ONCO-CNA-002 LIMITATIONS proposal: "`DetectFocalAmplifications` applies GISTIC2's focal filter (arm fraction < broad_len_cutoff ∧ log2 > t_amp) to each input segment as if it were one SCNA event; GISTIC2's ziggurat deconstruction (amplitude relative to the underlying level, cohort-learned arm broad levels) is not implemented. Raw segments of an arm-level gain interrupted by a focal peak (e.g. 0.5 | 1.5 | 0.5) therefore report the flanks as focal amplifications, whereas GISTIC2 reports one broad (0.5) and one focal (+1.0) event. Arm fraction is in bp (GISTIC2 default: marker units). Oncogene mapping is arm-level, not locus overlap. Reason: deconstruction needs a cohort-level 2D event-length/amplitude likelihood model with BIC breakpoint selection (`perform_deconstruction.m`, `find_max_broad_level_by_table`); critically complex and incompatible with the per-segment API." Declared in XML doc + algorithm doc.
