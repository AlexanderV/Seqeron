## Confirmed fixes

### F1 — PANGEN-CORE-001: open/closed classification was order-dependent and not micropan's method
- Defect: private `DeterminePanGenomeType` fitted a single new-gene curve in dictionary order (log-log OLS, zero-novelty floored to 1). Repro: base + 4,2,1 new clusters → Closed; reversed order → Open; "each genome lacks one distinct accessory" (truly closed) → Open.
- Source opened: micropan `R/powerlaw.R` `heaps()` (raw.githubusercontent.com/larssnip/micropan) — random permutations, pooled points x=2..ng, L-BFGS-B, K∈[0,1e4], α∈[0,2]; open ⟺ α<1 (Tettelin 2008).
- Reference (python scipy L-BFGS-B over all orderings + global α grid): 4 genomes each lacking one accessory → mean new curve 1,0,0, K=3.1745, α=2.0 Closed; 3 genomes → K=3.3402, α=2.0 Closed; base+4,2,1,0 any order → curve 1.75,1.75,1.75, α=0 Open (micropan's own 100-permutation run: α=0.78 Open).
- Fix: `DeterminePanGenomeType` → `FitHeapsLaw(CreatePresenceAbsenceMatrix(...))` (N≥3 guard kept). Tests: M8 (truly closed), M8b (Open both orders); wrong-expectation MutationKillers2 "decaying novelty ⇒ Closed" test replaced by a sourced closed case.

### F2 — PANGEN-CORE-001: presence/absence matrix matched clusters by gene id
- Defect: genes with the same id in different genomes but different sequences (two clusters) were both marked present in both genomes (rows [1,1] instead of [1,0]/[0,1]); null gene list threw.
- Source opened: micropan `R/panmat.R` `panMatrix()` — cell = genome i's members in cluster j, keyed by genome.
- Fix: presence from `GeneCluster.GenomeIds`; null gene list tolerated. Tests M11 (fails on old code), M12.
