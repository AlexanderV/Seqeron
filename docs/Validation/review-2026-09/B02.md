## Confirmed fixes

### F1 — TRANS-CODON-001: IUPAC-ambiguous codons always translated to 'X'

- Source: Biopython `Bio/Data/CodonTable.py` + `Bio.Seq._translate_str` (raw.githubusercontent master, = installed 1.88).
- Cross-check: exhaustive 15³ = 3375 IUPAC codons × 27 tables (translation, start, stop) — 100 % match to Biopython 1.88.
- Fix: expand the ambiguous codon; all-stop → '*', stop+AA mix → 'X', single AA → AA, else B/Z/J if the set is {D,N}/{E,Q}/{I,L}, else 'X'; start/stop only if all expansions are.
- Tests: `Translate_AllIupacCodons_AllTables_MatchBiopython`, `IsStartStopCodon_AllIupacCodons_AllTables_MatchBiopython`, `Translate_AmbiguousCodons_ResolvedAsBiopython` (+ embedded TSV `TestData/GeneticCode/biopython_ambiguous_codons.tsv`); test bent to old code (`Translate_AmbiguousIupacCodon_ProducesX`, "MXX*") corrected to sourced "MXA*".

## Simplifications kept (with reason) / LIMITATIONS proposals

- CODON-ENC-001 LIMITATIONS proposal: "ENC returns 0 = not calculable (CodonW `*****`); do not average it with real Nc values." MCP ENC tools have no genetic-code parameter (would change an existing signature; optional follow-up).

- CODON-RSCU-001: no pseudocount; absent family → 0 (CodonW convention, documented; not a simplification).

- TRANS-SIXFRAME-001: `FindOrfs` implements getorf `-find 1` only; tables 27/28/31 unsupported (context-dependent stops). Documented conventions (algorithm doc §5.4): minLength in aa, reverse-strand ORFs in reverse-complement coordinates, Biopython frame labels, stop-inclusive End. Accepted divergence: a 1-codon open ORF whose START is the last complete codon is reported when minLength ≤ 1 (getorf branch-order artefact omits it).

- TRANS-PROT-001: nucleotide `X` is rejected by Translate (Biopython treats it as N). Kept deliberately: NC-IUB 1984 defines only `N` as any-base; proposal for LIMITATIONS.md.
