## Confirmed fixes

### F1 — TRANS-CODON-001: IUPAC-ambiguous codons always translated to 'X'
- Defect: `GeneticCode.Standard.Translate("GCN")` → 'X' (Biopython 'A'); TAR → 'X' (Biopython '*'); RAY → 'X' ('B'), SAR → 'X' ('Z'), MTH → 'X' ('J'); table 2 AGR → 'X' ('*'). `IsStartCodon`/`IsStopCodon` rejected ambiguous codons. `Translator.Translate("AUGNNNGCNUAA")` → "MXX*" (Biopython "MXA*").
- Source: Biopython `Bio/Data/CodonTable.py` + `Bio.Seq._translate_str` (raw.githubusercontent master, = installed 1.88).
- Cross-check: exhaustive 15³ = 3375 IUPAC codons × 27 tables (translation, start, stop) — 100 % match to Biopython 1.88.
- Fix: expand the ambiguous codon; all-stop → '*', stop+AA mix → 'X', single AA → AA, else B/Z/J if the set is {D,N}/{E,Q}/{I,L}, else 'X'; start/stop only if all expansions are.
- Tests: `Translate_AllIupacCodons_AllTables_MatchBiopython`, `IsStartStopCodon_AllIupacCodons_AllTables_MatchBiopython`, `Translate_AmbiguousCodons_ResolvedAsBiopython` (+ embedded TSV `TestData/GeneticCode/biopython_ambiguous_codons.tsv`); test bent to old code (`Translate_AmbiguousIupacCodon_ProducesX`, "MXX*") corrected to sourced "MXA*".

### F2 — TRANS-CODON-001: only 4 of 27 NCBI translation tables
- Defect: only tables 1, 2, 3, 11 existed (declared "simplified").
- Source: NCBI gc.prt Version 4.6 (raw.githubusercontent ncbi/ncbi-cxx-toolkit-public `src/objects/seqfeat/gc.prt`), parsed and confirmed identical to Biopython's 27 tables.
- Fix: all tables 1–6, 9–16, 21–33 built from the NCBI strings; new `GeneticCode.SupportedTableNumbers`; dual-coding stops in tables 27/28/31 translate to the AA while `IsStopCodon` is true (as Biopython).
- Tests: `SupportedTableNumbers_MatchNcbiGcPrt_V46`, `DualCodingStops_Tables27_28_31_TranslateToAminoAcidAndAreStops`; `TranslationFuzzTests` table lists updated.

### F3 — TRANS-PROT-001: Translate threw on ambiguous codons resolving to B/Z/J (regression after F1)
- Defect: `Translator.Translate("RAYSARMTH")` → ArgumentException "Invalid amino acid 'B'" (Biopython "BZJ"); `ATGRAYSARMTHTAA` → should be "MBZJ*". `ProteinSequence` accepted only 20 AA + `*` + `X`. 94/6420 differential cases failed.
- Source: Biopython 1.88 `Bio.Seq._translate_str`, `Bio.Data.IUPACData.extended_protein_letters` / `protein_letters_1to3_extended` (installed copy = master).
- Cross-check: 6420 cases (random DNA/RNA/IUPAC/lower-case/invalid, all 27 tables, frames 0–2, to_stop on/off) vs Biopython `translate(seq[f:], table, to_stop)` — 100 % match or both error (except nucleotide `X`, below).
- Fix: `ProteinSequence.AmbiguousAminoAcids` (B→Asx, Z→Glx, J→Xle); `ValidCharacters` 25 members; three-letter codes Asx/Glx/Xle; MW/GRAVY/pI skip B/Z/J like X.
- Tests: `Translate_AmbiguousCodonsToAsxGlxXle_MatchBiopython` (12), `Constructor_IupacAmbiguousAminoAcids_Accepted_ThreeLetterCodesAsBiopython`, `Translate_String_AllTables_MatchBiopython` (54). Tests that used IUPAC Z/J as "invalid" examples now use `1` (`ProteinSequenceTests` ×3 incl. rename `ValidCharacters_Contains25Characters`, `CompositionCombinatorialTests.ForeignSymbol`, 5 MCP Sequence tests, `protein_validate` doc examples). Behaviour change: MCP `protein_validate` accepts B/Z/J.

### F4 — TRANS-PROT-001: toFirstStop silently read through terminators in tables 27/28/31
- Defect: `Translate("ATGTGAGGG", table 27, toFirstStop: true)` → "MWG"; Biopython raises ValueError ("You cannot use 'to_stop=True' with this table…"). 406 differential cases.
- Source: Biopython 1.88 `_translate_str`; `Bio.Data.CodonTable` (only 27/28/31 have dual-coding stops).
- Fix: `TranslateSequence` throws ArgumentException when `toFirstStop` and the table has a stop codon that also codes an AA.
- Tests: `Translate_ToFirstStop_DualCodingStopTable_ThrowsArgumentException`, `…WithoutToFirstStop_TranslatesAsAminoAcid` (27→MQGW, 28→MQGW, 31→MEGW per Biopython), `…AllTablesWithoutDualCodingStops_DoNotThrow`.

### F5 — TRANS-PROT-001: string overload skipped argument validation for empty input
- Defect: `Translate("", frame: 5)` → "" while the DnaSequence overload throws; empty + table 27 + to_stop passed (Biopython raises). Consistency fix.
- Fix: null/empty input goes through the same validation. Test: `Translate_EmptyOrNullString_InvalidFrame_ThrowsLikeTypedOverloads`.

### F6 — TRANS-SIXFRAME-001: ORF initiator not reported as Met
- Defect: `FindOrfs("GGTTGAAAGGGTAACC")` → "LKG"; reference "MKG".
- Source: EMBOSS getorf.acd `-methionine` default Y ("Change initial START codons to Methionine"), getorf.c (raw.githubusercontent kimrutherford/EMBOSS); Biopython 1.88 `Seq("TTGAAAGGGTAA").translate(cds=True)` = "MKG", `CTGCTGTAA` → "ML".
- Cross-check: Python port of getorf `-find 1 -methionine Y` vs C# on 30 000 random sequences (0–300 nt) × 26 tables: before 2409/3015 mismatching, after 0 mismatches over 153 483 reference ORFs; six-frame translation 0 mismatches vs Biopython.
- Fix: first residue always 'M'. Tests: old C1 test (asserted "LKG" "in this implementation") corrected → `..._InitiatesOrfWithMethionine`; C1b added.

### F7 — TRANS-SIXFRAME-001: open-ORF end counted trailing partial-codon bases
- Defect: `ATGAAACCCGG` → End 10 (NucleotideLength 11); getorf `WriteORF(start, pos+2)` → End 8, length 9.
- Fix: End = Start + 3·aa − 1. Tests: M11c (fwd), M11d (rev `CCGGGTTTCAT` → −1,0,8,"MKP"), M14 (table 12, 35 nt, exact getorf-port ORF list).

### F8 — TRANS-SIXFRAME-001: dual-coding tables 27/28/31 produced ORFs that never terminate
- Defect: all stop codons of these tables also code an AA (Biopython `stop_codons` ⊂ `forward_table`), so every ORF silently ran to the sequence end.
- Source: Biopython refuses `to_stop=True` for these tables (consistent with F4); EMBOSS has no EGC files for them (EGC.27/28/31 → 404).
- Fix: `FindOrfs` throws ArgumentException eagerly. Test: M15 `FindOrfs_DualCodingStopTable_Throws`.
- Doc fix (no behaviour change): the "EMBOSS getorf positions include the STOP" claim was false (getorf excludes the stop); the stop-inclusive End convention is kept and re-cited to the INSDC CDS definition ("location includes stop codon"); code comment, TestSpec, Evidence, algorithm doc corrected.

### F9 — CODON-USAGE-001: triplets with ambiguity codes / non-nucleotide characters counted as codons
- Defect: `CodonOptimizer.CalculateCodonUsage("ATGNNNGCTRYT")` → `{AUG:1, GCU:1, NNN:1, RYU:1}`; `"AUG-GC"` → `{"-GC":1, AUG:1}`; `CompareCodonUsage("NNNNNN","NNNNNN")` = 1.0; `"atgNNNgct"` vs `"ATGGCT"` = 2/3 (should be 1.0).
- Source: EMBOSS `cusp.c`, `ajcod.c` (`ajCodSetTripletsS`: "Skips triplets with ambiguity codes and any incomplete triplet at the end"), `ajbase.c` (raw.githubusercontent kimrutherford/EMBOSS); Biopython 1.88 `CodonAdaptationIndex` (count table closed over the 64 ACGT codons). Kazusa blocked (403). Note: EMBOSS `ajCodBase` actually maps ambiguous bases to the lowest constituent (N→A), contradicting its own doc — artefact not reproduced, recorded in TestSpec.
- Cross-check: 300 random inputs (ACGT, mixed-case DNA/RNA, IUPAC, gaps/X/space) vs port of documented cusp loop: 0 mismatches; 60 pure-ACGT inputs vs verbatim Biopython loop: exact; 303 `CompareCodonUsage` pairs vs `1 − scipy cityblock(f1,f2)/2`: max |Δ| 1.2e-15.
- Fix: `CalculateCodonUsage` normalises U→T, delegates to canonical `CodonUsageAnalyzer.CountCodons` (ACGT-only, frame-preserving skip), re-spells keys T→U.
- Tests: S7–S10 in `CodonOptimizer_CodonUsage_Tests.cs` (frame-preserving skip, mixed case, compare 1.0/0.0/2/3, agreement with CountCodons). Evidence doc corrected (null input returns empty, not ArgumentNullException).

### F10 — CODON-RSCU-001: RNA input silently gave empty / all-zero results
- Defect: `CodonUsageAnalyzer.CountCodons(string)` accepted only ACGT → `CalculateRscu("UUUUUC")` TTT=TTC=0 (CodonW 1.0/1.0); `CountCodons("AUGAAAUGA")` = {}; same for string overloads of `CalculateCai`, `CalculateEnc`, `GetStatistics`.
- Source: CodonW 1.4.4 `ident_codon` (T/t/U/u same base; original tarball from archive.ubuntu.com, built and run); EMBOSS `ajBaseAlphaToBin` (U → T bit).
- Fix: private `NormalizeCodingSequence` (upper-case, U→T) in every string entry point; other symbols still skipped frame-preservingly.
- Tests: `CalculateRscu_RnaInput_ReadsUAsT`, `CountCodons_RnaInput_CountsLikeDna`, `StringEntryPoints_RnaSpelling_EqualDnaSpelling` (ENC, CAI, GetStatistics).

### F11 — CODON-RSCU-001: synonymous families from a private table-1 copy (no other genetic code possible)
- Source: Sharp, Tuohy & Mosurski 1986 / Sharp & Li 1987 RSCU = n_i·x_ij/Σx; CodonW `codon_us.c rscu_usage_out` ("RSCU values are genetic code dependent"; 64 codons, stops as one family, absent family → 0.000); Biopython 1.88 `CodonTable`; CodonU 1.1.2, codon-bias 0.5.0 (PyPI) compared for conventions.
- Cross-check: CodonW binary `-code 0..7` (NCBI 1,2,3,4,5,6,10,9) × 155 genes = 79 360 values, 0 mismatches (max |Δ| 5e-4 = CodonW 3-dp rounding); Python port over all 27 NCBI tables × 472 inputs: max |Δ| 8.9e-16. Worked example `AGAAGGTAAATAATGTGATGG`: table 1 AGA=AGG=ATA=3, TAA=TGA=1.5; table 2 AGA=AGG=TAA=4/3, ATA=ATG=1, TGA=TGG=1 (= CodonW).
- Fix: families from `GeneticCode.CodonTable`; new overloads `CalculateRscu(DnaSequence|string, GeneticCode)` and core `CalculateRscu(IReadOnlyDictionary<string,int>, GeneticCode)` (pooled counts); dual-coding stops of tables 27/28/31 scored in their AA family (Biopython `forward_table`). Private `CodonToAminoAcid` literal replaced by a DNA-spelled view of `GeneticCode.Standard` (identical → CAI/ENC/GC3s unchanged).
- Tests: +9 in `CodonUsageAnalyzer_CalculateRscu_Tests.cs` (standard vs CodonW, vertebrate mito, table 27, count-table overload, null guards). No existing test asserted old behaviour.

## Simplifications kept (with reason) / LIMITATIONS proposals

- CODON-RSCU-001: no pseudocount; absent family → 0 (CodonW convention, documented; not a simplification).

- TRANS-SIXFRAME-001: `FindOrfs` implements getorf `-find 1` only; tables 27/28/31 unsupported (context-dependent stops). Documented conventions (algorithm doc §5.4): minLength in aa, reverse-strand ORFs in reverse-complement coordinates, Biopython frame labels, stop-inclusive End. Accepted divergence: a 1-codon open ORF whose START is the last complete codon is reported when minLength ≤ 1 (getorf branch-order artefact omits it).

- TRANS-PROT-001: nucleotide `X` is rejected by Translate (Biopython treats it as N). Kept deliberately: NC-IUB 1984 defines only `N` as any-base; proposal for LIMITATIONS.md.
