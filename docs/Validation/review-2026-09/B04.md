### F1 — SEQ-COMPLEX-COMPRESS-001: Lempel–Ziv complexity computed LZ78 phrases, not LZ76
- **Defect:** `CalculateLempelZivComplexity` used the Naereen "set of seen phrases" parse (Ziv–Lempel 1978 incremental parsing), documented as LZ76. Repro: `1001111011000010` → 8 (LZ76 = 6: 1/0/01/1110/1100/0010); `0`×16 → 5 (=2); `1010…`×16 → 7 (=3); `ACGT`×4 → 9 / 1.125 normalized (=5 / 0.625). TestSpec even asserted the wrong 8/2.0. `EstimateCompressionRatio` and MCP tools `compression_ratio`, `complexity_compression_ratio` inherited the error.
- **Sources opened:** antropy 0.2.2 `entropy.py` (`_lz_complexity`, `lziv_complexity` doctests) from PyPI wheel; NeuroKit2 `complexity_lempelziv.py` (raw.githubusercontent); Naereen `lempel_ziv_complexity` 0.2.2 wheel (the LZ78 parse); WebSearch snippets of Lempel & Ziv 1976 example `0001101001000101` (c=6), Estévez-Rams et al. arXiv:1311.0546 (`010011101101100`, C=6), Wikipedia LZ complexity (`1001111011000010`, c=6).
- **Reference cross-check:** brute-force exhaustive-history definition = antropy on 20 000 random strings (0 mismatches); antropy doctests reproduced (6/1.5; `HELLO WORLD!`×4 → 11 / 0.38596001132145313; A..Z → 26 / 1.0); 6 DNA strings + 20 kb DNA (c=2756, norm 0.984423382950957) match antropy to 1e-12. Lead re-checked 6/2/3/5 with an independent Kaspar–Schuster port.
- **Fix:** LZ76 factorization from the Longest-Previous-Factor array (Crochemore & Ilie 2008; prefix-doubling suffix array + Kasai LCP), O(n log² n) — identical values to the Kaspar–Schuster scan (a direct port took 45 s on the 200 kb fuzz case; now ~1 s). Normalization (Zhang 2009, c/(n/log_b n), base ≥ 2) unchanged. n=1 convention (returns 1) documented.
- **Tests:** `SequenceComplexity_EstimateCompressionRatio_Tests.cs` re-sourced M1–M9/C1/C2 + LZ1976, Estévez-Rams, antropy text (2), DNA (6), 20 kb cases; `ComplexityFuzzTests.cs` reference replaced by brute-force definition, homopolymer c=min(n,2); `Seqeron.Mcp.Analysis.Tests/CompressionRatioTests.cs` → 1.5 / 0.625. TestSpec, Evidence (correction header), `docs/algorithms/Complexity/Lempel_Ziv_Complexity.md`, MCP tool docs corrected.

### F2 — SEQ-COMPLEX-DUST-001: DUST score divisor ℓ instead of ℓ−1
- **Defect:** `CalculateDustScore` = Σ c(c−1)/2 / ℓ (ℓ = L−2 triplets), taken from the longdust README; the 2026-06 "fix" from `words-1` to `words` was a regression. Repro: `AAAAAAA` → 2.0 (correct 10/4 = 2.5).
- **Sources opened:** lh3/sdust `sdust.c` (`find_perfect`: `new_l = kdq_size(w) - i - 1`, test `new_r*10 > T*new_l`), NCBI dustmasker `symdust.cpp/.hpp` (`thresholds_[i] = i*level`), longdust README (raw GitHub); Morgulis et al. 2006 (J Comput Biol 13:1028) via WebSearch snippet showing (ℓ−1). OUP/arXiv blocked.
- **Reference cross-check:** compiled sdust (`-w 64 -t 20`, mask iff score > 2.0): flanked A×7 → 2.5 masked [19,26); flanked A×6 → 2.0 not masked; (AC)×6 → 20/9 masked [12,24); ACACACACACA → 2.0 not masked; A×7 → masked [0,7). Only ℓ−1 reproduces all five.
- **Fix:** divide by (words−1); < 2 words → 0. Word counting now via canonical `KmerAnalyzer.CountKmers`.
- **Tests:** `SequenceComplexity_CalculateDustScore_Tests.cs` re-locked (AAAAAA 2.0, ACGTACGT 0.4, ACACACAC 1.2, A10 4.0, AATAATAA 0.6, A18 8.0, AAA 0) + 4 boundary cases; fuzz/combinatorial/unit tests and MCP `DustScoreTests.cs` updated; TestSpec, Evidence (2026-09-28 revision), `docs/algorithms/Complexity/DUST_Score.md`, MCP tool docs corrected (sequence `complexity_dust_score` examples 0.45→0.4, 4.5→5.0).

### F3 — SEQ-COMPLEX-DUST-001: `MaskLowComplexity` was a fixed-window heuristic, now real SDUST
- **Defect:** masked whole 64-bp windows whose score exceeded threshold; sequences shorter than the window were never masked. Rule 2 (real algorithm implementable).
- **Source:** lh3/sdust `sdust_core` / `shift_window` / `find_perfect` / `save_masked_regions` (raw GitHub); Morgulis 2006.
- **Reference cross-check:** 3 000 random repeat-rich sequences (3–400 bp, windows 3–100, thresholds 1.0–3.0) → 0 mismatches vs compiled sdust; one 1 Mb sequence identical.
- **Fix:** line-by-line port with `x*10 > T*y` → `x > threshold*y` (public API unchanged). Now validates `windowSize ≥ 3` and finite non-negative threshold (`ArgumentOutOfRangeException`).
- **Tests:** 15 exact sdust-output rows, reverse-symmetry test, parameter-validation test.

### F4 — SEQ-COMPLEX-WINDOW-001: `FindLowComplexityRegions` region end off by one; overlapping low-entropy windows split

Repro: ATGC×20 + A×64 + ATGC×20, w=20, t=0.5 → 79..146 (correct 79..145; window at 126 = 0.286 bits, at 127 = 0.569); `CAAAAACAAAAACAAACAAA`, w=8, t=0.6 → (1,12)+(7,16) (correct single (1,15), min 0.5435644431995964).
- **Sources opened:** BBTools BBDuk `BBDuk.java` `maskLowEntropy` (lines 4134–4148) and `EntropyTracker.java` `passes()` (raw.githubusercontent.com/BioInfoTools/BBMap): each failing window (entropy < cutoff) sets its bit range; regions = maximal masked runs. No prior source/TestSpec existed for this method (uncovered public method, added to this unit).
- **Reference cross-check:** Python `scipy.stats.entropy(base=2)` per window + boolean mask: (79,145,67,0.0); ATGCATGC+A×64+ATGCATGC w=32 → (6,74,69,0.0) (code gave 6..75); (1,15,15,0.5436); A×10+(ACGT)×3+C×10 w=8 t=1 → (0,11,12,0.0),(21,31,11,0.0). `CalculateWindowedComplexity` (Shannon + LC per full window) was already correct: 50 bp mixed w=16 s=7 matches scipy/set-counting to 1e-12.
- **Fix:** union-of-flagged-windows loop (extend when `i ≤ regionEnd + 1`, end = last flagged window end), strict `<`, canonical `CalculateShannonEntropyCore`; XML doc rewritten.
- **Tests:** two unit tests that had locked the buggy ends (79..146; 6..75/70) corrected; new merge / two-region / eager-validation tests; windowed reference test; MCP `FindLowComplexityRegionsTests` (145, 67) and `WindowedComplexityTests` (LC 0.7931034482758621 / 0.20689655172413793). TestSpec R1–R6, Evidence, `docs/algorithms/Complexity/Windowed_Complexity.md` §5.2a, MCP docs (`find_low_complexity_regions` 146→145, source line anchors) corrected.

### F5 — REP-STR-001: the same microsatellite locus was reported once per rotation (phase)
- **Defect:** per unit length every rotation of a run extending into the partial trailing copy was reported (suppression only if fully contained in an earlier hit). Repro: `ATATATA` (p=2, k=3) → AT×3@0 **and** TA×3@1; `AAAAAACGCGCGCAGCAGCAG` → 2 di + 2 tri hits (correct 1 + 1). The TestSpec had locked the duplicates (AC×5@2 + CA×5@3, GCA×5@2 + CAG×5@3, AGAT×4@1 + GATA×4@2).
- **Sources opened:** MISA `misa.pl` v1.0 (Thiel et al. 2003, TAG 106:411; raw GitHub mirror) — leftmost match per motif size; pytrf 1.5.0 `src/str.c` (Krait engine, Du et al. 2018 Bioinformatics 34:681; PyPI sdist) — run seeded at its start, `repeat = rl/j` complete copies; maximal repetition definition (Kolpakov & Kucherov 1999, cited, not opened). Richard 2008 / Tóth 2000 / Benson 1999 define STRs but not the reporting rule.
- **Reference cross-check:** 3132 cases (66 crafted + 3000 seeded random, incl. N): independent Python brute-force maximal-primitive-run reference 3132/3132 identical; MISA rule 3099/3132, pytrf 2752/3132 — every difference is one of two documented convention differences (same-period runs overlapping by < p bases: 17; greedy consumption of non-primitive/N regions: MISA 16, pytrf 363 — pytrf has no primitivity check), 0 unexplained.
- **Fix:** single scan core: per p visit run starts only (`i==0 || S[i−1]≠S[i−1+p]`), extend while `S[e]=S[e−p]`, report ⌊(e−i)/p⌋ copies if the unit is primitive, jump to e−p+1 — O(n) per p (old O(n·hits) containment scan removed). Convention documented: per unit length, each maximal primitive run at its left end with complete copies; different unit lengths may overlap (MISA per-size style); no compound-SSR merging.
- **Tests:** M02/M03/M04 duplicate-rotation expectations removed; `RepeatFinderMutationTests.GetTandemRepeatSummary_MixedTypes_CountsPresentTypesNonZero` di/tri 2→1 (A×6@0, CG×3@6, GCA×3@11 — brute force = MISA = pytrf); new `FindMicrosatellites_MaximalRuns_EachLocusReportedOnce` (6 reference cases); property `Microsatellite_EachResult_IsMaximalRun`.

### F10 — REP-INV-001: `FindInvertedRepeats` reported every sub-stem; N/IUPAC paired; lazy validation
- **Defect:** `GAATTCAAAAGAATTC` (arm ≥ 4, loop 3–10) → 6 hits (EMBOSS `palindrome`: 1, (0,10,6)); `GGGGGAAACCCCC` → 3 hits (arm-5 stem + two arm-4 sub-stems; EMBOSS (0,8,5)); one stem of arm A gave O(A²) hits. N paired with N and IUPAC codes with each other (R/Y); U paired one way only (`UUUU…AAAA` yes, `AAAA…UUUU` no). String overload validated on enumeration; `maxLoopLength < minLoopLength` silently empty; unbounded arm loop (O(n²·L·A)).
- **Sources opened:** EMBOSS `palindrome.c`, `einverted.c` (raw GitHub kimrutherford/EMBOSS), EMBOSS palindrome documentation; EMBOSS 6.6.0 binaries (apt) run directly. `palindrome` extends each stem inward from its outer pair and with default `-overlap Y` drops stems nested in both arms (`palindrome_AInB`); einverted's match table scores a/c/g/t only (N never pairs). Wikipedia / Pearson 1996 / Bissler 1998 define an IR only (arm + spacer ≥ 0 + reverse complement).
- **Reference cross-check (0 mismatches each):** independent Python brute force vs `palindrome` binary 800 random cases; C# vs `palindrome` binary (min loop 0) 1000; C# vs Python 3000 (1138 non-empty; min loop 0–6, N, U, lowercase). (EMBOSS clamps `-minpallen` to len/2 — avoided.)
- **Fix:** private core rewritten: innermost pairs in the loop window that cannot move inward (or would go below `minLoopLength`) are extended outward; a stem is dropped only if a longer stem shifted by m (1 ≤ m ≤ loop − minLoop) covers it with the same arm starts or ends (exact test). Pairing via canonical `SequenceExtensions.GetComplementBase`, ACGT only. Eager validation (`minArm ≥ 2`, `minLoop ≥ 0`, `maxLoop ≥ minLoop`), `maxLoop` capped by n, output sorted by (LeftArmStart, RightArmStart). Timing: 200 kb default 0.2 s; `int.MaxValue` loop on (AT)×5000 0.5 s; worst case (5 kb, arm 2, unlimited loop) 13 s for 566 k results (output-bound).
- **Tests:** unit M2 6 → 1 (EMBOSS-locked), new sub-stem/slipped-pairing/inward-stop/multi-stem EMBOSS example/N-IUPAC-U/huge-maxLoop/eager-validation tests; differential oracle rewritten ("all exact stems, keep non-nested"); combinatorial `TTAA`-loop case now the true maximal stem arm 8 loop 0 (EMBOSS (12,20,8)); metamorphic MR21 "narrow ⊆ wide" (false once a relaxed min loop lets a stem extend inward) replaced by "every narrow stem is covered in both arms by a wide stem"; properties maximal/non-nested + reverse-complement mirror symmetry; MCP maximal-stem and `maxLoop < minLoop` tests. Evidence (new), TestSpec, algorithm doc, MCP docs (new example `GGGGGAAACCCCC` → (0,8,5)) updated.

### F11 — REP-DIRECT-001: `FindDirectRepeats` reported every nested sub-window instead of maximal repeated pairs; self-pairs; N matched N
- **Defect:** `AAAAAATTTTAAAAAA` (4–6, spacing ≥ 1) → 14 hits (maximal pairs: (0,10,6) (0,11,5) (0,12,4) (1,10,5) (2,10,4)); snapshot `ACGTACGTTTTTTTTTACGTACGT` (min 4) → 20 hits instead of 4 ((0,16,8) (0,20,4) (3,15,5) (7,12,4)); `ACGTACGTACGT`, 4, 4, −4 → 15 hits incl. self-pairs (0,0),(1,1)…; `N`×20 → NNNNN repeats. Cost O(r·n·(m+k)) (Substring + suffix-tree lookup per window + HashSet).
- **Sources opened:** mummer4 `src/tigr/repeat-match.cc` (raw GitHub; "identifies maximal exact repeat regions"; `-E` loop skips `Data[i-1]==Data[j-1]`, `List_Matches` skips left/right-extendable; `-f` forward only); mummer4 `src/essaMEM/mummer.cpp` (`-n` acgt-only matching); WebSearch snippets of Abouelhoda et al. 2004 / Gusfield 1997 maximal-pair definition and REPuter (Kurtz & Schleiermacher 1999). - **Reference cross-check (0 mismatches each):** `repeat-match` compiled from mummer4 sources; independent Python brute force vs `repeat-match -f` 3 000 random cases; C# vs brute force 8 000 cases / 373 960 pairs (N/IUPAC/`-`/lowercase, random min/max/spacing to ±int limits); C# vs `repeat-match -f` 2 000 cases (1–200 bp), 200 cases ≤ 5 kb (12.8 M pairs), 50 kb / 200 kb / 1 Mb genomes (1 Mb: C# 1.1 s, repeat-match 0.9 s).
- **Fix:** ACGT → 0..3, any other symbol a unique code (never matches); suffix array + Kasai LCP + bottom-up lcp-interval traversal with per-left-character lists (Gusfield §7.12.3 / Abouelhoda 2004), O(n log² n + z); output sorted by (FirstPosition, SecondPosition); eager validation on both overloads. `maxLength` = filter on maximal repeats (longer maximal repeats not truncated into windows; `int.MaxValue` disables); `minSpacing` any int on Spacing = j−i−L (negative admits overlapping copies; `int.MinValue` = full `repeat-match -f`); always i<j. Case-insensitive, null/empty string → empty unchanged.
- **Tests:** unit M11/M12/S1/C1 re-locked to repeat-match values; new S1b periodic copies, C3 full repeat-match lists (4 cases), negative minSpacing/no self-pairs, ACGT-only, sorted/unique/maximal on 3 kb; differential oracle = brute-force maximal pairs (5 fixed + 300 random); combinatorial embedded copy flanked by mismatches (maximal at 7 bp); fuzz homopolymer exact list (38 unfiltered pairs) + random maximality; property INV-6 (left/right-maximal + unique); snapshot re-verified (4 pairs = repeat-match); MCP periodic-copies test ((0,14,ACGTA,5,9)). ### F12 — REP-PALIN-001: non-ACGT windows reported as palindromes (string overload / MCP `find_palindromes`)
- **Defect:** window compared with `DnaSequence.GetReverseComplementString` (IUPAC complement N→N, S→S, W→W, R↔Y; other symbols passed through). Repro: `NNNNNN` → 4 hits; `ANNT`, `SSSS`, `RYRY`, `A--T`, `1111` → 1 hit each. An ambiguity code denotes a set of bases (`SS` may be CC), so equal symbols do not establish a palindrome. `DnaSequence` overload unaffected (ACGT-validated input).
- **Sources opened:** Rosalind REVP statement (WebSearch snippets + docstring of the zonghui0228 solution, raw GitHub: input "a DNA string", output "every reverse palindrome … length between 4 and 12 … any order"); EMBOSS `palindrome.c` (`alln` guard rejects all-N stems); einverted a/c/g/t scoring (REP-INV-001 Evidence). Consistent with the batch ACGT-only convention (REP-STR/INV/DIRECT).
- **Reference cross-check (0 mismatches each):** Biopython 1.88 `Seq(w).reverse_complement() == w` over every even ACGT-only window vs C#: 6 000 random cases (ACGT, AT, GC, ACGTN, mixed case, ACGTNRYSWU-, ACGTS; 2 563 non-empty, 18 378 palindromes); 20 kb ACGT (4–40) and 5 kb AT-only (4–100); zonghui0228 REVP solution vs reference 2 000 cases; REVP sample reproduced exactly (`4 6, 5 4, 6 6, 7 4, 17 4, 18 4, 20 6, 21 4`, 1-based).
- **Fix:** pairing via the shared private `IsWatsonCrickPair` (ACGT + canonical `SequenceExtensions.GetComplementBase`, as REP-INV-001); capped centre expansion per inter-base gap, window (i, 2h) reported iff radius[i+h] ≥ h — O(n·maxLength), no per-window allocation (Release: 1 Mb 4–12 646 → 72 ms; 100 kb 4–200 3 609 → 37 ms). Output order (position, length) (REVP sample order; REVP allows any). Shared eager `ValidatePalindromeParameters`; string overload returns empty for null/empty.
- **Tests:** R1 `NonAcgtWindows_NeverReported` (9 cases incl. U, lowercase); R2 `GAATTCNNNNGAATTC` → (0,GAATTC),(1,AATT),(10,GAATTC),(11,AATT); R6 ordering; Rosalind test asserts exact REVP order; differential oracle rewritten (REVP order, ACGT-only) + 400 random cases incl. ### F13 — REP-PALIN-001: `maxLength` near `int.MaxValue` overflowed the length counter

### F20 — dedup sweep: `CalculateLinguisticComplexity(string)` exceeded 1 with more than 4 symbols (B03 R23)
