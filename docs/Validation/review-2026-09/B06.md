## Confirmed fixes
### F1 — KMER-FIND-001: FindClumps rescanned the whole window count map on every slide (efficiency; output unchanged)
- Defect: after each 1-bp slide the whole window dictionary was scanned for counts ≥ t → O(n·(L−k+1)); E. coli (4,639,675 bp, k=9, L=500, t=3) ≈ 5.7 s.
- Source: Compeau & Pevzner, *Bioinformatics Algorithms* ch.1 BetterClumpFinding (only the k-mer entering the window can increase its count, so only it needs testing) — recalled from the textbook, not re-opened; definition/sample from Rosalind BA1E statement (quoted verbatim in jmoggridge/bioinfo-notebooks, raw.githubusercontent).
- Reference cross-check: E. coli k=9 L=500 t=3 → 1904 distinct 9-mers (textbook answer; yeojingi/finding-hidden-messages-in-dna README and Compbio-Grader `check_ecoli_clumps_count.py` both expect 1904); set identical to an independent Python implementation; 3000 random cases vs Python brute force (incl. L<k, L>|seq|, t=1, k>L) 0 mismatches. BA1E sample → CGACA GAAGA AATGT; BA1B sample → CATG GCAT.
- Fix: incremental check of the entering k-mer; first window counted via canonical `CountKmers`; results streamed. O(n·k); E. coli ≈ 0.75 s, same 1904-set.
- Tests (+7, KmerAnalyzer_Find_Tests.cs): BA1E statement TGCA (25,3)-clump example (L=25 and L=22 → {TGCA}, L=21 → ∅ — locks the "occurrence must lie fully in window" rule), lower-case, clump only in last window, overlapping occurrences (AAAAA → {AAA}), t=1 → all distinct k-mers, M3 tightened to exactly {AA}.

### F2 — KMER-ASYNC-001: usage error (k ≤ 0) stored in the task instead of thrown from the call
- Defect: `CountKmersAsync("GTAGAGCTGT", 0, preCanceledToken)` returned a Canceled task, so the usage error was lost.
- Source (opened as the dotnet/docs Markdown sources on raw.githubusercontent.com, since learn.microsoft.com is blocked): TAP overview `task-based-asynchronous-pattern-tap.md` ("throw … directly from the asynchronous method call only in response to a usage error"); `implementing-the-task-based-asynchronous-pattern.md` (validate arguments synchronously, the hybrid approach).
- Fix: a new private `ValidateKmerLength` runs before `Task.Run`, and the synchronous overload uses the same helper. Null or empty input still returns empty for any k. This changes behaviour: a k ≤ 0 error now surfaces at the call site, not when the task is awaited.
- Tests: k ≤ 0 throws from the call (ParamName "k"); the usage error takes precedence over a pre-canceled token; empty input with k ≤ 0 returns empty.

### F3 — KMER-ASYNC-001: early-return paths skipped the final progress report
- Defect: the null/empty input and k > L paths completed without the final 1.0 progress report promised by the documented contract (algorithm doc §3.1).
- Source: only the unit's own documented contract; TAP does not require a final report. This is a contract-consistency fix, not a sourced numeric one.
- Fix: these paths now report 1.0 exactly once. This also applies to the synchronous `CountKmers` progress overload, whose tests stay green.
- Tests:
  - Trivial completion reports exactly [1.0].
  - 2500 windows report exactly [0, 0.4, 0.8, 1.0].
  - Pre-canceled token: the task is Canceled, the exception carries the caller's token, and no progress is reported.
  - Cancel mid-run: the task is Canceled with the same token, and progress is exactly [0.0].

### F4 — KMER-GENERATE-001: GenerateAllKmers held O(k²) memory (the docs promise O(k))
- Defect: the recursive `GenerateKmersRecursive` kept every prefix string alive. `GenerateAllKmers(200000, "A").First()` used more than 10 GB and never finished; k = 20000 used about 400 MB.
- Source: the Python `itertools.product` "odometer" order, where the rightmost element advances first. The wording comes from the existing Evidence file, not re-opened. Rosalind LEXF statement and sample come from archived copies (mtarbit/Rosalind-Problems `e015-lexf.py`, cedricusureau/Rosalind via raw.githubusercontent).
- Reference cross-check: output is byte-identical to Python `itertools.product` for ACGT k=1..5, TAGC k=4, 20-letter protein k=3, AB k=10, AAC k=3, acgT k=3 and A k=7. The LEXF sample (T A G C, n=2) gives TT TA TG TC AT AA AG AC GT GA GG GC CT CA CG CC.
- Fix: `EnumerateCartesianProduct` walks a single k-character buffer like a counter. Memory is O(k), each k-mer costs O(k), and output order is unchanged. Input checks still run at the call, before enumeration.
- Tests added:
  - The Rosalind TAGC sample.
  - Unsorted "GTCA" k=3, checked pair by pair against the LEXF order rule.
  - Repeated letters: "AAC" k=2 against the `itertools.product` output.
  - "A" with k = 100000, which must finish.
  - Input checks throw without starting enumeration.

### F5 — KMER-POSITIONS-001: FindKmerPositions compared every window in full (worst case Θ((L−k+1)·k); output unchanged)
- Defect: every one of the L−k+1 windows was compared with the k-mer via `SequenceEqual`. `FindKmerPositions(A^1,000,000, A^99,999·C)` took 5.35 s in Release. The checklist promises O(n).
- Source: Knuth, Morris & Pratt 1977, *SIAM J. Comput.* 6:323–350, and CLRS §32.4 KMP-MATCHER / COMPUTE-PREFIX-FUNCTION: an O(m) prefix function plus one O(n) pass, continuing from π after a full match so that overlapping occurrences are kept. Both were recalled from the textbooks, not re-opened. The failure-array reference code opened was TheAlgorithms/Python `strings/knuth_morris_pratt.py` (raw.githubusercontent).
- Reference cross-check: 5000 random cases (alphabets AC, ACGT, ACGTN, mixed case and A; L ≤ 60, k ≤ 8; 35,249 positions) against Python `re.finditer("(?=P)")` gave 0 mismatches. Fixed values agree with Biopython 1.88 `nt_search` and the Rosalind samples (see unit summary).
- Fix: a private `ComputeKmpPrefixFunction` and a single KMP scan. The method is still lazy, returns ascending positions, folds case and returns empty for null, empty or k > L. Timings: the adversarial case above now takes 26 ms; A^10⁶ vs A^10⁵ gives 900,001 hits in 31 ms; random 10 Mbp is unchanged at about 60–70 ms.
- Tests (+11, KmerAnalyzer_FindKmerPositions_Tests.cs): SUBS samples (1-based 2 4 10; legacy 3 7 11 → 0-based 2 6 10), 4 nt_search/regex rows, 3 bordered-pattern rows (KMP fallback), lower-case sequence, and an adversarial homopolymer case (A^2e6, k = 2e5, < 5 s; naive needs about 4e11 comparisons).

- Source: mean multiplicity = Total/Distinct (Jellyfish `stats` Total and Distinct definitions, `stats_main_cmdline.yaggo`, opened); no source prescribes rounding (the Evidence file recorded it as an ASSUMPTION).
- Reference: Python `sum(c)/len(c)` over `collections.Counter` gives 1.2857142857142858, 1.1666666666666667, 1.2857142857142858 (BA1B sample k=4).
- Fix: exact `(double)total / distinct`. Behaviour change (≤ 0.005) for callers that relied on the rounded value; MCP docs updated.
- Tests: M2/M4/S2 now lock the exact ratios (1e-15); Differential `AnalyzeKmers_MatchesManualStats` exact; heavy-tier `KmerProperties.AnalyzeKmers_StatsAreConsistent` and `KmerStatsFuzzTests` INV-04 tightened from 0.0051 to 1e-12 (edited, run with `~Kmer`, green).

### F7 — KMER-STATS-001: "UniqueKmers" meant Distinct; Jellyfish's Unique (count 1) and the -L/-U filters were missing
- Defect: the result named `UniqueKmers` reports the distinct count, which is Jellyfish "Distinct", whereas Jellyfish "Unique" = number of k-mers with count 1 (5 for ATCGATCAC k=3, BioInfoLogics also says unique = 5). The singleton count was not reported, and the reference tool's lower/upper count filters were not available.
- Source: Jellyfish `sub_commands/stats_main.cc` `compute_stats` (`if(val < low || val > high) continue; uniq += val == 1; total += val; max = max(max,val); ++distinct;`) and `stats_main_cmdline.yaggo` (field descriptions, `-L` default 0, `-U` default 2^64), both opened via raw.githubusercontent.com.
- Reference cross-check: a Python replica of `compute_stats` over `Counter` + scipy 1.17.1 `entropy(base=2)`, 10 rows (algorithm doc §7.2), e.g. GTAGAGCTGT k=2 → Unique 5, Distinct 7, Total 9, Max 2; `-L 2 -U 2` → 0, 2, 4, 2, entropy 1.0; BA1B sample k=4 → 17, 21, 27, 3, entropy 4.254525464966174; `-L 2` → 0, 4, 10, 3, 1.970950594454669. C# equals all rows (counts exact, mean 1e-15, entropy 1e-12).
- Fix (backward compatible): `KmerStatistics` keeps its positional members; it gains `DistinctKmers` (= `UniqueKmers`) and `SingletonKmers` (init property, Jellyfish Unique). There is a new overload `AnalyzeKmers(sequence, k, lowerCount, upperCount = int.MaxValue)` that applies the same rules as `compute_stats`. Retained k-mers feed min, mean and entropy. If nothing is retained, the result is all zeros. Negative bounds throw. The two-argument overload calls it with the defaults (0, ∞). MCP: `AnalyzeKmersResult` and `KmerAnalyzeResult` gain the additive init properties `DistinctKmers` and `SingletonKmers`. `analyze_kmers` takes optional `lowerCount`/`upperCount` parameters. Tool docs, mcp.json and READMEs are updated.
- Tests: +14 Genomics (10 Jellyfish rows, SingletonKmers = |FindUniqueKmers|, the no-filter overload equals the two-argument call, empty-filter all-zero cases, negative bounds), +1 MCP Analysis (fields + filters + validation), +1 MCP Sequence (BioInfoLogics fields).

### F8 — KMER-STATS-001: the sequence was counted twice and the entropy loop was duplicated (efficiency + rule 3)
- Defect: `AnalyzeKmers` called `CountKmers`, then `CalculateKmerEntropy`, which ran `GetKmerFrequencies` → `CountKmers` again, so the O(L·k) count ran twice. It also called `ToList`, `Sum`, `Max`, `Min` and `Average` as separate passes. `CalculateKmerEntropy` carried its own −Σ f·log₂ f loop, a copy of the canonical Shannon computation.
- Source: campaign rule 3. The canonical Shannon is `StatisticsHelper.ShannonIndex` (nats; equals scipy `entropy`). B04's `SequenceComplexity.CalculateKmerEntropy` is the canonical k-mer entropy: ShannonIndex ÷ ln 2 over `KmerAnalyzer.CountKmers`.
- Fix: there is now one `CountKmers` pass plus a single loop over the table. Entropy is a private `ShannonEntropyBits` (ShannonIndex ÷ ln 2, the same operation and order as SequenceComplexity). `KmerAnalyzer.CalculateKmerEntropy` delegates to `SequenceComplexity.CalculateKmerEntropy(string,int)` and keeps its own contract: null/empty input returns 0 for any k, and k ≤ 0 throws only for non-empty input, with ParamName "k".
- Numeric effect: the values are bit-identical to `SequenceComplexity.CalculateKmerEntropy`, checked by a test over 300 random sequences. Against the old `Math.Log2` loop the results differ by at most 4.6e-14 bits: in a Python simulation of 20,000 random tables, 78% differed in the last bits. All existing tolerance-based entropy tests stay green.

### F9 — KMER-UNIQUE-001: no upper-count filter (Jellyfish `dump -U`, KMC `-cx`), unspecified output order, range filter re-implemented per method
- Defect: (a) the reference tools filter k-mers by an inclusive count range — `jellyfish dump` `-L/-U` and KMC `-ci/-cx` — but only the lower bound existed, so "k-mers occurring exactly 2 times" (`dump -L 2 -U 2`) could not be expressed. (b) Ties in `FindKmersWithMinCount` and all of `FindUniqueKmers` came out in `Dictionary` enumeration order, which .NET does not specify (ATGATG k=3: TGA before GAT). (c) Three methods (FindUniqueKmers `== 1`, FindKmersWithMinCount `>= min`, AnalyzeKmers `< L || > U`) each wrote their own count predicate.
- Source (opened via raw.githubusercontent.com): Jellyfish `sub_commands/dump_main.cc` (`if(it.val() < lower_count || it.val() > upper_count) continue;`, defaults 0 / uint64 max) and `dump_main_cmdline.yaggo` (`-L` "Don't output k-mer with count < lower-count", `-U` "... > upper-count"); `stats_main.cc` (`uniq += val == 1`); KMC `kmc_CLI/kmc.cpp` (`-ci<value> - exclude k-mers occurring less than <value> times`, `-cx<value> - exclude k-mers occurring more of than <value> times`). Jellyfish dump emits hash order, so no source fixes an order; the API now documents its own.
- Reference cross-check: Python replica of `dump` over `collections.Counter`, sorted by (−count, k-mer). BA1B sample k=4: `-L1 -U1` → 17 k-mers (= Jellyfish stats Unique 17 from F7); `-L2` → CATG:3 GCAT:3 ATGA:2 TGCA:2; `-L2 -U2` → ATGA:2 TGCA:2; `-L3 -U3` → CATG:3 GCAT:3. GTAGAGCTGT k=2 unique → CT GA GC TA TG, `-L2` → AG:2 GT:2. ATCGATCAC k=3 unique → CAC CGA GAT TCA TCG. AAAACGTAAA k=2 `-L2` → AA:5, `-L2 -U2` → none. C# equals every row.
- Fix (backward compatible): new overload `FindKmersWithMinCount(sequence, k, minCount, maxCount)` (negative maxCount throws at the call, ParamName "maxCount"; maxCount < minCount → empty; minCount ≤ 1 keeps "no lower bound" as before). The 3-argument overload delegates with `int.MaxValue`; `FindUniqueKmers` = range [1, 1]. Order: count descending, ties ascending ordinal (`dump -c | sort -k2,2nr -k1,1`); FindUniqueKmers ascending ordinal. Private `SelectByCountRange` is the single range predicate, also used by `AnalyzeKmers(seq,k,lowerCount,upperCount)`. MCP `kmers_with_min_count` gains optional `maxCount` (default unbounded; negative → ArgumentException); `unique_kmers` description says Jellyfish Unique ≠ distinct. Behaviour change: only the order of tied/unique k-mers (was unspecified); sets and counts unchanged.
- Tests (+25 Genomics, +1 MCP): 9 dump-replica range rows, 4 unique rows (ordered), ordinal tie-break, 3-arg = 4-arg, minCount 0/−5 → 21 distinct, U < L empty, negative maxCount, null/empty for any k, 6 rows agreeing with `AnalyzeKmers(L,U)` (Distinct/Total/SingletonKmers); MCP `maxCount` + order + validation; MCP `unique_kmers` test now checks the lexicographic order.

### F10 — KMER-COUNT-001 (audit round 1, WP1): Jellyfish ACGT-only window rule and canonical (`-C`) counting were missing
- Gap: the reference counter has two behaviours the library could not express. (a) Jellyfish skips every window that contains a non-ACGT base, so `ACGTNACGT` k=4 → ACGT:2, while the library returned 5 keys, including CGTN/GTNA/TNAC/NACG. (b) Jellyfish `count -C` keys each k-mer by min(w, RC(w)), so ATGATG k=3 → ATC:1 ATG:2 TCA:1. Both were listed as "Intentionally simplified / Not implemented" in four algorithm docs, and Jellyfish `stats`/`histo` are normally run on `-C` counts.
- Source (opened via raw.githubusercontent.com, gmarcais/Jellyfish master): `include/jellyfish/mer_iterator.hpp` (`if(code >= 0) {…} else filled_ = 0;`; `operator*` → `!canonical_ || m_ < rcm_ ? m_ : rcm_`), `include/jellyfish/mer_dna.hpp` (`codes[256]`: only A/C/G/T in either case are ≥ 0; `get_canonical`), `sub_commands/count_main_cmdline.yaggo` (`-C` "Count both strand, canonical representation"); Marçais & Kingsford 2011, Bioinformatics 27:764.
- Reference: the **real Jellyfish 2.3.1 binary** (apt `jellyfish 2.3.1-3build1`), run as `count -m k -s 10000 -t 1 [-C]` + `dump -c`/`stats`/`histo` on 10 inputs × {plain, -C}. Inputs: lower case, N, R, U, homopolymer, BA1B, the KMER-BOTH reference, and the Rosalind KMER sample at k=4/5. An independent Python replica of `mer_iterator` equals Jellyfish on all 20 rows. Examples: Rosalind k=4 plain 91/209/412/8 and `-C` 23/130/412/10 (Unique/Distinct/Total/Max), with `-C` histo 1:23 2:34 3:27 4:25 5:7 6:5 7:4 9:3 10:2. `acgtNNacgtacgRtTTGCAnA` k=3 `-C` → AAA:1 ACG:5 CAA:1 GCA:2 GTA:2. scipy entropies of the `-C` tables: 6.779144227048732 / 4.1343361131944505 / 2.0403733936884962. C# equals every row. PyPI alternatives (sourmash hashes, khmer unmaintained) were not needed once the real binary was available.
- Fix (additive, backward compatible):
  - New `readonly record struct KmerCountingOptions(bool Canonical = false, bool AcgtOnly = false)`. `Canonical` implies ACGT-only (`SkipsNonAcgt`), because the canonical form is defined only over ACGT. `Default` = literal.
  - New `CountKmers(string, int, KmerCountingOptions, CancellationToken = default, IProgress<double>? = null)` on the single counting loop `CountKmersCore`. ACGT-only is O(1) per window via the last non-ACGT index. Canonical folds the forward table once per distinct k-mer with the canonical B01 `DnaSequence.GetReverseComplementString`, keyed by the ordinal minimum, which equals Jellyfish's A<C<G<T 2-bit order.
  - New `DistinctKmers(string, int[, KmerCountingOptions])`, returning a caller-owned ordinal `HashSet<string>` (DUP_MAP §18 helper).
  - New `GetKmerSpectrum(string, int, KmerCountingOptions)` (= `count -C` + `histo`) and `AnalyzeKmers(string, int, KmerCountingOptions, lowerCount = 0, upperCount = ∞)` (= `count -C` + `stats -L/-U`).
  - The existing overloads delegate with default options and are bit-for-bit unchanged.
  - `FindUniqueKmers`/`FindKmersWithMinCount` deliberately got no option overloads, to keep the API small: they are a count filter over the option-aware `CountKmers` (documented).
  - MCP `count_kmers` gains optional `canonical=false`, `acgtOnly=false`, delegating to the new overload.
- Tests: +36 Genomics (`KmerAnalyzer_CountingOptions_Tests`: 8 `-C` dump tables, 4 ACGT-only tables, 9 stats+histo rows, 3 mean/entropy rows, `-C -L 2`, invariants: default = literal, canonical ⊂ ACGT-only, ordinal-min keys, RC-input invariance, contracts and cancellation/progress), +1 MCP Analysis (`CountKmers_JellyfishModes_DelegateToOptionAwareCounter`).

## Duplication removed
- KMER-COUNT-001: `CountKmers(string,int)` duplicated the counting loop of `CountKmers(string,int,CancellationToken,…)` → now delegates (single loop; behaviour identical).
- KMER-FIND-001: `FindClumps` hand-written first-window counting loop → canonical `CountKmers`.
- KMER-STATS-001: `CalculateKmerEntropy`'s own −Σ f log₂ f loop → canonical `SequenceComplexity.CalculateKmerEntropy` (→ `StatisticsHelper.ShannonIndex` ÷ ln 2); `AnalyzeKmers` no longer re-counts the sequence for entropy (one `CountKmers`, entropy via `StatisticsHelper.ShannonIndex`). Fulfils the B04 cross-batch request.
- KMER-UNIQUE-001: three hand-written count predicates (FindUniqueKmers `== 1`, FindKmersWithMinCount `>= min`, AnalyzeKmers `< L || > U`) → one private `SelectByCountRange` (Jellyfish dump/stats predicate); `FindUniqueKmers` → `FindKmersWithMinCount(seq,k,1,1)`, 3-arg overload → 4-arg; all over one `CountKmers` table.

## Simplifications kept (with reason) / LIMITATIONS proposals
- (KMER-COUNT-001 / KMER-BOTH-001) Literal counting (non-ACGT symbols kept as keys) stays the **default** of the option-less overloads, for backward compatibility and non-DNA text. The Jellyfish ACGT-only rule and canonical `-C` counting are now options (F10, audit round 1). The earlier "non-ACGT kept literal" item is resolved.
- (KMER-UNIQUE-001, audit round 1) No option-aware `FindUniqueKmers`/`FindKmersWithMinCount` overloads, to avoid exploding the API: `jellyfish count -C` + `dump -L/-U` is a count filter over `CountKmers(seq, k, KmerCountingOptions)`, documented in Unique_And_MinCount_Kmers.md §5.3. They can be added later if a caller needs them. No LIMITATIONS entry is needed.
- (KMER-GENERATE-001) k = 0 throws. `itertools.product` would return one empty string (|Σ|^0 = 1), but Rosalind LEXF defines n as a positive integer, so this is documented as the convention. The output has |Σ|^k items, so callers should stream it rather than materialise it. No LIMITATIONS entry is needed.
