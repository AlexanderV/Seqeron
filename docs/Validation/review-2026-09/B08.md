## Confirmed fixes

### F1 — CRISPR-PAM-001: reverse-strand `PamSite.TargetStart` was not a genome coordinate
- **Defect:** for reverse-strand hits `TargetStart` indexed into the reverse-complement string while `Position` was a forward-strand coordinate, so the two fields lived in different frames. Repro: `FindPamSites("CCAACGTACGTACGTACGTACGTACGTACGT", SpCas9)` → `TargetStart` 8; CRISPOR `flankSeqIter` gives guideStart 3. It leaked into `DesignGuideRnas` (`GuideRnaCandidate.Position = pamSite.TargetStart`), so reverse-strand guides carried a meaningless position.
- **Source opened:** CRISPOR `crispor.py` (master, raw.githubusercontent.com): `findPat` L951, `patMatch` L2347, `findPams` L1033 (incl. doctests), `flankSeqIter` L1582, `findAllPams` L4627, `setupPamInfo` L458, Cpf1 staggered-cut text L1565.
- **Cross-check:** CRISPOR's `revComp/patMatch/findPat/findPams/flankSeqIter` copied verbatim into Python and driven directly against a C# dumper: 4 designed + 60 pseudo-random sequences (seed 20260928, len 10–200) × 7 systems = 136 reference sites. Before: all forward sites matched, all reverse sites mismatched; after: 0 mismatches.
- **Fix:** in `FindPamSitesCore` reverse branch, `TargetStart = Position + pamLen` (PAM-after) / `Position - guideLength` (PAM-before) — CRISPOR's minus-strand `guideStart`. Forward-strand output byte-identical.
- **Tests:** `FindPamSites_SpCas9_ReverseStrand_MatchesCrisporConvention`, `FindPamSites_Cas12a_ReverseStrand_MatchesCrisporConvention`, `FindPamSites_AllSites_AreConsistentInForwardCoordinates` (4 parametric), updated `FindPamSites_SpCas9_SearchesReverseStrand`.

### F2 — CRISPR-PAM-001: reverse-strand `PamSequence` was reported reverse-complemented
- **Defect:** reverse SpCas9 hits reported `CCA` and Cas12a `TAAA` — strings that do not satisfy the system's own PAM motif — while `TargetSequence` was correctly protospacer-oriented (violating documented INV-01).
- **Source / cross-check:** same CRISPOR run above (`pamSeq`).
- **Fix:** report the matched window as read on the protospacer strand (`TGG`, `TTTA`).
- **Tests:** same reference-row tests as F1 (they assert pamStart/guideStart/pamSeq/guideSeq jointly).


### F3 — CRISPR-GUIDE-001: cut site was wrong on the reverse strand and not exposed
- **Defect:** `IsInRegion` computed the cleavage position from `pamSite.Position` with the forward-strand formula for *both* strands (`Position - 3` for Cas9, `Position + pamLen + 18` for Cas12a), so on the minus strand it pointed 3 bp on the wrong side of the PAM and region filtering admitted/rejected the wrong guides. The convention was also private, so callers could not reproduce the region test.
- **Source opened:** CRISPOR `crispor.py` (master, raw.githubusercontent.com): the expected cleavage position "-3bp 5' of the PAM site", the `startFt = start - 3` / `ftSeq + "---"` cut-marker construction, and the Cpf1 staggered-cut text ("after the 18th base on the non-targeted strand which has the TTTV PAM motif", Zetsche et al. 2015, Cell 163:759, Fig. 3).
- **Fix:** new public `CrisprDesigner.GetCutSite(PamSite)` returning a forward-strand 0-based coordinate for both strands (Cas9: `Position - 3` / `Position + pamLen + 2`; Cas12a: `Position + pamLen + 18` / `Position - 19`); `IsInRegion` delegates to it and no longer takes a system.
- **Tests:** cut-site tests for both strands and both PAM topologies; region-boundary tests for `DesignGuideRnas`.

### F4 — CRISPR-GUIDE-001: the site's CRISPR system was silently replaced by SpCas9
- **Defect:** `EvaluateGuideRna(PamSite, …)` mapped `system.Name` back to a `CrisprSystemType` with a `_ => CrisprSystemType.SpCas9` fallback, so SpCas9-NAG, AsCas12a, LbCas12a and CasX guides were re-evaluated as SpCas9 — wrong seed-region orientation (PAM-before systems take the 5' end) and wrong reported system/guide length.
- **Fix:** the pipeline passes `pamSite.System` straight into the shared `EvaluateGuideRnaCore`; no name-based remap exists any more.
- **Tests:** per-system evaluation tests asserting the reported system and the seed window orientation for a PAM-before system.

### F5 — CRISPR-GUIDE-001: designed guides carried no published on-target score, and output was unranked
- **Defect:** `DesignGuideRnas` returned candidates in PAM-scan order scored only by the library's composition heuristic, although the validated Doench 2016 Rule Set 2 / Azimuth model was already implemented (`CalculateOnTargetRuleSet2`) — it was simply never applied to designed guides, because nothing extracted the model's 30-nt context. The XML doc also claimed a "ranked list".
- **Source opened:** CRISPOR `crispor.py` / `crisporEffScores.py`: the 30-mer context window (`trimSeqs(seqs, -24, 6)` around the PAM start = 4 nt 5' flank + 20-nt protospacer + 3-nt PAM + 3 nt 3' flank), the per-guide "Doench '16" efficiency column, and `mergeGuideInfo`'s `guideData.sort(reverse=True, …)` ranking.
- **Fix:** `TryGetRuleSet2Context` builds that window on the protospacer strand for 20-nt NGG systems (null when the system does not qualify, the flanks do not fit, or the window is not all A/C/G/T — the reference's "can't do Ns"); new `GuideRnaCandidate.Context30Mer` / `OnTargetScore`; new `GuideRnaRanking` (`Score` default, `OnTargetRuleSet2`) with a deterministic position/strand tie-break.
- **Tests:** context extraction on both strands (incl. flank-overrun and N cases), score plumbing, ranking order and tie-break determinism.

### F6 — CRISPR-GUIDE-001: self-complementarity used an unsourced ad-hoc metric only
- **Defect:** the only self-complementarity measure was a normalised complementary-pair fraction with an unsourced 0.3 threshold and an `L²` denominator; the published measure used by the reference tool (count of 4-bp stems, guide-internal or against the sgRNA scaffold) was absent, as was any way to filter on it.
- **Source opened:** CHOPCHOP `chopchop.py` (Carl-labhub/chopchop-clone mirror of the Bitbucket repo — the Bitbucket raw endpoint and the valenlab GitHub paths 404): `STEM_LEN = 4`, `selfComp` / `calcSelfComplementarity` (`rvs[0:(L-i)]` with `L = len − STEM_LEN − 1`, `gccontent(stem) >= 0.5`, PAM excluded), `args.backbone = [revcomp(el) for el in split(",")]` with CLI help "same strand as guide", and `-filterSelfCompMax` default `-1` (no filter). Labun et al., Nucleic Acids Res 44:W272 (2016) / 47:W171 (2019).
- **Cross-check:** the reference algorithm was re-implemented verbatim in Python and driven against the C# method: guide `ACGGACTAGCCTACGTACGT` → 0 internal stems, 8 against the standard backbone `AGGCTAGTCCGT`, 1 when the backbone is passed already reverse-complemented (the palindromic-in-context window `CTAG` matches in both orientations); guide `ACGTACGTACGTACGTACGT` → 10. All identical in C#.
- **Fix:** new public `CountSelfComplementaryStems(guide, stemLength = 4, backboneRegions = null)` + `StandardSgRnaBackboneRegion`; reported on every candidate as `SelfComplementaryStems`; `GuideRnaParameters.MaxSelfComplementaryStems` (null = the reference's own no-filter default) filters in `DesignGuideRnas` and raises an issue in `EvaluateGuideRna` without deducting; the legacy `SelfComplementarityScore` is kept for backward compatibility and documented as the older metric.
- **Tests:** reference-locked counts above, inclusive-limit filtering, backbone orientation, argument validation.

### F7 — CRISPR-GUIDE-001: Graf 2019 inefficiency motifs were not reported
- **Source opened:** CRISPOR `crisporEffScores.py` `getGrafType` (TT-motif: ends `TTC`/`TTT`, or last 4 bases are only T/C with ≥2 T, or contain `TT` with ≥3 T or ≥1 C; GCC-motif: ends `[AGT]GCC` or `GCCT`), applied by the reference to NGG systems only; Graf et al. 2019, Cell Reports 26:1098–1103.
- **Fix:** public `GetGrafMotif` + `GuideRnaCandidate.GrafMotif`, reported as an issue for NGG systems with no score deduction (CRISPOR reports it as a warning).
- **Tests:** each published motif branch and the NGG-only restriction.

### F8 — CRISPR-GUIDE-001: `AvoidPolyT` / `CheckSelfComplementarity` were ignored
- **Defect:** both `GuideRnaParameters` flags existed and were documented, but `EvaluateGuideRna` applied the TTTT (−20) and self-complementarity (−30 × score) penalties unconditionally, so switching them off changed nothing.
- **Fix:** both penalties are now gated on their flag.
- **Tests:** penalty on/off for each flag, asserting score and issue list.

## Duplication removed
- CRISPR-GUIDE-001: `AzimuthRuleSet2.MeltingTemp`/`NearestNeighbor` (inlined DNA_NN3 table + salt/concentration arithmetic) deleted in favour of the canonical `ThermoConstants.CalculateNearestNeighborTm` — verified **bit-identical** over 821,840 comparisons (200,000 random 30-mers × the four azimuth windows [0,30) [19,24) [11,19) [6,11), plus every 2..7-mer exhaustively; 0 bitwise differences), both reproducing Biopython 1.88 `Tm_NN(seq, nn_table=DNA_NN3)` exactly (e.g. `Tm_NN("ACGTACGTACGTACGTACGTACGTAGGACG") = 62.55983015288416`). **Closes the B07 cross-batch request.**
- CRISPR-GUIDE-001: the fixed-window GC loops in `CrisprDesigner.CalculateOnTargetDoench2014` and `AzimuthRuleSet2.FeaturizeNoPos`, and the new stem-GC test, now call the canonical `SequenceExtensions.CountGcAndValidNucleotides` over the fixed window. **Closes the B01 cross-batch request** (the windows are validated ACGT-only, so the canonical primitive is exact here).
- CRISPR-GUIDE-001: `HasCommonRestrictionSite`'s five hand-written recognition literals now resolve by name from the canonical `RestrictionAnalyzer.Enzymes` table at type-init.
- CRISPR-PAM-001: none needed — `FindPamSitesCore` already calls canonical `DnaSequence.GetReverseComplementString` and `IupacHelper.MatchesIupac`; MCP `find_pam_sites` / `crispr_system_info` delegate. Noted for the sweep: `CrisprDesigner.CountMismatches` re-implements Hamming distance.
