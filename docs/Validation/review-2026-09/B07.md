## Confirmed fixes

### F1 — PRIMER-TM-001: `CalculateMeltingTemperatureWithSalt` double-counted the salt term
- Defect: returned basic Tm + 16.6·log10(Na/1000) although Wallace / 64.9+41(GC−16.4)/N already assume 50 mM Na+. Repro: `ACGTACGTACGTACGTACGT` @50 mM → 30.2 °C; `ACGT` @50 mM → −9.6 °C.
- Source: OligoCalc (Kibbe 2007) "Salt Adjusted" Tm (formula + 50 mM assumption via WebSearch snippets; site blocked); Biopython 1.88 `MeltingTemp.py` source.
- Reference: OligoCalc 39-mer `GAGCAGGATCCCTATAGAGTGACAAAAGGATCTTGGTCC` @50 mM basic 67.6 / salt 78 → ours now 67.633 / 77.852 (OligoCalc rounds). 20-mer @50 mM now 58.4 (was 30.2).
- Fix: <14 nt Wallace + 16.6·log10([Na+]/0.05); ≥14 nt 100.5 + 41·GC/N − 820/N + 16.6·log10([Na+]); Na+ ≤0/NaN/∞ throws. New additive helper `ThermoConstants.CalculateOligoCalcSaltAdjustedTm`; XML docs of `CalculateSaltAdjustedTm` (Biopython Tm_GC valueset 7) and `CalculateSaltCorrection` (Biopython method 1) corrected.
- Tests: `PrimerDesigner_MeltingTemperature_Tests` (`_OligoCalcWorkedExample_39mer`, `_Long_OligoCalcSaltAdjusted`, `_Short_WallaceRelativeCorrection`, `_Short_At50mM_EqualsBasicWallace`, `_IncreasesBy16_6PerDecade`, `_InvalidSodium_Throws`); ThermoConstants tests vs Biopython (−21.59709792802209, 50.40290207197791); properties, combinatorial oracle, snapshot, MCP `PrimerMeltingTemperatureSaltTests` (12.0/33.6/58.4) updated to sourced values.

### F2 — PRIMER-TM-001: `CalculatePrimer3Penalty` lacked Primer3's default thermodynamic mode
- Defect: Primer3 default `PRIMER_THERMODYNAMIC_OLIGO_ALIGNMENT=1` uses `compl_any_th`/`compl_end_th`/`hairpin_th` with `temp_cutoff`=5 and ignores `WT_SELF_ANY`/`WT_SELF_END`; code always used the legacy alignment-score terms and had no end-stability term.
- Source: primer3 `libprimer3.cc` `p_obj_fn`, `pr_set_default_global_args_1/_2` (raw.githubusercontent.com).
- Reference: primer3-py 2.3.1 `PRIMER_*_PENALTY` matched to 1e-9 for 30 designed primers + 8 `check_primers` runs, both modes, both temp_cutoff branches.
- Fix: appended optional record-struct members (`SelfAnyTh`, `SelfEndTh`, `HairpinTh`, `EndStability`, `ThermodynamicOligoAlignment`; inputs `HairpinTh`, `EndStability`), constant `Primer3TempCutoff`; `DefaultPrimer3Weights` now thermodynamic mode (default penalty value unchanged).
- Tests: `_ThermodynamicMode_MatchesPrimer3Py` (5), `_AlignmentMode_MatchesPrimer3Py` (4), `DefaultPrimer3Weights_ThermodynamicModeWithZeroStructureWeights`; M7/M8/M10/S3 set alignment mode explicitly (per source).

### F3 — PRIMER-DESIGN-001: Primer3 Tm window applied to the wrong Tm scale
- Defect: `EvaluatePrimer` compared OligoCalc/Marmur–Doty Tm against Primer3's 57/60/63 °C limits (≈5–6 °C lower scale). Repro: AGCTAGCTAGCTAGCTAGCT 51.78 (ours) vs 58.10 (`primer3.calc_tm`) → wrongly rejected.
- Source: primer3 `src/oligotm.c` (`oligotm`, `seqtm`, `long_seq_tm`, `divalent_to_monovalent`, SantaLucia_1998 tables).
- Reference: new `PrimerDesigner.CalculateMeltingTemperaturePrimer3(primer, dnaNM=50, monoMM=50, divMM=1.5, dntpMM=0.6)` identical to `primer3.calc_tm` (max |Δ| = 0 over 3000 random 2–45-mers).
- Fix: `EvaluatePrimer` uses it; non-ACGT base → invalid (Primer3 default max Ns = 0).
- Tests: `CalculateMeltingTemperaturePrimer3_DefaultConditions_MatchesPrimer3CalcTm` (7), `_NonDefaultConditions_MatchesPrimer3CalcTm`, `_InvalidInput_NaNOrThrows`, `EvaluatePrimer_NonAcgtBase_TmNotComputableAndInvalid`.

### F4 — PRIMER-DESIGN-001: greedy pair selection returned no pair when a valid one exists
- Defect: best forward and best reverse chosen independently by an unsourced `Score`. Repro: template `TAATTGGTGTAATAATCTAGGGGTGCTTTTTTTTTGCAGTCCGGTGTTGCGCTCGTGCTCCAT`, target [26,34): greedy picks primers 5.58 °C apart → invalid; Primer3 returns left [3,23] + right [62,19], pair penalty 8.925688.
- Source: primer3 `libprimer3.cc` `choose_pair_or_triple`, `primer_rec_comp`, `compare_primer_pair`, `p_obj_fn`.
- Reference: primer3-py 2.3.1 `design_primers` — 553/553 identical left/right primers and pair penalties (3 seeds × 300 random templates, all cases where Primer3's best pair passes our extra filters).
- Fix: exhaustive Primer3-style pair search (same pruning) minimising summed per-primer `CalculatePrimer3Penalty`; ΔTm ≤ 5 °C unrounded; Primer3 tie ordering; `PrimerCandidate.Penalty` appended (optional); failure message names the violated constraint.
- Tests: `EvaluatePrimer_Penalty_IsPrimer3PerPrimerPenalty`, `DesignPrimers_RandomTemplate_MatchesPrimer3DesignPrimers`, `DesignPrimers_IndividuallyBestPrimersTmIncompatible_SearchesPairs`, `DesignPrimers_NoPairWithinTmLimit_ReturnsInvalidWithTmMessage`, differential `DesignPrimers_MatchesBruteForcePrimer3PairSearch`; property/combinatorial/mutation/MCP anchors moved to primer3 values (standard template → forward 76/20, reverse Position 154, product 98).

### F6 — PRIMER-STRUCT-001: `HasPrimerDimer` tested parallel, not antiparallel, 3′ complementarity
- Defect: compared suffix(primer1) with prefix(revcomp(primer2)) by *complementarity*; since the second window is already the reverse complement, this detects parallel pairing. Repro: `HasPrimerDimer("AAAAAAAA","AAAAAAAA")` → true (A·A cannot pair); `("TTCAGTCAGTCAGTGGCC","ACTGACTGACTGAGGCC")` (GGCC/GGCC 3′ ends) only flagged by coincidence; the unit test "non-complementary" fixture `AAAACCCCCCCC`/`GGGGGGGGTTTT` is in fact a perfect reverse-complement pair, and `ACGTACGT` self (8/8 complementary) was asserted not to reach 8.
- Source: Primer3 `libprimer3.cc` `characterize_pair` (alignment mode: `compl_end = max(align(s1,s2,end), align(s2_rev,s1_rev,end))`), `align`, `oligo_compl`; `dpal.c` `set_dpal_args`, `_dpal_long_nopath_maxgap1_global_end`, `_dpal_generic` (raw.githubusercontent.com primer3-org/primer3 main).
- Reference: dpal.c compiled locally — 3000/3000 random pairs identical; primer3-py 2.3.1 `design_primers` check_primers with `PRIMER_THERMODYNAMIC_OLIGO_ALIGNMENT=0`: 300/300 `PRIMER_PAIR_0_COMPL_END`, 600/600 `PRIMER_*_SELF_END` identical. A₈/A₈ → 0 (calc_heterodimer: no structure), GGCC ends → 4, AACCGGTTAACCATCGATCG + AACCGGTTAACGATCGAT → 8.
- Fix: new public `CalculatePrimerDimerEndComplementarity` (Primer3 compl_end) and `CalculatePrimerSelfEndComplementarity` (self_end); `HasPrimerDimer` = score ≥ minComplementarity (default 4 ≡ Primer3 `PRIMER_PAIR_MAX_COMPL_END` 3.00 exceeded).
- Tests: `HasPrimerDimer_IdenticalPolyA_IsNotADimer`, `_SelfComplementaryGgccEnds_Detected`, `CalculatePrimerDimerEndComplementarity_MatchesPrimer3ComplEnd` (4), `CalculatePrimerSelfEndComplementarity_MatchesPrimer3SelfEnd` (4); corrected `_NonComplementary3Ends_ReturnsFalse`, `_Complementary3Ends_ReturnsTrue`, `_CustomMinComplementarity`, `PrimerDesignerTests.HasPrimerDimer_SmokeTest`, `PrimerDesign_Tests.HasPrimerDimer_ComplementaryPrimers_ReturnsTrue` (primer2 now ends with revcomp of primer1's end; old pair scores 1 in Primer3), combinatorial `PrimerStruct_Dimer*` (pairs re-engineered, scores 2/4/6 verified with dpal.c).

### F7 — PRIMER-STRUCT-001: `Calculate3PrimeStability` diverged from Primer3 `end_oligodg` for short primers and N
- Defect: returned 0 below 5 nt and skipped unknown dinucleotides / treated N as A·T terminal. Primer3 scores the whole primer when shorter than 5 (incl. symmetry −0.43) and has N parameters. Repro: `ACGT` → 0 (Primer3 2.56 → ΔG −2.56); `GC` → 0 (Primer3 −0.15); `ACGTN` → −2.71 (Primer3 3.62).
- Source: primer3 `oligotm.c` `oligodg`, `end_oligodg`, `symmetry`, `SantaLucia_1998_dG`; `libprimer3.cc` (END_STABILITY = `end_oligodg(seq,5,santalucia)`).
- Reference: oligotm.c compiled locally: 2000/2000 random 1–12-mers (ACGTN) identical (ours = −end_oligodg); primer3-py check_primers 600/600 `PRIMER_*_END_STABILITY`. ACGT 5-mer values unchanged (0.98+0.98 = 1.96, 1.03−0.98 = 0.05).
- Fix: Primer3 table + initiation 1.96 / 0.05 per terminal A·T / 0.43 symmetric; window = last 5 or whole; non-ACGTN in window → NaN (Primer3 OLIGOTM_ERROR); MCP `three_prime_stability` rejects NaN with ArgumentException.
- Tests: `Calculate3PrimeStability_MatchesPrimer3EndOligoDg` (8), `_InvalidCharacterInWindow_ReturnsNaN`; MCP `ThreePrimeStabilityTests` (ACGT −2.56, U rejected).

### F9 — PRIMER-STRUCT-001: heuristic hairpin/dimer screen stood in for Primer3's implementable thermodynamic screen
- Defect: `EvaluatePrimer`/`DesignPrimers` (which claim Primer3 semantics) used `HasHairpinPotential` (any 4-bp stem + 3-nt loop) and the F6-broken `HasPrimerDimer`, while Primer3's default (`PRIMER_THERMODYNAMIC_OLIGO_ALIGNMENT=1`) rejects on ntthal Tm > 47 °C of self-any/self-end/hairpin and pair compl-any/compl-end. ntthal END1/END2 and the Mg²⁺/dNTP salt term were not available. Repro: random template (seed 2026, target 70..90): Primer3 rejects right primer GATCGAGGACTGCCTTGGTA (hairpin 47.19 °C) and returns AGGAACGGATCGAGGACTGC (pair penalty 2.425289002682007); ~30 % of random templates differed (B07 PRIMER-DESIGN-001 note).
- Source: `libprimer3.cc` `create_thal_arg_holder`, `characterize_pair`, `oligo_compl_thermod`, `oligo_hairpin`, `align_thermod` (Tm < 0 → 0), defaults `max_self_any_th`/`max_self_end_th`/`max_hairpin_th`/`pair_compl_any_th`/`pair_compl_end_th` = 47; primer3-py vendored `thal.c` (type 2/3 END1/END2 terminal-pair selection, `saltCorrectS`).
- Reference: primer3-py 2.3.1 `calc_end_stability`/`calc_heterodimer`/`calc_hairpin` at mv 50/dv 1.5/dntp 0.6/dna 50 and `design_primers` check_primers `*_TH` values: identical to 1e-9 wherever the ntthal engines are exact (END1/END2/dv code paths add no new discrepancy; residual engine discrepancies ≈ 1.6 % of random dimers (ΔG offset ≈ 122 cal/mol, low-Tm structures) and ≈ 5 % of random hairpins (up to ≈ 10 °C) are pre-existing → PRIMER-DIMER-001 / PRIMER-HAIRPIN-001, repro e.g. calc_hairpin GGGAGACAGTAGTCGCCCAT 59.27 vs ours 67.16; CCGGGCTGAAACATCAGACT 44.88 vs 52.00). `DesignPrimers` vs `design_primers` (thermodynamic default, our per-primer limits): 574/600 random templates identical; all 26 differences trace to those engine values.
- Fix: `NtthalDimer.Run(..., AlignmentType Any/End1/End2, dv, dntp)` (+ thal.c (1,1) no-structure fallback), `NtthalHairpin.Run(..., dv, dntp)`, shared `NtthalDimer.SaltCorrectS`; public `PrimerDesigner.NtthalAlignmentMode`, overloads `CalculateDimerThermodynamicsNtthal(a,b,mode,mv,dv,dntp,c)`, `CalculateHairpinThermodynamicsNtthal(s,mv,dv,dntp)`, `CalculatePrimer3OligoStructure`, `CalculatePrimer3PairComplementarity`, `Primer3MaxStructureTm` = 47; `PrimerParameters.StructureScreen` (default `Primer3Thermodynamic`, `Heuristic` keeps the old screens) and `MaxStructureTm` (default 47); `PrimerCandidate.SelfAnyTh/SelfEndTh/HairpinTh` (appended optional); `DesignPrimers` runs the structure screen lazily per primer exactly where `characterize_pair` does, then the pair check (compl_any first, stopping at the first value over the limit); both results are cached per sequence / sequence pair (an all-A 250-mer has ~800 candidates per side but 8 distinct sequences — uncached the pair loop ran for hours; now < 1 s).

## Duplication removed

- PRIMER-TM-001: two AT/GC counting loops in `PrimerDesigner.cs` merged into one private `CountAtGc` helper.
- PRIMER-DESIGN-001: `new DnaSequence(seq).ReverseComplement().Sequence` → canonical `DnaSequence.GetReverseComplementString`; >36 nt Tm reuses `ThermoConstants.CalculateSaltAdjustedTm`; ranking reuses `CalculatePrimer3Penalty`. (Primer3 SantaLucia-1998 integer NN table deliberately separate from `NnUnifiedParams`: AA/TT values differ and integer units are needed for bit-exact ties.)

- PRIMER-STRUCT-001: MCP `primer_dimer` delegates to `PrimerDesigner` (F10); private `Complement(string)` now wraps the canonical `SequenceExtensions.TryGetComplement` and `GcFraction` was replaced by the canonical `CalculateGcFractionFast` (identical on the validated uppercase ACGT duplexes; canonical is also case-insensitive); `IsSelfComplementary` / `AreComplementary` / `IsComplementary` confirmed correct and kept (strict Watson–Crick; the canonical reverse complement maps N→N, which would change the hairpin screen); `ReverseComplementPrimer3` kept local because Primer3's `p3_reverse_complement` maps every non-ACGT character to N (needed for exact dpal scores); ntthal dv/dntp salt term shared via `NtthalDimer.SaltCorrectS`.

## Simplifications kept (with reason) / LIMITATIONS proposals

- PRIMER-TM-001 basic Tm: closed-form Wallace / Marmur–Doty (OligoCalc "Basic") is the published formula as designed; accurate Tm is `CalculateMeltingTemperatureNN`. Not a simplification.
- LIMITATIONS proposal: "PRIMER-TM-001 penalty: bound/failure_rate/pos_penalty/seq_quality/repeat_sim/template_mispriming terms not modelled (need annealing model, mispriming library, base qualities, target geometry); all zero under Primer3 defaults." (declared in XML doc)
- PRIMER-DESIGN-001: no product-size range (±200 bp flanks bound product); dinucleotide-repeat limit has no Primer3 equivalent; 3′-ΔG < −9 gate cannot fire (min SantaLucia 5-mer CGCGC = −6.86), consistent with Primer3 default end-stability limit 100.
- LIMITATIONS proposal: "PRIMER-DESIGN-001: DesignPrimers reproduces Primer3's Tm, per-primer penalty and pair search, but has no product-size range or mispriming library." (hairpin/dimer screen: implemented as Primer3's thermodynamic screen in PRIMER-STRUCT-001, F9)
- PRIMER-STRUCT-001: `HasHairpinPotential` (sequence-only stem-loop screen) and `FindLongestDinucleotideRepeat` have no Primer3 counterpart; they are kept as documented screens (the former only for `PrimerStructureScreen.Heuristic` and the `hairpin_potential` MCP tool) — the thermodynamic hairpin is the default.
