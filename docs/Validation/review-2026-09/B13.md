### F17 — MIRNA-CONTEXT-001: SA estimate is not RNAplfold; zero and 3'-end rules differed
- (a) SA used one 80-nt McCaskill window with no span limit. TargetScan uses RNAplfold `-L 40 -W 80`, which averages every 80-nt window holding the region and limits pairs to a 40-nt span. log10 p (library vs RNAplfold): 8mer 41 −2.43 vs −1.98; 6mer 85 −6.04 vs −4.19; 7mer-m8 122 −1.42 vs −2.34; 7mer-A1 176 −3.02 vs −2.56; 8mer 268 −0.67 vs −3.19; 8mer 31 (181-nt UTR) −0.86 vs −2.01. SA contributions are off by up to the whole coefficient (8mer 268: −0.115 vs −0.036). ViennaRNA cross-check: averaging the windows with span 40 reproduces RNAplfold to ≤ 0.07 log10; without the span limit it is off by up to 1.4. The canonical partition function has no span limit, so this is blocked (request below). Fix: opt-in `ContextPlusPlusInputs.PlfoldUnpairedProbability` (the `_lunp` row `utrStart+7`, col l=14), which makes SA exactly TargetScan's (parity test). The estimate is documented as an approximation in the XML docs and the algorithm doc.
- (b) perl `if (! $plfold) { return 0; }`: a zero probability now gives 0 and SA is listed as omitted (before: `log10 → 0`, then scaled to a non-zero value).
- (c) `grep -A7 … | tail -1`: a site within 7 nt of the 3' end reads the last row. The library used to omit SA there. Tests: `SaContribution_ZeroPlfold_ContributesZeroAndIsOmitted`, `SaContribution_SiteNear3PrimeEnd_ReadsLastRowLikeGrepTail`. Existing SA window-boundary tests unchanged.
