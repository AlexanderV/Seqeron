## Confirmed fixes
### F1 — MIRNA-SEED-001: FindSimilarMiRnas matched seedless miRNAs
- Defect: mismatch count computed over min(seed lengths) → entry with empty seed (<8 nt) scored 0 mismatches; empty query matched all. Repro `FindSimilarMiRnas(let7a,[CreateMiRna("short","UGA")],0)` returned "short".
- Source: Bartel 2009 (seed = nt 2–8); fix uses CompareSeedRegions (Hamming + length difference), skips empty seeds. Tests: miR-21 vs miR-590-5p = 0 mm, vs let-7a = 5 mm (hand Hamming), thresholds 0/4/5.
### F2 — MIRNA-SEED-001: GroupBySeedFamily grouped all seedless miRNAs as family ""
- Contradicted CompareSeedRegions (empty seed ⇒ no family). Now excluded. Test: {let-7a,b,c}→GAGGUAG, {miR-21-5p, miR-590-5p}→AGCUUAU.
### F3 — MIRNA-SEED-001: seed family comparison was case- and T/U-sensitive
- `gaggtag` ≠ `GAGGUAG`. Source opened: TargetScan 7.0 `targetscan_70.pl` L229–232 (`s/T/U/gi; uc`) (raw.githubusercontent.com/nsoranzo/targetscan). Fix: private NormalizeSeed (upper, T→U) in comparison/grouping. Test: DNA lower-case let-7a vs RNA → 7 matches, same family, one group.
### F4 — MIRNA-SEED-001: GenerateSeedVariants duplicates / dead flag

### F5 — MIRNA-TARGET-001: FindTargetSites duplex window taken downstream of the seed match
- Defect: `CreateTargetSite` used `mrna[Start..Start+L-1]`, but the miRNA 3′ end pairs **upstream** of the seed match → wrong Alignment/FreeEnergy/Score/TargetSequence. Repro: let-7a vs `GGGGGCUACCUCAGGGGG` → window `CUACCUCAGGGGG`, seed shown unpaired.
- Sources opened: TargetScan `targetscan_70_context_scores.pl::extractSubseqForAlignment` (utrStart−16..utrEnd), `targetscan_70.pl` (classification unchanged, confirmed correct); Bartel 2009 Fig 1.
- Fix: window `mrna[max(0,p1−L+1)..p1]`, p1 = base opposite nt 1 (N-padding past end). Now `GGGGGCUACCUCA`, `||||||||:   :`, Score 0.97, ΔG −17.96. Tests REG-001..004; property/metamorphic oracles that locked the old window corrected.
### F6 — MIRNA-TARGET-001: AnalyzeTargetContext contradicted Grimson 2007
- Defect: +0.3 bonus for mid-UTR sites (paper: sites away from the centre are more effective), unweighted AU including the site, "near start" = 15 % of length instead of 15 nt.
- Sources: Grimson 2007 (WebSearch snippets); TargetScan `getLocalAU_contribution` + `$MIN_DIST_TO_CDS=15` (opened). Fix: TargetScan inverse-distance-weighted AU excluding site; NearStart = 1-based start < 15; ContextScore 0 if NearStart else 0.5·AU+0.5·EndProximity; out-of-range → zeros. Cross-check: weighted AU fixture = (H10−1)/H10 = 0.6585828478525945 (unweighted 0.9). Tests CTXA-001..007.
### F7 — MIRNA-TARGET-001: CalculateSiteAccessibility was a pair-count heuristic returning 0

ViennaRNA 2.x cross-check (d2 / Seqeron): 0.9770/0.9721, 0.9701/0.9630, 1.3e-4/3.2e-4 (old heuristic: 0,0,0). Tests ACC-001..007; MCP tests `AnalyzeTargetContextTests`, `SiteAccessibilityTests` updated to sourced values.
### F8 — MIRNA-PRECURSOR-001: pre-miRNA hairpin energy re-implemented a reduced Turner model
- Defect: `CalculateHairpinEnergy` (inline) = stacks + initiation + terminal mismatch + AU/GU on the outer/closing pair. It left out the NNDB special tri/tetra/hexaloops, the UU/GA and GG first-mismatch bonuses, the special GU closure, the all-C penalty and the GGUC special stack, and it copied `RnaSecondaryStructure`. The dot-bracket was also built inline. Repro: 57-nt hairpin `GCAUAGCUAGCUAGCUAGCUAGC`+`GAAAAAAAAAA`+`GCUAGCUAGCUAGCUAGCUAUGC` (23 bp, GA first mismatch) → −43.90 (GA bonus missing).
- Sources opened: NNDB Turner 2004 hairpin page `rna.urmc.rochester.edu/NNDB/rna_2004/rna_2004_hairpin_loops.html` (equation; triloops get no mismatch; special loops; worked example 5.3 puts the AU end penalty on the pair that closes the loop). NNDB parameter files `turner_2004_{loop,tetraloop,triloop,terminal_mismatch,watson_crick_stack}_dg.txt`.
- Reference: ViennaRNA 2.8.0 `eval_structure` on all 33 accepted windows of the fixtures: max |Δ| 0.24 kcal/mol. The hairpin-loop terms are identical (GA case 4.30, UUCG 3.70). The residual is Vienna's 0.1-kcal stacks and `TerminalAU = 0.50` (NNDB 0.45). Locked values: GA hairpin −44.80 (Vienna −44.70; old −43.90). UUCG-tetraloop 44-mer −37.66 (Vienna −37.60). ValidHairpin57 −48.48 (Vienna −48.40), WobbleHairpin57 −39.80 (Vienna −39.80), ShortHairpin47 −38.69 (Vienna −38.60). Each equals the NNDB hand sum and `CalculateMinimumFreeEnergy`.
- Fix: `AnalyzeHairpin` now calls `RnaSecondaryStructure.FindStemLoops(candidate, minStemLength: stem, minLoopSize: loop, maxLoopSize: loop).Single()`. With the loop fixed there is exactly one stem-loop, scored by `CalculateStemEnergy` + `CalculateHairpinLoopEnergy`. `TotalFreeEnergy` and `DotBracketNotation` come from the canonical renderer. Stems are counted with `RnaSecondaryStructure.CanPair`. Removed: `CalculateHairpinEnergy` and the unused `HairpinLoopInitEnergies`, `TerminalMismatchEnergies` and `TerminalAU_GU_Penalty` aliases.
- Tests: `FindPreMiRnaHairpins_GaFirstMismatch_BonusApplied`, `_SpecialTetraloop_UsesCanonicalHairpinLoopModel`, `_PerfectHairpin_StructureAndEnergyEqualCanonicalMfe` (3 cases); M10/M11 re-locked.
### F9 — MIRNA-PRECURSOR-001: stem truncated at an unsourced min(n/2 − 5, 35)
- Defect: every reported loop was ≥ 10 nt, so the documented 3–25 range was never fully covered. The structure and energy were also for a non-consecutive-stem structure. Repro: ValidHairpin57 was reported as 23 bp/11 nt, −43.50, although bases 23–24 pair with 32–33. The real consecutive stem is 27 bp/3 nt, −48.48, which is the ViennaRNA MFE structure (−48.40). Perfect stems > 35 bp were rejected as a "loop" > 25: LargeHairpin110 (50 bp/10 nt) was rejected.
- Source: NNDB (hairpin loops < 3 nt prohibited); Bartel 2004 (loop 3–25). Fix: the stem extends while the mirrored bases pair, up to maxStem = (n − 3)/2.
- Tests: M5/M8/M10/M11 re-locked; `_LongPerfectStem_NotTruncated`. The property generator (loops now 3–25, no 35 cap) and anchors `Anchor_TinyConstructedLoop_ReDecomposedWithinLoopBounds` (now exact 26/4) and `Anchor_WorkedExample_YieldsValidHairpin` (27/3) were corrected. They had locked the cap.
### F10 — MIRNA-PRECURSOR-001: hidden 55-nt floor and unvalidated lengths
- Defect: `AnalyzeHairpin` had `if (n < 55) return null`, so `minHairpinLength < 55` was ignored. Repro: `FindPreMiRnaHairpins(ShortHairpin47, 40)` → ∅, although it has a 22-bp stem and a 3-nt loop. `matureLength ≤ 0` or a negative `minHairpinLength` threw lazily from `Substring`.

- Tests: `_MinHairpinLengthBelow55_Honoured` (windows (0,46),(1,45),(2,44),(3,43)), `PreMiRnaScans_InvalidLengths_ThrowEagerly`. The combinatorial oracle `MiRnaPrecursor_*` encoded the hidden 55 floor; it now uses the caller's window.
### F11 — MIRNA-PAIR-001: AlignMiRnaToTarget.FreeEnergy was a stacking-only sum ("intentionally simplified, only sign validated")
- Defect: `CalculateDuplexEnergy` summed Turner stacks over consecutive pairs only: no intermolecular initiation, no AU/GU end penalties, no loop terms between helices, no dangling ends / terminal mismatches. Repro: `AlignMiRnaToTarget("AGCGCU","AGCGCU")` = −13.36 (NNDB worked example −7.94); `AAAA`/`UUUU` = −2.79 (NNDB +2.20, Vienna +2.40 — a 4-bp A·U duplex is not stable); let-7a vs site window `GGGGGCUACCUCA` −17.96 (Vienna −11.4).
- Sources opened (2026-11-25): NNDB Turner 2004 `rna_2004_watson_crick_helices.html` (equation incl. initiation 4.09, AU end 0.45, symmetry 0.43; worked examples −7.94 / −6.04), `rna_2004_dangling_ends.html` ("both strands extended ⇒ terminal mismatch, not the sum"; example −0.4/−0.2) + `turner_2004_dangle_dg.txt` (key orientation), `rna_2004_terminal_mismatches.html` (UA/GA −1.1), `rna_2004_exterior_loops.html`.
- Fix: new private `EvaluateDuplexEnergy(pairs)`: init 4.09 (+0.43 for a symmetric duplex of identical strands) + per helix canonical `RnaSecondaryStructure.CalculateStemEnergy` (stacks, GGUC special, AU/GU end — kept only on exterior ends) + `CalculateInternalLoopEnergy` / `CalculateBulgeLoopEnergy` between helices + exterior terminal mismatch (`GetTerminalMismatchEnergy`) or single dangle (`GetDanglingEndEnergy`) at both duplex ends; non-ACGU neighbours (N padding) ignored. Unused `StackingEnergies` alias removed.
- Reference: ViennaRNA 2.8.0 `fold_compound(m+'&'+t).eval_structure(s)` (d2) on 51 fixtures (11 hand + 40 generated): max |Δ| 0.31 kcal/mol without 2×2 internal loops (Vienna 0.1-kcal rounding, init 4.10, AU 0.50); up to 2.2 with 2×2 loops (canonical kernel lacks int22 — known RNA-STRUCT-001 residual, B12, already in QUEUE). - Tests: `_FullyPairedDuplex_FreeEnergyIsNndbSum` (−16.24), `_AllMismatchDuplex_FreeEnergyZero`, `_NndbSelfComplementaryExample_Minus7_94`, `_NndbNonSelfComplementaryExample_Minus6_04`, `_ThreePrimeDanglingEnd_NndbValue`, `_TerminalMismatch_NndbValue`, `_ShortAuDuplex_PositiveNndbEnergy`, `_FreeEnergy_MatchesViennaEval` (9 cases); snapshot gains FreeEnergy −35.79; MCP `AlignMirnaToTargetTests` locks +2.20 / −35.90. Heavy tier: `MiRnaFuzzTests.AlignMiRnaToTarget_PerfectMatch_AllWatsonCrickStabilisingDuplex` locked "AAAA/UUUU ΔG ≤ 0" — wrong per NNDB (+2.20); re-locked to 2.20 with the hand sum; the 7–22-bp perfect complements stay ≤ 0 (−9.25, −13.61, −35.90). ## Simplifications kept (with reason) / LIMITATIONS proposals
- MIRNA-TARGET-001 (proposal): "MiRnaAnalyzer.FindTargetSites.Score and AnalyzeTargetContext.ContextScore are heuristic rankings — site-type bases and term directions are sourced (Grimson 2007) but weights are not fitted; use ScoreTargetSiteContextPlusPlus (Agarwal 2015) for a calibrated score. The published model (MFE fold + Ambros ≥16 bp + Bartel loop + Zhang MFEI) is fully implemented as `FindPreMiRnaHairpinsByMfe`/`AssessHairpinByMfe`. Making it the default would change the record type (no mature/star). This is an API decision for the lead/auditor. Mature/Star are the 5′-arm window start and its blunt base-paired partner. Processing-accurate coordinates (Drosha +11, Dicer 22 nt, 2-nt 3′ overhang) exist in `PredictDroshaDicerCleavage` (MIRNA-CLEAVAGE-001), so this is documented as labels.
