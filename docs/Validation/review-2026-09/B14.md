## Confirmed fixes

### F1 — PROTMOTIF-FIND-001: hits wholly included in a previous hit were reported
- **Defect:** the lookahead scan reported every start position. For variable-length patterns this included hits that sit entirely inside the previous hit. Repro: `FindMotifByPattern("LLALLAL", "L.{2,3}L")` returned 0-4, 1-4 and 3-6. ScanProsite/`ps_scan` returns 1-5 and 4-7 (1-based), i.e. 0-4 and 3-6.
- **Source (opened):** the original PROSITE scanner `ps_scan.pl` (raw.githubusercontent.com/ebi-pf-team/interproscan/.../bin/prosite/ps_scan.pl: `scanPattern`, `prositeToRegexp`, options `-g`/`-v`/`-i`), plus a WebSearch snippet of the ps_scan README: "default is to be greedy and allow overlaps which are not completely included in another match".
- **Reference cross-check:** I ran `scanPattern` from `ps_scan.pl` in Perl on 350 seeded random proteins (50 containing X) against all 17 `CommonMotifs` patterns. Before the fix, C# gave 123 extra hits (122 NES1, 1 PS00028). After the fix, all 5593 hits match `ps_scan -x 0` exactly.
- **Fix:** a hit is kept only if its end is past the end of the last kept hit (`$stop > $prevstop`, as in `ps_scan`). The XML doc now states the greedy / overlaps / no-includes behaviour.
- **Tests:**
  - Added `FindMotifByPattern_IncludedMatch_IsSuppressed_AsScanProsite`, `FindCommonMotifs_Nes1_IncludedMatch_IsSuppressed_AsScanProsite` and `FindCommonMotifs_Nes1_PartialOverlapsKept_IncludedDropped`.
  - `FullWorkflow_AnalyzeProtein` count changed from 64 to 60 (the `ps_scan` value).
  - The `FindCommonMotifs` snapshot drops one included NES hit, 5-14. The whole snapshot was checked hit-for-hit against `ps_scan`.
- **Note for orchestrator:** the checklist lists methods `FindMotifs`, `FindAllKnownMotifs` and `ScanForPattern` for this unit. They do not exist; the real methods are `FindMotifByPattern` and `FindCommonMotifs`.
### F2–F5 — PROTMOTIF-PROSITE-001: PROSITE→regex converter did not match the reference ps_scan tokenizer
- **Sources (opened):**
  - `ps_scan.pl` `prositeToRegexp`/`scanPattern` (raw.githubusercontent.com/ebi-pf-team/interproscan), read and executed in Perl.
  - The ps_scan README via a GitHub mirror (raw.githubusercontent.com/anuragkh/succinctx/master/scanprosite/ps_scan/README).
  - WebSearch snippets of the ScanProsite manual (prosite.expasy.org is blocked).
- **F2 — Kleene star:** `ConvertPrositeToRegex("<{C}*>")` threw. ps_scan supports it: `<{C}*>` → `^([^C]*)$`, which hits 1-7 on MKVLAAG and nothing on MCKV; `A-x*-C` on AKKCAC gives 1-6. Fix: `*` after an element becomes regex `*`; a stray `*` still throws.
- **F3 — uppercase `X`:** `N-X-[ST]` became `NX[ST]`, treating X as a literal. ps_scan matches `x`/`X` as any residue (`/x/i → "."`). Fixed.
- **F4 — B/Z ambiguity codes:**
  - Defect: PS00001 on `BGTA` gave 0 hits, where ps_scan gives 1-4.
  - Other ps_scan values reproduced: `[DE](2)` on BZEQ → 1-2, 2-3; `B-x-Z` on NKEDGQ → 1-3, 4-6; `{B}-G` on DGNG → none; NXTA → hit; XATA → none.
  - Fix: the new overload `ConvertPrositeToRegex(p, matchAmbiguityCodes: true)` is used by `FindMotifByProsite`. The one-argument overload returns the same output as before for valid patterns, so the MCP `prosite_to_regex` output is unchanged.
  - Score and E-value still come from the plain translation, via a private `FindMotifByPatternCore`.
- **F5 — malformed patterns:** `(3)-A`, `A-x(2)(3)`, `[ST`, `A-[]-G`, `A-x(a)` and `[S-T]` produced broken regexes and silently found nothing. They now throw `FormatException`.
- **Reference cross-check:** 3388/3388 identical hits against ps_scan: 28 patterns × 70 sequences containing B, Z and X.
- **Tests:**
  - 8 ps_scan-locked tests added in `ProteinMotifFinder_PrositePattern_Tests.cs`.
  - In `ProteinPrositeFuzzTests.cs`, the old star-rejection tests are replaced and a backtracking-timeout test is added.
  - The PATTERN-001 TestSpec, Evidence and doc (INV-06/S3) are updated, since `*` is now valid.

## Simplifications kept (with reason) / LIMITATIONS proposals

- PROTMOTIF-FIND-001: `MotifMatch.Score`/`EValue` are information-content numbers under a uniform 20-residue background (Schneider & Stephens 1990). They are not ScanProsite statistics, because ScanProsite reports no such value. This is already declared "Simplified" in the algorithm doc.
  - Proposed LIMITATIONS text: "MotifMatch.Score/EValue are uniform-background IC heuristics, not ScanProsite statistics; for arbitrary .NET regex constructs the per-position allowed-count parse is approximate."
- PROTMOTIF-PROSITE-001: ps_scan's options `-g` (non-greedy), `-v` (no overlaps), `-i` (allow includes) and `-x` (max X count) are not exposed; only the defaults are reproduced. Element ranges such as `[RK](2,4)` are accepted, as ps_scan accepts them. Both are declared in the algorithm doc, so no LIMITATIONS entry is needed.
