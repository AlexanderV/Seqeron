# TEMPORARY hand-off package A2-19c-fastapair2 (for the user's Mac)

**Why.** The first run (`handoff/A2-19c-fastapair`, 180 sets) is integrated (B09 F346 - F349): the port of the alignment half of FASTA 3.4, `dndfast7` and the script equal the programs on every set (one set is refused: the program reads an unassigned variable). But
62 of its 90 DNA sets end with a segmentation fault of `dndfast7` and 27 stop with "count (fasta34 -z 3) = n": **only ONE DNA set ran to the end**. The success path of the nucleotide reader (`ReadFasta34m10_nuc`: the blocks of the reverse strand, several blocks per pair, `cutal` on both strands,
`-A` on DNA, the blocks of `fasta34` for 600 - 1500 nt) therefore has one example. This package gives it the data: 288 sets, 200 DNA sets of 40 - 1500 nt (related families, reverse-complemented members, fragments, N, lower case, duplicates; 3 - 15 sequences) and 88 protein or mixed sets (48 of them name further files: `--add` / `--addprofile` / `--keeplength` / `--mapout` / `--seed` / `--merge` / `--treein` with `new.fa`, `seed.fa`, `table.txt`, `tree.txt`, made by `make_inputs.py` with the installed mafft), with 20 / 10 + 16 option lines
(`--retree 1 / 2 / 3`, `--maxiterate 2 / 3 / 5`, `--treeout --distout`, `--reorder`, `--anysymbol`, `--op --ep`, `--nofft`, `--large`, `--stepadd`, `--weighti 0`, `--bl 80`, `--jtt 100`, `--kappa 4`, `--nuc`, `--leavegappyregion`).

**What it does.** For each set of `inputs/sets.tsv` (generated by `make_inputs.py`, fixed seed): (1) `mafft <options> in.fa` WITHOUT `--quiet` with `FASTA_4_MAFFT` pointing to the logging wrapper (`fasta34-log`): rows, names, return code, standard error, `in.fa.tree`, `in.fa.hat2`, every raw call of fasta34;
(2) `dndfast7 [-A] < in.fa` run directly: its `hat2`, `hat3`, standard error. Debian 12 `mafft` 7.505-1, `fasta34` 34.26.5 built from `../A2-19c-fastaparttree/inputs/fasta-34.26.5.shar.Z` (parsed, not executed). No account data, no secrets.
