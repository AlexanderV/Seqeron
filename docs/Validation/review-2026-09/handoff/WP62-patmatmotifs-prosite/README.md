# Hand-off WP62-patmatmotifs-prosite (temporary Docker package for the user's Mac)

**Why.** `patmatmotifs` of EMBOSS 6.6.0 reads the PROSITE database (`PROSITE/prosite.lines`, `prosite.dat`, `prosite.doc` made by `prosextract` from the SIB files `prosite.dat` / `prosite.doc`). The audit machine has no PROSITE data and no
network access to the SIB FTP site, so the program cannot be run there with real data (the port is checked against the program with synthetic PROSITE files in the work directory; this package is the check with the real release).
Nothing else is blocked: `patmatdb` takes its motif on the command line and is checked in the sandbox.

**What it does.** Builds a `linux/amd64` image (Ubuntu 22.04, package `emboss` 6.6.0+dfsg, the same version the port is built against), downloads the real `prosite.dat` / `prosite.doc` (`https://ftp.expasy.org/databases/prosite/`; neutral
User-Agent `Seqeron-review/1.0`, no account data), runs `prosextract`, then runs `patmatmotifs -auto ARGS` for every line of `inputs/rows.txt` (generated by `make_rows.py`: 6 input files x `-full` x `-prune`, 22 report formats, the report qualifiers, ranges, damaged / empty / missing input) on the
sequences of `inputs/*.fa` (generated deterministically by `make_inputs.py`: random proteins with planted instances of frequent PROSITE patterns). Every row writes standard output, error stream, exit status, the written files and a valgrind verdict to `out/rows/NNN/`; `out/environment.txt`
holds `uname -m`, the program version and the checksums of the data files.

**Commands (the 3 you need).**
```
cd docs/Validation/review-2026-09/handoff/WP62-patmatmotifs-prosite
./run.sh                      # builds the image, runs the rows, writes ./out and ./returned/WP62-patmatmotifs-prosite-out.zip
ls -l returned                # on Apple Silicon the run emulates x86_64: allow ~10-20 minutes
```
**Send back.** The archive `returned/WP62-patmatmotifs-prosite-out.zip` (or the `out` + `inputs` directories) placed in `docs/Validation/review-2026-09/handoff/WP62-patmatmotifs-prosite/returned/`.

**How it is integrated.** The next session converts `out/rows` into `tests/.../TestData/Alignment/emboss_prog_patmatmotifs_prosite_oracle.jsonl.gz` (same row format as `emboss_prog_oracle_lib.py`; the PROSITE data files are not stored: the test rows carry the
data lines the patterns of the rows need) and runs `EmbossPrograms_Oracle_Tests` on it. It decides whether the port of `patmatmotifs` (PROSITE pattern -> regular expression `embPatPrositeToRegExp`, the profile / rule items of `prosite.lines`,
the pruning of the simple patterns, the `dbmotif` report with the documentation of `-full`) equals the program on the real data.
