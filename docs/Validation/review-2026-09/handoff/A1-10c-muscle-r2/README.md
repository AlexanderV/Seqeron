# TEMPORARY hand-off package A1-10c-muscle-r2 - ROUND 2 of the MUSCLE 3.8.1551 oracle (Docker, for the user's Mac)

**Why.** Round 1 (`../A1-10c-muscle`, 420 sets) is returned and **equal**: `SequenceAligner.MultipleAlignMuscle` gives the rows and the output order of the unmodified MUSCLE v3.8.1551 on 420 / 420 sets
for `-maxiters 1|2` with `-le/-sp/-sv`, `-gapopen/-gapextend/-center`, `-distance1 kmer6_6`, `-cluster1/-cluster2`, `-sueff`, `-maxtrees 0`. Everything else the 3.8 command line offers for the alignment
algorithm is now **implemented from the source** (`SequenceAligner.Muscle*.cs`, `MuscleOptions`, MCP `multiple_align_muscle` / `muscle_msa_command`) but has **no oracle yet**. This package runs the same
unmodified binary on 638 deterministic sets that exercise every such option and command line, so the next session can compare row for row (and file for file).
Until the returned archive is integrated these options are marked **"implemented from the source, awaiting oracle"** in `B09.md`, the algorithm doc, the TestSpec and the MCP descriptions.

## What it runs (inputs/sets.tsv, regenerated by `make_inputs.py`, matrices in inputs/matrices)

| kind | sets | what is compared |
|---|---|---|
| `align` (449) | iterations 3-16 and the default 8 (`-maxiters` absent), `-anchors/-noanchors`, `-anchorspacing`, `-smoothwindow`, `-smoothscoreceil`, `-minbestcolscore`, `-minsmoothscore`, `-objscore sp/dp/xp/spf/spm/ps`, `-weight/-weight1/-weight2 none/henikoff/henikoffpb/gsc/clustalw/threeway`, `-maxtrees 0-5`, `-termgaps full/half/ext`, `-distance1 kmer20_3/kmer20_4/kbit20_3/pwkimura/pwscoredist`, `-distance2 pctidkimura/pctidlog/edit/scoredist`, `-cluster1/2 neighborjoining + upgm*`, `-root1/-root2 pseudo/midlongestspan/minavgleafdist`, `-brenner`, `-matrix` (BLOSUM62 with / without the `*` column, PAM250), `-usetree` (the tree of `-clusteronly -tree1` of the same sequences), the files `-tree1 -tree2 -distmx1 -distmx2 -computeweights`, `-clusteronly`, the options the source compiles out (`-diags*`, `-hydro*`, `-tomhydro`, `-gapopen2/-gapextend2/-gapambig`, `-maxmb`, `-maxhours`, `-core/-nocore/-group/-dimer/-verbose`: expected **no effect**), `-stable` (expected: "not supported") | rows in written order, labels, the files |

| `spscore` (22) | `muscle -spscore aln` | the printed `SP=%.4g` |

Sequences are at least 12 residues long (the k-mer distances `kmer20_3/kmer20_4/kbit20_3` read outside their buffer for shorter ones). Every run uses `-quiet -seqtype <type>`.

## Run it (Apple Silicon: the image is x86-64 and is emulated; docker must be running)

```bash
cd docs/Validation/review-2026-09/handoff/A1-10c-muscle-r2
./run.sh                  # builds the image (a few minutes: compiles MUSCLE), runs 638 muscle3 calls, zips ./out
ls -l returned/           # A1-10c-muscle-r2-out.zip
```

`run.sh` needs only `docker` (and `zip` or `tar`). The image is built from the unmodified Debian source `muscle3 3.8.1551-2` with the upstream flags (sha256 of every source file and of the binary
are recorded in `out/`); no account data, the download uses the User-Agent `Seqeron-review/1.0`. Nothing aborts: a set on which MUSCLE fails (or crashes) is recorded with its exit status and message -
those rows are part of the oracle.

## What to send back

`returned/A1-10c-muscle-r2-out.zip` (or `.tar.gz`), kept in this repository under `docs/Validation/review-2026-09/handoff/A1-10c-muscle-r2/returned/`. It contains `out/ENV.txt` (date, `uname -m`, `muscle3 -version`,
binary checksum), `out/build.log`, `out/preflight.txt`, `out/fetch_src.sha256`, `out/muscle3_r2_oracle.tsv`, `out/run.log`.

## How the next session integrates it

`python3 scripts/alignment/generate_muscle3_r2_oracle.py` converts the archive into `tests/Seqeron/Seqeron.Genomics.Tests/TestData/Alignment/muscle3_r2_oracle.tsv` (the matrix texts are substituted, so the
file is self-contained; the column mapping of every `kind` to the port - `MuscleRun`, `MuscleProfileAlign`, `MuscleRefine`, `MuscleScoreAlignment`, `MuscleProfileScore`, `MuscleGuideTree`,
`MuscleRefineWindows`, `MuscleLocalAlign` - is in the script header) and a test `SequenceAligner_MuscleOracleRound2_Tests` (same pattern as `SequenceAligner_MuscleOracle_Tests`) asserts rows, written order and files
**equal** on every set. Every difference is a defect of the port (or of a reading of the source) and is fixed stage by stage - the intermediate quantities (distance matrices, trees, weights, profiles, scores)
are re-derived from the source in a scratch re-implementation and compared with the `-tree1/-tree2/-distmx*/-computeweights` files; nothing is "accepted". Rows that MUSCLE refuses or crashes on
must be refused by the port (`NotSupportedException` / `ArgumentException`). When the archive is integrated and equal, the options listed above lose the qualifier "awaiting oracle" in `B09.md` (A1-10c a2 ticked),
`Multiple_Sequence_Alignment.md`, `ALIGN-MULTI-001` TestSpec / Evidence / report and the MCP tool descriptions. If `ENV.txt` shows a `muscle3 -version` other than 3.8.1551, nothing is integrated until that is explained.
