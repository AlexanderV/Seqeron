## Confirmed fixes

### F1 — CHROM-TELO-001: telomeres ending in a partial repeat were missed
- **Defect:** the old scan checked fixed 6-bp windows (≥70 % similarity) locked to the repeat phase at the terminus. If a chromosome end stops partway through a repeat unit, every window is out of phase and the length comes out 0.
  - Repro: `A×1000 + (TTAGGG)×200 + "TTAG"` gives 3′ length 0 and `Has3PrimeTelomere=false`. seqtk gives 1204.
  - Symmetric 5′ repro: `"AA" + (CCCTAA)×200 + A×1000` gives 0. seqtk gives 1202.
  - No source supports the old window/70 % rule.
- **Source:** seqtk 1.5-r133 `stk_telo` (raw.githubusercontent.com/lh3/seqtk/master/seqtk.c, with kseq.h and khash.h), compiled locally.
- **Fix:** `AnalyzeTelomeres` is now a faithful port of that scan:
  - A position is a hit when its k-mer is any rotation of the motif (or of its reverse complement at the 5′ end).
  - Score +1 per hit and −penalty per miss. The tract ends at the maximum cumulative score, and the scan stops once the score drops more than maxDrop below it.
  - seqtk's scoring offsets are kept.
  - Only A/C/G/T are valid bases; any other base resets the k-mer.
  - New optional parameters `penalty=1` and `maxDrop=2000` (seqtk `-p` and `-d`).
  - An empty or non-ACGT motif now throws.
- **Cross-check:**
  - A Python line-by-line port matched seqtk telo on 66 sequences (60 random mutated tracts plus fixtures) with 0 mismatches.
  - The C# code matched the Python port on the same 66, lengths and purities to 1e-12.
  - Locked fixtures from seqtk:
    - every-10th-unit TTAGGA tract: 1194 bp, purity 1075/1189;
    - N inside the tract: 1201 bp, purity 1190/1196;
    - Arabidopsis motif CCCTAAA: 1050;
    - single unit: 3′ = 6, 5′ = 0.
- **Tests:** `Unit/Chromosome/ChromosomeAnalyzer_Telomere_Tests.cs`
  - `TerminalPartialRepeat_MatchesSeqtkTelo`
  - `AmbiguousBaseInsideTract_MatchesSeqtkTelo`
  - `SingleUnit_SeqtkScoringOffsets`
  - `NonMotifHexamerTract_NotDetected`
  - `InvalidMotif_Throws`
  - `DivergentRepeats_LowerPurity` (rewritten to seqtk values)
  - Metamorphic, property and fuzz tests adjusted where they assumed the old algorithm: "length is a multiple of 6" is dropped, and the purity bound is now > 0.5.
- **Behaviour change:**
  - Lengths are now counted per base, not in whole repeat units.
  - A tract built only from a non-motif hexamer (e.g. TTAGGA×200) is no longer detected.
  - The prior report `docs/Validation/reports/CHROM-TELO-001.md` (CLEAN) is superseded.

### F1b — CHROM-TELO-001 follow-up: property tests assumed pre-seqtk semantics
- **Defect:** `ChromosomeProperties` failed intermittently. The 5′ generator allowed k = 1, and seqtk scores 5′ positions only from i ≥ k, so a single unit is 0. The presence-flag oracle ignored the `len > 0` rule.
- **Confirmed** with the compiled seqtk on 71 sequences (`CCCTAA`×k + A-suffix): k = 1 gives no tract; every k ≥ 2 gives exactly 6k.
- **Fix (tests only):** the generator now uses k ∈ [2,400], and the oracle is `len ≥ min ∧ len > 0`. Six consecutive runs were green.

### F2 — CHROM-CENT-001: `AnalyzeCentromere` hangs when windowSize < 4
- **Defect:** the scan step is `windowSize/4`, which is 0 for windowSize 0–3, so the loop never ends. The MCP wrapper still accepted 1–3.
- **Fix:** windowSize ≤ 0 now throws `ArgumentOutOfRangeException`, and the scan and extension steps are clamped to at least 1.
- **Tests:** `AnalyzeCentromere_TinyWindow_TerminatesAndReturnsUnknown`, `AnalyzeCentromere_NonPositiveWindow_Throws(0,-5)`.

### F3 — CHROM-CENT-001: window scan off-by-one
- **Defect:** the loop ran `i < L−W`, so a sequence exactly W long returned Unknown. The doc says only shorter sequences do.
- **Fix:** `i ≤ L−W`.
- **Reference:** Python/numpy script `cent_ref.py`. (ACGTGA)×400 with W = 2400 gives (0, 2400, 1.0, Metacentric).

### F4 — CHROM-CENT-001: GC-SD sub-window off-by-one
- **Defect:** the last full 1-kb sub-window was dropped, so the default 100 kb window used only 99 of its 100 sub-windows.
- **Reference (numpy population SD):**
  - (AT)500(GC)500, W = 2000: score 0.49647532729103727. The old code gave Unknown.
  - (AT)500(GC)750: region (500, 2500), score 0.744712990936556. The old code picked a different window, with score 0.99295.

### F5 — CHROM-CENT-001: boundary extension never reached position 0 or L
- **Fix:** the comparisons `>` and `<` became `>=` and `<=`.
- **Reference:**
  - 300 kb poly-A: End = 300000; the old code gave 295000.
  - Embedded array: exact (3000, 5400).
- The existing locks held the old off-by-one values and were corrected to the reference:
  - MCP test `AnalyzeCentromere_Binding_InvokesSuccessfully`: 295000 → 300000.
  - Snapshot `AnalyzeCentromere_KnownSequence`: End 15500 → 16000.

### F6 — CHROM-CENT-001: suprachromosomal-family rules contradicted the sourced A/B taxonomy
- **Source:** McNulty & Sullivan 2018 (PMC6121732), as tabulated in the unit's Evidence: J1 = A with J2 = B, D1 = B with D2 = A, M1 = A, SF5 = R1/R2.
- **Defect 1:** a period-2 array returned `Sf1OrSf2Dimeric` whatever its box types.
- **Defect 2:** a monomeric B-only array returned `Sf5`.
- **Fix:** a dimer now needs one A-type and one B-type monomer, and B-only monomeric arrays return Unknown.
- **Confirmed** on the Dfam monomers: (ALR·ALRa)×6 resolves to [A,A] and now returns Unknown; ALRb×8 now returns Unknown.
- **Tests:** `AssignSuprachromosomalFamily_DimericAAArray_IsNotSf1OrSf2`, `AssignSuprachromosomalFamily_MonomericBOnlyArray_IsUnknown`.

All CENT tests are in `Unit/Chromosome/ChromosomeAnalyzer_Centromere_Tests.cs` and `…_SuprachromosomalFamily_Tests.cs`. Four of the new tests failed on the old code, and the window-0 test hung it.

## Duplication removed
- **CHROM-CENT-001:** `EstimateRepeatContent` now calls the canonical `KmerAnalyzer.CountKmers` instead of its private dictionary loop. 15-mers containing N are still excluded, so behaviour is unchanged. GC already used `CalculateGcFractionFast`. The inline population SD stays, because StatisticsHelper has no public SD helper.

## Simplifications kept (with reason) / LIMITATIONS proposals
- **CHROM-TELO-001, `EstimateTelomereLengthFromTSRatio`:** uses a zero-intercept proportional calibration, `refLen·(T/S)/refRatio`. Cawthon (2002) reports only that T/S correlates with TRF length. A regression with an intercept needs lab-specific TRF-vs-T/S data, which the code cannot supply. *Proposed LIMITATIONS entry:* "T/S→bp conversion is a single-point proportional calibration; a lab-specific TRF-vs-T/S regression (with intercept) is required for absolute lengths."
- **CHROM-TELO-001:** telomere variant repeats (TCAGGG/TGAGGG/TTGGGG) are scored as misses, the same as seqtk telo. *Proposed LIMITATIONS entry* to match.
- **CHROM-CENT-001, `AnalyzeCentromere` localisation:** a heuristic score, 15-mer repeat density × (1 − GC-SD). Functional centromere identity is epigenetic (CENP-A; Mehta et al. 2010), so no sequence-only published finder exists to implement. This is now declared in the XML `<remarks>`. *Proposed LIMITATIONS row:* "AnalyzeCentromere — heuristic single-region localisation, not a published centromere caller; AlphaSatelliteContent is a composite score. Use DetectAlphaSatellite / DetectHigherOrderRepeat / AssignSuprachromosomalFamily for human alphoid signal, or RepeatMasker / HumAS-HMMER / CENP-A ChIP for reference-grade calls."
