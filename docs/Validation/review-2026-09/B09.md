## Confirmed fixes

### F1 — ALIGN-GLOBAL-001: `ScoringMatrix.GapOpen` ignored; no affine-gap global alignment
- Defect: every `GlobalAlign` overload is linear NW (each gap position = `GapExtend`); `GapOpen` never read, so `BlastDna` (2/−3/−5/−2) could not be applied as BLAST scoring. Repro: `GlobalAlign("ACGTTTTACGT","ACGTACGT",BlastDna)` charges the 3-nt gap as 3×(−2) instead of −5+3×(−2).
- Sources: Gotoh 1982 gap cost w(k)=v+u·k (GapOpen excludes first extension); BLAST+ manual NBK279684 blastn defaults (reward 2, penalty −3, gapopen 5, gapextend 2 — search snippets); Flouri et al. 2015 (bioRxiv 10.1101/031500, snippets + gata-bio/affine-gaps README) for correct border initialisation.
- Reference cross-check: new `GlobalAlignAffine` = Biopython 1.88 `PairwiseAligner(mode='global', open_gap_score=GapOpen+GapExtend)` = parasail 1.3.4 `nw_trace` on 1048 cases (8 schemes), 0 mismatches; every returned alignment re-scores to its score. Gotoh original border gives A/CAC = −9 vs correct −11.
- Fix: `GlobalAlignAffine` (DnaSequence + string overloads), three-state M/X/Y DP with explicit inter-matrix traceback, Flouri border X(i,0)=o+i·e, Y(0,j)=o+j·e, overflow-safe −∞ sentinel. Linear `GlobalAlign` kept (documented as linear-only).
- Tests: `BlastDnaPreset_MatchesNcbiBlastnDefaults`, `Affine_SingleLongGap_ChargedOneOpening_BlastDna` (5), `Affine_ReferenceScores_MatchBiopythonAndParasail` ×4 (−17, −6, 16, −3), `Affine_TwoSeparateEndGaps_EachChargedAnOpening_FlouriInitialization` (A/CAC = −11, `-A-`/`CAC`), `Affine_ZeroGapOpen_EqualsLinearNeedlemanWunsch`, `Affine_EmptyInputs_BorderValues` (""/ACGT = −13), `Affine_DnaSequenceAndStringOverloads_Agree`.

### F4 — ALIGN-MULTI-001: `MultipleAlign` (center-star) was not an optimal pairwise alignment for k = 2
- Defect: the pairwise stage of the "center-star" was `AnchorBasedAligner` (exact-match anchors force the alignment path), so the MSA of two sequences was not the Needleman-Wunsch optimum and the center was a 4-mer cosine heuristic, not Gusfield's. Repro: `MultipleAlign(GGAAGCCAATAATCGTGCACGAAGGTGACTGCAGGAGAGTACGAAGGT, AGACAGCCAAAATCTTCAGAGTTCGACTGGAGGTGACTACGAAGAT)` TotalScore 9 vs optimum 24; 4 of 2000 random related pairs suboptimal (22 vs 27, −35 vs −3, …).
- Sources: Gusfield 1993 (Bull Math Biol 55:141, WebSearch records: center-star, bound 2 − 2/k) and Gusfield 1997 §14.6.1 (method description); Feng & Doolittle 1987 (once a gap, always a gap).
- Reference cross-check: Biopython 1.88 `PairwiseAligner(mode='global', match 1, mismatch −1, open = extend = −1)`: 24 / 27 / −3 for the three repro pairs; independent Python Gusfield center-star (own NW with diagonal > up > left, center = argmax of total pair score, gap-slot merge) reproduces the rows of 300 random sets (k = 2..6, 3 scoring schemes) exactly (0 mismatches); the k = 2 SP equals the Biopython optimum in all 62 two-sequence sets.
- Fix: `MultipleAlign` = Gusfield center-star with the canonical linear NW for every pair (pair scores from the linear-space NW pass, alignments via `GlobalAlignLinearSpace`, exact Hirschberg above 4 M cells so memory stays bounded); center = best total pair score (ties: lowest index). The former behaviour is kept as the explicitly approximate additive `MultipleAlignAnchored` (public). `ReconcileAlignments` → `MergeCenterAlignments` (no unused score, shared by both variants); `MultipleAlignClassic` (benchmark baseline) now merges properly instead of right-padding.
- Tests: `SequenceAligner_MultipleAlignStar_Tests` ×16 (3 Biopython pair optima, 3/4/5-sequence independent-reference rows, center rule, determinism, 150 random validity sets, empty member, large pair via Hirschberg path, anchored-variant contract).
- Commit: `114ab66e`.

### F5 — ALIGN-MULTI-001 (B05 request): `AnchorBasedAligner` chaining, gap scoring, large gaps, comments
- Defects: (1) comments claimed "all MEMs"/MUMmer while `FindExactMatchAnchors` returns one MEM per diagonal run; (2) `ChainAnchors` dropped one of two overlapping anchors (greedy `RemoveOverlaps`) and maximised the NUMBER of anchors (LIS) rather than the covered bases; (3) one-sided gap runs scored `GapOpen + k·GapExtend` while DP gaps and the `GlobalAlign` fallback were linear, so `Score` disagreed with the returned rows; (4) segments > 5000 bases were "aligned" by a diagonal heuristic; (5) empty input returned `AlignmentResult.Empty`. Repro (2): anchors (0,0,10) and (6,20,10) → old chain covered 10 bases, new 16.
- Sources: Delcher et al. 1999 (MUMmer; suffix tree, longest colinear subset, DP between matches); Abouelhoda & Ohlebusch 2005 (PDF opened: maximum-weight chain of colinear non-overlapping fragments); Hirschberg 1975.
- Fix: comments accurate; weighted colinear chain (O(a²) DP) with front-trimming of overlapping anchors (a suffix of an exact match is an exact match); linear scoring everywhere (`Score` = linear re-score of the rows, ≤ unconstrained optimum); exact linear-space Hirschberg (`GlobalAlignLinearSpace`, score identical to NW on 200 random pairs × 4 schemes with forced recursion) for segments above 25 M cells; empty side → proper all-gap alignment.
- Tests: `AnchorBasedAligner_Tests` ×17 (chain overlap/coverage/crossing + 300 random-anchor invariants, identical, empty side, linear scoring, 120 related pairs ≤ `GlobalAlign` with valid rows, repeated blocks, Hirschberg vs Biopython 24 / 27 and random schemes).

### F7 — ALIGN-MULTI-001: T-Coffee extension only for primary pairs; percent identity over gap columns
- Defect: (a) `BuildExtendedLibrary` extended only the pairs present in the primary library, so a residue pair that no direct alignment joins but two alignments join through a third sequence scored 0 in the progressive DP; the paper ("Extension will be carried out on each pair of residues of A and B") and T-Coffee's `residue_pair_extended_list` (evaluate.c, opened) score every pair. (b) The percent-identity weight divided by the alignment length including gap columns; T-Coffee `get_seq_sim` (aln_convertion_util.c, opened) divides by aligned non-gap columns with integer division. Repro: CTT/ACT/CAA, pair (S1.1, S2.0): extended 0 (old) vs 133 = min(200, 133); ACGTTACGT/ACG--ACGT weight 78 (old) vs 100.
- Sources: Notredame, Higgins & Heringa 2000 (PDF pp.207-210 opened); cbcrg/tcoffee `evaluate.c`, `aln_convertion_util.c` (raw files opened); T-Coffee technical documentation.
- Reference cross-check: independent Python T-Coffee (own NW/SW, `get_seq_sim` weights, on-demand triplet extension, zero-gap progressive DP): 0/300 row mismatches after the fix; 170/300 differed before. Hand values: ACGTTACGT/ACGACGT/ACGTACGA primary 200, extended 385 = 200 + min(187, 185).
- Fix: `ExtendedLibrary` (primary + neighbour index + cache) evaluating any pair on demand; `PercentIdentity` per `get_seq_sim`; primary-library building shared (`BuildPrimaryLibrary`, diagnostics duplicate removed).
- Binary cross-check (Debian `t-coffee` 13.45 installed by apt, run with the same explicit primary library and the same guide tree, `-extend_mode slow_triplet`): its alignments differ from the paper-formula DP in most random sets (k = 3: 105 of 120) because T-Coffee rescales every extended pair score by its residue's partner-weight total (`evaluate.c` L5245-5250, not in the paper), but under the paper's objective (sum of extended weights) the T-Coffee alignment never scored higher than ours for k = 3 (0/120); for k = 4-5 it scored higher in 7/150 sets, where its tree traversal/normalisation changes the merges. The extension rule itself is therefore confirmed by the paper text and `residue_pair_extended_list`, not by identical rows.
- Tests: +3 in `SequenceAligner_MultipleAlignConsistency_Tests` (weights 200/385, indirect pair 0 → 133, rows `-CTT`/`AC-T`/`-CAA`).
- Commit: `114ab66e`.

### F8 — ALIGN-MULTI-001: progressive distance was not the ClustalW distance; UPGMA ties decided by rounding noise

## Simplifications kept (with reason) / LIMITATIONS proposals

- ALIGN-MULTI-001 (declared in the algorithm doc §5.3): (1) linear-gap model for all MSA methods, `GapOpen` unused — the exact SP objective with affine natural gap costs (Altschul 1989) depends on the whole column history of every row pair; MSA programs use quasi-natural/position-specific approximations and no exact polynomial profile-profile DP exists; the 2-sequence case is covered by `GlobalAlignAffine`. (2) UPGMA guide tree instead of NJ for the T-Coffee path; (3) single best SW alignment per pair instead of Lalign's top-N non-intersecting alignments and no sequence-redundancy weights. (2) and (3) change merge order / library density only.
- ALIGN-SEMI-001: only the *fitting* (query-in-reference) semi-global variant is provided; overlap / all-ends-free variants are not implemented. Scope choice, documented in XML + algorithm doc; no LIMITATIONS entry needed.
