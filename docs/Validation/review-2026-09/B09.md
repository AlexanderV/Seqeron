### F4 — ALIGN-MULTI-001: `MultipleAlign` (center-star) was not an optimal pairwise alignment for k = 2
- Defect: the pairwise stage of the "center-star" was `AnchorBasedAligner` (exact-match anchors force the alignment path), so the MSA of two sequences was not the Needleman-Wunsch optimum and the center was a 4-mer cosine heuristic, not Gusfield's. Repro: `MultipleAlign(GGAAGCCAATAATCGTGCACGAAGGTGACTGCAGGAGAGTACGAAGGT, AGACAGCCAAAATCTTCAGAGTTCGACTGGAGGTGACTACGAAGAT)` TotalScore 9 vs optimum 24; 4 of 2000 random related pairs suboptimal (22 vs 27, −35 vs −3, …).
- Sources: Gusfield 1993 (Bull Math Biol 55:141, WebSearch records: center-star, bound 2 − 2/k) and Gusfield 1997 §14.6.1 (method description); Feng & Doolittle 1987 (once a gap, always a gap).
- Reference cross-check: Biopython 1.88 `PairwiseAligner(mode='global', match 1, mismatch −1, open = extend = −1)`: 24 / 27 / −3 for the three repro pairs; independent Python Gusfield center-star (own NW with diagonal > up > left, center = argmax of total pair score, gap-slot merge) reproduces the rows of 300 random sets (k = 2..6, 3 scoring schemes) exactly (0 mismatches); the k = 2 SP equals the Biopython optimum in all 62 two-sequence sets.
- Fix: `MultipleAlign` = Gusfield center-star with the canonical linear NW for every pair (pair scores from the linear-space NW pass, alignments via `GlobalAlignLinearSpace`, exact Hirschberg above 4 M cells so memory stays bounded); center = best total pair score (ties: lowest index). The former behaviour is kept as the explicitly approximate additive `MultipleAlignAnchored` (public). `ReconcileAlignments` → `MergeCenterAlignments` (no unused score, shared by both variants); `MultipleAlignClassic` (benchmark baseline) now merges properly instead of right-padding.
- Tests: `SequenceAligner_MultipleAlignStar_Tests` ×16 (3 Biopython pair optima, 3/4/5-sequence independent-reference rows, center rule, determinism, 150 random validity sets, empty member, large pair via Hirschberg path, anchored-variant contract).

### F14 — ALIGN-STATS-001: no residue-pair similarity; markup differed from EMBOSS; identical X/X counted similar
- Defect: similarity could only come from a scalar mismatch score, so protein (BLOSUM62/PAM250) and IUPAC-DNA (EDNAFULL) similarity — the very example of the needle documentation (HBA/HBB: 90 similar of 149) — was unreachable; markup printed a space for mismatches and the doc claimed the `.` tier unreachable and `:` for score > 1.0 (AlignFormats web page), while the needle/water 6.6.0 binary writes `.` for aligned non-similar columns; MCP `format_alignment` described `.` for mismatches but printed a space. Repro: `FormatAlignment("ACGT","ACGA")` gave `||| `, needle gives `|||.`.
- Sources: EMBOSS 6.6 `ajax/core/ajalign.c` `alignConsStats` / `alignSim` (raw.githubusercontent.com, opened), needle/water 6.6.0 binaries + data files `EBLOSUM62`, `EPAM250`, `EDNAFULL`, Biopython 1.88 `substitution_matrices` (BLOSUM62, PAM250, NUC.4.4), NCBI blastn defaults (BLAST+ manual: reward 2, penalty −3, existence 5, extension 2).
- Rule recovered from the source and confirmed by single-pair experiments with the binary (both orders, all BLOSUM62 pairs / all IUPAC pairs): similar iff `M(x,y) > 0 ∧ (M(x,x) > 0 ∨ M(y,y) > 0)`; markup `h = [M(x,x)>0] + [M(x,y)>0]`: 2 → `|` (identical) / `:`, 1 → `.`, 0 → space (gap columns space). So an identical X/X (−1) or N/N (−1) is an identity but neither similar nor barred; a first-row ambiguity residue gets `.`/space even if the pair is positive (needle R/A `.`, A/R `:`) — an EMBOSS quirk, reproduced and documented.
- Oracle numbers: 301 alignments (needle global + water local; DNA, IUPAC DNA / EDNAFULL, protein / EBLOSUM62 + EPAM250 incl. B/Z/X; 12 439 columns): Length, Identity, Similarity, Gaps, markup line equal in all; mismatches and open gaps equal Biopython; HBA/HBB literal example 149 / 65 / 90 / 9. Matrices: 576 + 576 + 256 cells equal the EMBOSS data files; 576 + 576 + 225 shared cells equal Biopython 1.88.

### F16 — GENOMIC-COMMON-001 (B05 request): `FindCommonRegions` quadratic → matching statistics
- Defect: per-start binary search with `Substring(i, mid)` + `Contains` copied up to m characters per probe: O(m²) time and allocation regardless of `minLength` (random 100 kbp pair 2.6 s; extrapolated ≈ 4 min at 1 Mbp).
- Source: Chang & Lawler 1994 matching statistics (search snippets; paper not opened), MUMmer MEMs (Kurtz 2004) through the canonical `SuffixTree.FindMaximalExactMatches` (B05 F20). The per-start longest right-maximal match is ms(i); ms(i) ≥ ms(i−1) − 1.
- Fix: no public per-position matching-statistics API exists on this branch (`SuffixTreeAlgorithms.CollectMaximalMatchingStatistics` is private; src/SuffixTree untouched per instructions), so ms(i) is assembled from public primitives, exactly: ms(i) < K = ⌈log₄(n·m)⌉ + 2 by carry-over + `Contains(span)` extension (O(m·K), no substring copies); ms(i) ≥ max(K, minLength) from the MEM stream (ms(i) = max over MEMs with start ≤ i of end − i; exact because the maximising diagonal's maximal run is a MEM of length ≥ ms(i)); expected MEM count between unrelated random sequences O(1). Strings are deduplicated with an alternate span lookup (no allocation for duplicates). `ArgumentNullException` for null arguments (eager; was `NullReferenceException`).
- Results: random 1 Mbp pair (Debug) LCS 2.8 s, regions min 1 (666 618) 3.8 s, min 20 1.7 s; 1 Mbp with 1 % substitutions, min 20: 861 267 regions (131.6 Mchar) 4.6 s. Output equal to the oracle (283 pairs + 120 extra 200-2500 bp pairs with planted blocks and min up to 40, run ad hoc) and to the in-test brute force.
- Tests: `FindCommonRegions_OneMegabasePair_IsLinearAndCorrect` (1 Mbp + planted 5 kb block, < 60 s guard), oracle + brute-force differential tests, `CommonRegionMethods_NullSequences_ThrowArgumentNullException`, lower-case equality, non-ACGT (N/U) rejected by `DnaSequence`, `FindCommonRegions_ExtremeMinLength_Handled` (int.MinValue … int.MaxValue).
