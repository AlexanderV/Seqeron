## Confirmed fixes

### F1 — PAT-EXACT-001: MCP `suffix_tree_find_all` returned positions in traversal order
- Defect: `SuffixTreeFindAll("GATATATGCATATACTT","ATAT")` → `[1,9,3]`.
- Source: Rosalind SUBS (locations reported ascending); reference: Python `re.finditer("(?=ATAT)")` → [1,3,9]; mississippi/i → [1,4,7,10]; abracadabra/a → [0,3,5,7,10].
- Fix: sort in the MCP wrapper; core `FindAllOccurrences` keeps O(m+z) traversal order (documented in `ISuffixTreeSearch`). Tool docs say "0-based, overlapping, ascending".
- Test: `SuffixTreeFindAllTests.SuffixTreeFindAll_ReturnsPositionsInAscendingOrder` (red before, green after); `MotifFinderTests.FindExactMotif_RosalindSubs_ReturnsOverlappingPositionsAscending`.

### F2 — PAT-APPROX-002: FindWithEdits was a brute-force window scan; Sellers end-position search missing
- Defect: `FindWithEdits` recomputed a full DP for each of (2k+1) window lengths at every start (O(n·(2k+1)·m·(m+k))); no Sellers k-differences end-position search existed.
- Source: Sellers 1980 / Navarro 2001 §5.1 (via search snippet), Ukkonen 1985 cut-off; edlib README (HW infix mode).
- Reference cross-check: survey in surgery, k=2 → ends (4,2),(5,2),(6,2); windows SURGE/SURGER/SURGERY d=2. TTAC in GATTACAGATTTACA, k=1 → (4,1),(5,0),(6,1),(12,1),(13,0),(14,1) (edlib best d=0 at ends 5,13). ACGA in ACGTTGCAACGT, k=2 → 9 ends (edlib best d=1 at 2,3,10,11). 3000 random cases window-ends == Sellers ends.
- Fix: shared private column kernel `AdvanceColumn`; `EditDistance` (top=j, unchanged results); new public `FindEditEndPositions` (top=0, O(n·m)); `FindWithEdits` one start-anchored DP per start covering all lengths with Ukkonen early stop. Output content/order unchanged.
- Tests: `FindEditEndPositions_NavarroSurveySurgery_ReturnsSellersEnds`, `_TtacInGattaca_MatchesEdlib`, `_AcgaK2_MatchesEdlib`, `_Guards`, `FindWithEdits_NavarroSurveySurgery_ReturnsAllWindows`, `FindWithEdits_EndPositionSet_EqualsSellers` (300 seeded cases).

### F3 — PAT-APPROX-003: FindFrequentKmersWithMismatches returned non-DNA k-mers for windows containing N
- Defect: `("ANGANG",3,1)` returned ANA/ANC/ANT (count 2) besides AAG/ACG/AGG/ATG; `("NNNN",2,1)` returned NA/NC/NG/NT:3.
- Source: Compeau & Pevzner BA1N — neighbourhood = k-mers over {A,C,G,T} within Hamming d; go-rosalind reference (`rosalind_ba1.go`) restricts to DNA.
- Reference cross-check (Python brute force over 4^k): {AAG,ACG,AGG,ATG}:2; NNNN → empty; `ACGTTNCATGTCGCATGATGCANGAGAGCT`,4,1 → {ATGA,ATGT,CATG}:4.
- Fix: positional neighbour generation over ACGT, one mismatch per substituted base; non-ACGT symbol always costs one mismatch. Identical set for ACGT input, no duplicates.
- Tests: `FrequentKmers_NonAcgtWindows_ReturnOnlyDnaKmers_MatchesBruteForce` (red before), `FrequentKmers_SingleWindow_ReturnsBa1nNeighborhood`.
