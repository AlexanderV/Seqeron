### F2 — PAT-APPROX-002: FindWithEdits was a brute-force window scan; Sellers end-position search missing
- Defect: `FindWithEdits` recomputed a full DP for each of (2k+1) window lengths at every start (O(n·(2k+1)·m·(m+k))); no Sellers k-differences end-position search existed.
- Source: Sellers 1980 / Navarro 2001 §5.1 (via search snippet), Ukkonen 1985 cut-off; edlib README (HW infix mode).
- Reference cross-check: survey in surgery, k=2 → ends (4,2),(5,2),(6,2); windows SURGE/SURGER/SURGERY d=2. TTAC in GATTACAGATTTACA, k=1 → (4,1),(5,0),(6,1),(12,1),(13,0),(14,1) (edlib best d=0 at ends 5,13). ACGA in ACGTTGCAACGT, k=2 → 9 ends (edlib best d=1 at 2,3,10,11). 3000 random cases window-ends == Sellers ends.
- Fix: shared private column kernel `AdvanceColumn`; `EditDistance` (top=j, unchanged results); new public `FindEditEndPositions` (top=0, O(n·m)); `FindWithEdits` one start-anchored DP per start covering all lengths with Ukkonen early stop. Output content/order unchanged.
- Tests: `FindEditEndPositions_NavarroSurveySurgery_ReturnsSellersEnds`, `_TtacInGattaca_MatchesEdlib`, `_AcgaK2_MatchesEdlib`, `_Guards`, `FindWithEdits_NavarroSurveySurgery_ReturnsAllWindows`, `FindWithEdits_EndPositionSet_EqualsSellers` (300 seeded cases).
