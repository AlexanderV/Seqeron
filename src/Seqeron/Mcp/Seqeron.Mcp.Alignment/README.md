# Seqeron.Mcp.Alignment

MCP server — **Pairwise and multiple sequence alignment, overlap/assembly and approximate matching.**

Exposes **43 tools** — the same validated `Seqeron.Genomics` algorithms as the C# API, callable over
MCP. Every tool carries an explicit JSON input/output schema and a Schema+Binding test, with a
per-tool doc under [`docs/mcp/tools/alignment/`](../../../../docs/mcp/tools/alignment). Rollout status:
[`docs/mcp/MCP_STATUS.md`](../../../../docs/mcp/MCP_STATUS.md).

## Run

```bash
dotnet run --project Seqeron.Mcp.Alignment
```

Register it in any MCP client as a stdio server (`command: dotnet`, `args: ["run","--project","Seqeron.Mcp.Alignment"]`). New to MCP? The [hub guide](../../../../docs/mcp/README.md) lists all 11 servers and how to wire them up.

**Protein / matrix multiple alignment (B09 F61, audit A1-14).** Every `multiple_align*` tool except `multiple_align_clustalw` takes `type = dna | protein` and `matrix = BLOSUM62 | PAM250 | EDNAFULL` (additive; `type=protein` defaults to BLOSUM62, EDNAFULL gives IUPAC DNA) and then scores residue pairs with the published substitution table and real-valued (fractional, EMBOSS-style 0.5) gap scores, linear or affine (`gapModel`); `gapOpen` / `gapExtend` are numbers (integers unless a matrix is used). The protein path is the same code as the DNA path (the string / `ProteinSequence` overloads of `SequenceAligner.MultipleAlign*` with `MatrixScoring`); results carry `exactTotalScore` (the real sum of pairs; `totalScore` is it rounded half away from zero) and, for `multiple_align_exact`, `scoreScale`. Verified against independent Python implementations of every method (238 protein / IUPAC-DNA sets, rows equal), Biopython 1.88 pairwise optima, exhaustive enumeration of tiny sets and the `t_coffee` program (160 protein sets for the progressive stage).

**ClustalW protein pairwise stages (B09 F62, audit A1-15b b).** With `type=protein`, `distance=clustalw` (full DP) and `distance=clustalw-quick` (`-QUICKTREE`) of `multiple_align_progressive`, `multiple_align_iterative` and `multiple_align_consistency` use ClustalW 2.1's PROTEIN pairwise stages (exact ports; the printed `Score:` equals the installed `clustalw -TYPE=PROTEIN` on 4 204 + 3 774 pairs): matrix `pwMatrix = gonnet (default) | blosum | pam | id`, `pwGapOpen` 10 / `pwGapExtend` 0.1 (length-dependent opening), fast stage k-tuple 1-2 with defaults 1 / 5 / 5 / 3 (`ktuple`, `window`, `topDiagonals`, `pairGap`). `multiple_align_clustalw` itself (the profile stage) remains DNA only.

**ClustalW user matrices (B09 F64, audit A1-10d).** `multiple_align_clustalw` with `type=protein` accepts `matrixFile` (the text of a `-MATRIX=file`: one matrix, or a `CLUSTAL_SERIES` file whose entries `MATRIX llimit ulimit file` are looked up in `matrixFiles`) and `pwMatrixFile` (`-PWMATRIX=file`); rows and pairwise scores equal `clustalw -MATRIX / -PWMATRIX` on 240 + 800 sets with integer / floating-point / unlabelled / tab-separated / header-subset files.

**ClustalW end-gap options (B09 F67, audit A1-10d part 2).** `multiple_align_clustalw` (DNA and protein) takes `useEndGaps` (`UserParameters::useEndGaps`) and `endGapPenalties` (`endGapPenalties`), the menu-only end-gap options of ClustalW's profile stage (the command-line `-ENDGAPS` is a no-op); verified on 340 sets x 4 modes of the patched `clustalw` 2.1 binary of the user-run Docker package `docs/Validation/review-2026-09/handoff/A1-10d`. With `endGapPenalties` ClustalW 2.1 writes no output when the score of a first-pass profile alignment is negative (34 of the 340 sets); the tool then fails with an explicit "ClustalW 2.1 abandons the alignment" error (`ClustalWAbortedException`).

**ClustalW nucleotide matrices (B09 F68, audit A1-10d part 3).** `multiple_align_clustalw` with `type=dna` takes `dnaMatrix` / `pwDnaMatrix` (`-DNAMATRIX` / `-PWDNAMATRIX` = `iub` (default) | `clustalw`), `dnaMatrixFile` / `pwDnaMatrixFile` (the text of a `-DNAMATRIX=file` / `-PWDNAMATRIX=file` matrix file) and `userDnaMatrixUse`: `applied` (default; what ClustalW's interactive menu does - the file is the matrix of the stage) or `commandline` (what `clustalw -DNAMATRIX=file` really does: the file is read and validated but registered under the PROTEIN slot, so the DNA stages keep IUB). `transitionWeight` (`-TRANSWEIGHT`) rewrites the cells of the user matrix at the letters of header positions 0 / 4, 2 / 11 and 2 / 12.

**MUSCLE 3.8 (B09 F65 / F69 / F70, audit A1-10c).** `multiple_align_muscle` is a port of MUSCLE 3.8.1551: `maxIters` 1 and 2 with the first-round options equal the 3.8.1551 binary (user-run Docker oracle, 420 / 420 sets, rows + output order); all other options (`maxIters` >= 3 with anchors, `objScore`, `weight1/weight2`, `distance1/distance2`, `neighborjoining` + `root1/root2`, `termGaps`, `brenner`, `matrix`, `useTree`, the tree / distance / weight files, `clusterOnly`) are implemented from the source and await the second Docker round (`docs/Validation/review-2026-09/handoff/A1-10c-muscle-r2`); the options the source compiles out (`diags*`, `hydro*`, `gapOpen2` ...) are accepted with no effect. `muscle_msa_command` runs the program's command lines on alignments (`profile`, `refine`, `spscore`, `ppscore`, `maketree`, `refinew`, `sw`).

**Waterman-Eggert in linear space (B09 F77, audit A1-7c).** `local_align_top_n` keeps the O(len1*len2) matrices of the 1987 algorithm up to 25 000 000 cells; above that (e.g. two 5-20 kb sequences) it returns the same alignments (rows, scores, coordinates, order, ties) from the exact linear-space local program, one run per reported alignment with the aligned pairs of the earlier ones forbidden (SIM / EMBOSS `matcher` scheme): memory O(len1 + len2) per round, running time about one local alignment per reported alignment. `local_align_co_optimal` still keeps the matrices and rejects more than 25 000 000 cells.

**Memory and length limits (B09 F46).** The six pairwise tools (`global_align`, `local_align`, `semi_global_align` and their `_affine` variants, scalar and `matrix` scoring, every `endGaps` policy) switch automatically to exact linear-space programs (Hirschberg / Myers–Miller / Huang–Miller locate-then-solve) above 25 000 000 dynamic-programming cells; the output is identical to the full-matrix result, the memory is O(len1 + len2) (20 kb × 20 kb affine: 111 MB peak, 100 kb × 100 kb: 185 MB, 6.5 min on one core). `general_gap_align` with a non-affine gap table is limited to 4 000 000 cells (clear error above); linear/affine tables are delegated and unlimited. Progressive / iterative / consistency MSA tools throw above 50 000 000 profile-column cells; `multiple_align` (exact center-star) is linear-space. The program ports have their own guards (audit A2-41, B09 F83): `multiple_align_tcoffee` with the default `proba_pair` library keeps the pair-HMM forward / backward matrices `(len1 + 1) x (len2 + 1) x matrixTypes` floats (3 DNA / 5 protein) and refuses pairs above 2^28 floats (about 7 300 x 7 300 protein, 9 400 x 9 400 DNA; `t_coffee` itself overflows its 32-bit index at 2^31 floats and fails to allocate before) with a clear error (use the `slow_pair` / `lalign_id_pair` method for longer sequences); `multiple_align_muscle` keeps one traceback byte per profile-profile cell and refuses above 1 000 000 000 cells (two 30 kb sequences = 954 MB; the program itself has no limit and aborts when memory runs out); `multiple_align_clustalw` is linear-space but O(k^2 L^2) in time - no size guard, it is cancellable.

**Empty sequences and cancellation (B09 F82 / F86).** The pairwise tools delegate to the library, which accepts an empty sequence (all-gap alignment of the other sequence; `local_align_top_n` / `local_align_co_optimal` return no alignments); only a missing (null) value is rejected. The three program ports (`multiple_align_clustalw`, `multiple_align_muscle`, `multiple_align_tcoffee`) refuse an empty member with one shared message, because the programs do. The alignment tools of this server and `find_repeats`, `find_known_motifs`, `find_common_regions`, `find_open_reading_frames` of the Analysis server take the request's `CancellationToken` (supplied by the MCP SDK, not part of the input schema): a cancelled request stops at the next row / iteration boundary of the dynamic program.
